    Introduction

    How to use this handbook

    This handbook does not reteach data structures. It is about the step before you write code: looking at an unfamiliar problem and working out which structural property makes an efficient solution possible.

    What each chapter gives you

    SectionPurpose
    Pattern identityWhat the technique is for, the input shape it expects, and its key insight in one or two sentences.
    Recognition signalsThe structural reasons a problem fits, the question to ask yourself, when the pattern is wrong, and the patterns most easily confused with it.
    Concepts & invariantsThe invariant, monotonicity, recurrence or amortised argument that makes the technique correct.
    Reusable Java templatesCompilable templates, with the reusable skeleton separated from the problem-specific logic. Variants that genuinely differ get their own template.
    Complexity & pitfallsTypical costs, off-by-one traps, overflow hazards and common interview follow-ups.
    Mastery checklistTakeaways, a recognition rule, an in-interview checklist and the key distinction from a neighbouring pattern.
    Assigned problemsProblem → Key insight → Approach → Java solution → Complexity → Pitfall. Where a problem's primary technique differs from the chapter heading, a classification note says so.

    Suggested study loop

    1. Read the recognition signals and invariants first. Skip the template for now.
    2. Cover the solutions. For each assigned problem, read only the problem number and title, then write down the pattern, the invariant and the complexity you expect.
    3. Implement from memory on a blank editor, ideally against a 20–25 minute limit for Medium problems.
    4. Compare against the handbook, paying most attention to the Key insight and Pitfall lines, since those are where interview solutions usually fail.
    5. Re-derive the template a few days later without looking, and tick it off in the revision checklist.

    Conventions

    • Intervals of indices are written mathematically: [l, r] is inclusive, [l, r) is half-open. Each template states which one it uses.
    • Prefix sums use pre[0] = 0 and pre[i+1] = pre[i] + a[i], so sum(a[l..r]) = pre[r+1] − pre[l].
    • Complexities are worst case unless marked amortised or expected. Space means auxiliary space and excludes the input and the required output, unless stated otherwise. Recursion stack depth is always counted.
    • Graphs use V vertices and E edges. Every graph solution states whether edges are directed and what the weights are assumed to be.
    • Java. Code targets Java 17 and LeetCode's method signatures. LeetCode supplies ListNode, TreeNode and (for 759) Interval; they are not repeated in the solutions. Templates are complete, non-public classes that compile on their own.
    • Premium marks LeetCode problems that need a subscription. They are kept because the syllabus assigns them.

    Part I · Recognition Framework

    The ten-question recognition framework

    Pattern recognition is not keyword matching. A phrase like "subarray" or "shortest" suggests a starting hypothesis, but the decision comes from structure: what the input is, what is being asked, what the constraints allow, and which property you can exploit. Work through these ten questions, in order, for every new problem.

    #QuestionWhat you are really looking for
    1What is the input structure?Array, string, set of intervals, tree, explicit graph, grid (an implicit graph), state space (an implicit graph), or a sequence of operations (a data-structure design problem).
    2What is being asked?Existence (boolean), counting (number of ways: DP or prefix-count), optimisation (min/max: greedy, DP, binary search on answer), ordering (sorting, topological order), connectivity (DFS/BFS/DSU), or shortest path (BFS, Dijkstra, Bellman–Ford).
    3Which constraints rule out brute force?Turn the bound on n into a complexity budget (table below). The budget usually removes most candidate patterns at once.
    4Is there ordering, monotonicity, an invariant or a repeated subproblem?Sorted input → pointers or binary search. A monotone predicate → binary search on the answer. A window property that is monotone in its length → sliding window. Overlapping subproblems → DP. A local choice that is never regretted → greedy.
    5What can the problem be reduced to?Maintaining a window, finding a boundary, traversing states, combining partial answers (divide and conquer or tree DP), or answering range queries.
    6Does it need a specific data structure?Heap for repeated min/max, monotonic stack for nearest greater/smaller, deque for window max, hash map for complements and prefix counts, DSU for incremental connectivity, trie for prefixes, segment/Fenwick tree for dynamic range aggregates.
    7What makes the algorithm correct?State the invariant or exchange argument in one sentence. If you cannot, the pattern choice is probably wrong.
    8What are the edge cases?Empty or single-element input, all-equal values, negatives, zero, duplicates, overflow, disconnected components, cycles, unreachable targets, and touching interval boundaries.
    9What are the time and space costs?Include sorting, the recursion stack, heap size and hash-map size, then compare against the budget from question 3.
    10Which plausible alternative is wrong, and why?Say it explicitly, for example: "Sliding window fails because values can be negative, so I use prefix sums with a hash map." Interviewers listen for this.

    Part I · Distinctions

    Similar patterns, different decisions

    Most wrong choices come from confusing two neighbouring techniques. For each pair below, the deciding question is the property that separates them.

    PairDeciding questionChoose the first when…Choose the second when…
    Sliding Window vs Prefix SumIf I extend a window, can its validity flip back and forth?Validity is monotone in the window (non-negative values, counts, "at most k distinct"); O(1) space beyond the window stateValues can be negative, or the condition is exact equality or divisibility: count via pre[j] − pre[i] with a hash map
    Two Pointers vs Binary SearchAm I searching a pair or one boundary?Pair/triplet over sorted data; pointer moves discard candidates in O(n) totalA single boundary in a monotone predicate; O(log n) per query, or as an inner step (fix one, search the other)
    DFS vs BacktrackingDo I undo state after returning?Visiting each node or state once (visited set persists): components, tree aggregatesEnumerating paths or choices; state is restored so the same node can be revisited along a different path
    BFS vs DijkstraAre all edge weights equal?Unit (or equal) weights: FIFO order is distance order, O(V+E)Non-negative, different weights: needs a priority queue, O((V+E) log V). With 0/1 weights, 0-1 BFS (deque) sits in between
    Greedy vs DPCan I prove the local choice never needs revisiting?An exchange argument or "stays ahead" proof exists (unweighted interval scheduling)Choices interact (weighted intervals, knapsack, coin change with arbitrary denominations)
    Binary Search (array) vs on AnswerIs the search space the input or the output?Searching positions in a sorted or partially ordered arraySearching a value range (speed, capacity, largest sum) with a monotone feasibility check that costs O(n)
    Segment Tree vs Fenwick TreeIs the operation invertible, and are range updates or non-sum aggregates needed?Segment tree: any associative operation (min, max, gcd, custom merges), lazy range updatesFenwick: invertible operations (sum, xor, counts), less code and memory, prefix queries
    Dijkstra vs Bellman–FordAre there negative edges, or a cap on the number of edges?All weights ≥ 0, no edge-count limit: O((V+E) log V)Negative edges, negative-cycle detection, or "at most K edges": O(V·E) or O(K·E)
    Monotonic Stack vs HeapDo I need the nearest qualifying element or the global extreme?Nearest greater/smaller by position, with amortised O(1) per elementRepeated global min/max over a changing set, O(log n) per operation
    DSU vs Graph TraversalIs the graph static, and do I need paths?Edges arrive incrementally; only "same component?" is asked; cycle detection on insertionThe graph is given up front and you need paths, distances, order, or any directed-graph reasoning

    When the obvious pattern is wrong. Be suspicious when (a) your sliding-window proof needs "values are non-negative" and the constraints say otherwise; (b) a greedy proof relies on an example rather than an exchange argument; (c) a "shortest path" has weights and you reached for BFS; (d) a DP state cannot answer "what does the future need to know?"; or (e) binary search on the answer has a predicate you cannot prove monotone.

    Part II · Pattern 01

    Two Pointers: Opposite Direction / Left–Right

    Two indices start at opposite ends and move toward each other. Each move is justified by an ordering argument showing that every candidate it skips is impossible or dominated.

    1.1Pattern identity

    Primary purpose
    Search pairs (or, by fixing outer indices, triplets and k-tuples) over a linear order in O(n) per scan instead of O(n²).
    Typical input
    A sorted array, or one that may be sorted without losing information the answer needs. Also an array whose answer depends on a bound set by its two ends (container height, water level).
    Interview applications
    Two Sum on sorted data, 3Sum / 4Sum, closest-sum variants, container with most water, trapping rain water, palindrome checks, reversing in place, merging from the back.
    Key insight
    The candidate pairs form an n × n grid. Under a monotone order, comparing f(l, r) with the target eliminates a whole row (all pairs containing l) or a whole column (all pairs containing r) in O(1).

    Key insight. Two pointers is correct only when each move discards a provably useless set of candidates. If you cannot say "every pair containing the pointer I just moved is impossible or no better than one already seen", you do not have a valid two-pointer solution.

    1.2Recognition signals

    SignalStructural reason
    Sorted input; find a pair or triplet meeting a sum, difference or closeness conditionSum is monotone in each pointer: moving l right can only increase it, moving r left can only decrease it.
    Answer is determined by the smaller of the two ends (container, water)The limiting side caps every pair it belongs to, so after evaluating it once it can be discarded.
    Output asks for values or a count, not original indicesSorting is then free (O(n log n)) and does not lose required information.
    n up to 104–105 with an O(n²) brute force over pairsThe budget suggests O(n) per fixed element or O(n log n) overall.
    O(1) extra space is requestedHash-based complement search uses O(n) space; pointers do not.

    Ask yourself. "If f(l, r) is too small (or too large, or computed), which pointer's every remaining pair is now useless?" If the answer is unambiguous, two pointers applies.

    When it is inappropriate.

    • Original indices required on unsorted data (LeetCode 1, Two Sum): sorting scrambles indices. Use a hash map, or sort index–value pairs if O(n log n) is acceptable.
    • No monotonicity: if the pair score can rise or fall as either pointer moves, nothing can be eliminated.
    • Contiguous-range constraints: when the answer is a subarray, the pointers move in the same direction. That is a sliding window (Pattern 2).
    • Counting pairs with exact sum and many duplicates needs careful block counting; a frequency map is often simpler.
    Confused withHow to tell them apart
    Sliding windowWindow pointers both move right and maintain a contiguous range. Opposite pointers move toward each other and score a pair of positions.
    Binary searchFixing one element and binary searching its complement costs O(n log n). Two pointers costs O(n) after sorting because both pointers move monotonically.
    Hash-map complementO(n) time, O(n) space, preserves indices and works unsorted. Two pointers needs order but uses O(1) space and extends naturally to k-sum with duplicate skipping.

    1.3Concepts and invariants

    The elimination invariant. For a sorted array a and target t, maintain:

    Invariant: if a valid pair (i, j) with i < j exists, then l ≤ i and j ≤ r. If a[l] + a[r] < t: for every j ≤ r, a[l] + a[j] ≤ a[l] + a[r] < t ⇒ no pair uses l ⇒ l++ If a[l] + a[r] > t: for every i ≥ l, a[i] + a[r] ≥ a[l] + a[r] > t ⇒ no pair uses r ⇒ r--

    Each step shrinks the search rectangle by one row or column, so the scan ends after at most n − 1 moves.

    The dominance invariant (optimisation version). In Container With Most Water, area(l, r) = min(h[l], h[r]) · (r − l). Suppose h[l] ≤ h[r]. Then for every r' < r, the width shrinks and min(h[l], h[r']) ≤ h[l], so area(l, r') ≤ h[l] · (r' − l) < area(l, r). Pointer l has achieved its best pair, so discard it. The argument does not show the move is safe for the taller side, which is why you must move the shorter one.

    Bounded-side invariant (Trapping Rain Water). Water above index i is min(maxLeft(i), maxRight(i)) − h[i]. Track leftMax over a[0..l] and rightMax over a[r..n−1]. If leftMax < rightMax, then for index l the true right maximum is at least rightMax > leftMax, so its water level is exactly leftMax, even though the rest of the right side has not been seen.

    Duplicate handling in k-sum: why skipping is correct

    After sorting, equal values are adjacent. Two triplets are duplicates if they have the same multiset of values. Enforce a canonical form: choose the first value from the first occurrence of each distinct value (i > 0 && a[i] == a[i−1] → skip). After recording a hit (l, r), advance both pointers past their runs of equal values. Any other (l', r') with a[l'] = a[l] would need a[r'] = a[r] to keep the same sum, which is the same triplet.

    The skip happens after a match, not before evaluating. Skipping before evaluating could jump past the only valid pair such as (−1, −1, 2), where the two −1 values are different indices.

    When sorting changes the problem. Sorting is safe when the answer depends only on the multiset of values (3Sum returns values). It is unsafe when it depends on positions: Container With Most Water uses indices as widths, so it must not be sorted, and its two-pointer validity comes from dominance, not order. Two Sum I returns indices, so sort index–value pairs or use a hash map.

    1.5Complexity and pitfalls

    TimeO(n) per scan; O(n log n) if you sort first; O(nk−1) for k-sum with k ≥ 2 after sorting.
    Auxiliary spaceO(1) beyond the sort. Java's Arrays.sort(int[]) (dual-pivot quicksort) uses O(log n) stack. The output list is not counted.
    Off-by-oneUse l < r for pairs of distinct indices. l <= r pairs an element with itself.
    Wrong invariantMoving the taller side in container problems, or moving both pointers on a non-match.
    OverflowSums of two or three ints can exceed 231−1 (4Sum famously does). Accumulate in long.
    Breaks naive codeAll-equal arrays (duplicate explosion), all-negative arrays, arrays shorter than the tuple size, and the need for original indices.
    Interview follow-upsClosest sum (track |s − t|); count pairs instead of listing them; 4Sum / k-sum recursion; unsorted input with an O(1) space requirement; streaming input (two pointers no longer applies, so use a hash map).

    1.6Pattern mastery checklist

    Essential takeaways

    • Every pointer move must eliminate a row or column of the pair grid; that is the whole proof.
    • Sort only when the answer depends on values, not positions.
    • For dominance problems, move the side that limits the score.
    • Deduplicate by canonical choice: skip repeated outer values, and skip runs only after a match.
    • Accumulate sums in long whenever three or more ints are added.

    Recognition rule. Pair over an ordered axis + a score that is monotone in each end → shrink from the side that can no longer help.

    In-interview checklist

    • Is the input sorted, or can I sort without losing what the output needs?
    • Which pointer moves when the score is low, high, or computed, and why is that safe?
    • How do I avoid duplicates (outer skip, post-match run skip)?
    • Does the sum fit in an int?
    • What happens with n < 2 (or n < 3)?

    Key distinction. Opposite pointers score pairs of endpoints. A sliding window aggregates everything between them. If the elements between l and r matter, it is not this pattern.

    Part II · Pattern 02

    Sliding Window: Fixed and Variable Size

    Two same-direction pointers bound a contiguous range [l, r]. The right pointer only ever expands and the left pointer only ever contracts, so every element enters and leaves the window at most once. The work is maintaining an O(1)-updatable summary of the window.

    2.1Pattern identity

    Primary purpose
    Optimise or test a property over all contiguous subarrays or substrings in O(n) instead of O(n²) by reusing the previous window's state.
    Typical input
    An array or string, plus either a fixed length k or a constraint on the window's contents (distinct count, character frequencies, sum bound, number of "bad" elements).
    Interview applications
    Longest substring without repeats, minimum window substring, longest run after k flips or deletions, max/average of every k-window, anagram and permutation search, at-most-k distinct.
    Key insight
    If a window that violates the constraint keeps violating it when extended to the right (or a valid window stays valid when shrunk), then for each r the best l never moves left. Both pointers are monotone, giving O(n) total.

    Key insight. A variable window is correct only when validity is monotone under containment: every sub-window of a valid window is valid (for "longest" problems), or every super-window of a valid window is valid (for "shortest" problems). Without that property, a greedy shrink can throw away the answer.

    2.2Recognition signals

    SignalStructural reason
    Contiguous subarray or substring; "longest", "shortest", "maximum over windows of size k"Contiguity means adjacent candidate ranges differ by one element at each end, so the state can be updated incrementally.
    Constraint is a count: at most k distinct, at most k zeros, no repeated characters, contains all of tCounts change by ±1 when one element enters or leaves, and the constraint is monotone under shrinking or growing.
    Sum constraint with non-negative valuesWith non-negative values the sum is monotone in window length, so "sum ≥ S" persists when extending and "sum ≤ S" persists when shrinking.
    Fixed k given explicitlyFixed window: add a[r], remove a[r−k]. No validity logic needed.
    n up to 105, O(n²) enumeration of ranges is obviousThe budget asks for O(n) or O(n log n).

    Ask yourself. "If [l, r] is invalid, is [l, r+1] also invalid? If [l, r] is valid, is [l+1, r] also valid?" A yes to the one you need means each pointer can move monotonically.

    When it is inappropriate.

    • Negative values with a sum condition. In [5, −10, 6] with "shortest subarray with sum ≥ 6", the window expands to [5, −10, 6] with sum 1. It never becomes valid, so it never shrinks, and the valid answer [6] is missed. A super-window of a valid window can be invalid, so validity is not monotone and the greedy shrink is unjustified. Use prefix sums plus a hash map (exact sum), or a monotonic deque over prefix sums (LeetCode 862).
    • Exact-count constraints ("exactly k distinct") are not monotone directly. Use exactly(k) = atMost(k) − atMost(k−1).
    • Non-contiguous selections (subsequences) belong to DP or greedy, not windows.
    • Window maximum or minimum needs a monotonic deque. A plain counter cannot evict the maximum in O(1).
    Confused withHow to tell them apart
    Prefix sum + hash mapExact target sums, divisibility, or negative values: prefix sums handle any value sign but need O(n) space. Windows need monotone validity but use only O(window-state) space.
    Opposite two pointersOpposite pointers score a pair of endpoints. Window pointers aggregate everything between them and move the same direction.
    Monotonic dequeA deque is a sliding-window state when the summary is a max or min. Choose it when the aggregate is not invertible.

    2.3Concepts and invariants

    Fixed window. The state equals the aggregate of exactly the last k elements:

    S(r) = S(r−1) + a[r] − a[r−k] for r ≥ k; window = [r−k+1, r]

    The aggregate must be invertible (sum, count, xor, frequency map) to remove a[r−k] in O(1). Max and min are not invertible, which is why they need a deque.

    Variable window, "longest valid". Invariant after processing r: [l, r] is the longest valid window ending at r. When adding a[r] breaks validity, shrink until valid. Correctness: if [l, r] is invalid then every [l', r'] with l' ≤ l, r' ≥ r is invalid (it contains an invalid window), so no future answer starts at or before the discarded l.

    Variable window, "shortest valid". Invariant: after shrinking, [l−1, r] was the last valid window. Expand r until valid, then shrink while still valid, recording the answer at each valid state. Correctness: once [l, r] is valid, any window [l, r'] with r' > r is longer, so l never needs to pair with a larger r.

    Window length = r − l + 1 (inclusive [l, r]) Longest with ≤ k bad : grow r; while bad > k: drop a[l++]; ans = max(ans, r − l + 1) Shortest with condition : grow r; while valid: ans = min(ans, r − l + 1); drop a[l++] Exactly k = atMost(k) − atMost(k − 1) (counting problems)

    Window state design. Keep a frequency array (int[26], int[128]) when the alphabet is small, and a HashMap otherwise. Pair it with a single scalar that summarises validity: distinct, bad, or missing. Checking the scalar is O(1); re-scanning the frequency table per step is O(σ) and turns O(n) into O(nσ).

    Amortised analysis: why the nested while loop is still O(n)

    The inner while only increments l, and l never exceeds r + 1 ≤ n. Over the entire run l moves at most n times and r moves exactly n times, so total pointer movement is at most 2n. Each movement does O(1) state update, giving O(n) total regardless of how the inner loop's iterations are distributed.

    The "jump" optimisation in Longest Substring Without Repeating Characters (l = max(l, last[c] + 1)) preserves the same bound and replaces the inner loop with O(1). It relies on max, because last[c] may point to a position already left of the window.

    2.4Reusable Java templates

    Template A — fixed size k. Reusable: the add/remove rhythm. Problem-specific: what the state is and what is recorded.

    Template B — variable size, longest valid window (shrink while invalid).

    Template C — variable size, shortest valid window (shrink while valid). Uses the "need/missing" counter idiom.

    Assumption. Template C is correct only because all values are non-negative, so shrinking never makes an invalid window valid again. With negative values, use prefix sums with a monotonic deque instead.

    2.5Complexity and pitfalls

    TimeO(n) pointer movement (amortised 2n). Add O(σ) if the state is compared table-to-table instead of through a counter scalar.
    Auxiliary spaceO(σ) for a frequency array over the alphabet, or O(min(n, distinct)) for a hash map; O(1) for scalar sums.
    Off-by-oneLength is r − l + 1 for inclusive windows. In a fixed window the outgoing index is r − k, not r − k + 1. Record the answer after shrinking (longest) or inside the shrink loop (shortest).
    Incorrect invariantUsing if instead of while to shrink is only safe when a single step always restores validity (e.g. a window that grows by at most one per step and never shrinks: the "non-shrinking window" trick).
    OverflowWindow sums of up to 105 ints of size 109 overflow int; use long.
    Breaks naive codeNegative numbers; k > n; empty target; a frequency map that keeps zero-count keys (so size() overstates distinct); char - 'a' on input that also has uppercase letters.
    Interview follow-upsExactly k (use the atMost difference); window max (deque); streaming input (the window is already online); returning the window instead of its length (store bestL).

    2.6Pattern mastery checklist

    Essential takeaways

    • Fixed window: add one, remove one, with an invertible aggregate.
    • Variable window: prove validity is monotone under containment before writing the shrink loop.
    • Longest → shrink while invalid, record after. Shortest → shrink while valid, record inside.
    • Summarise the window with a single scalar (missing, distinct, bad) so validity checks are O(1).
    • Negative values usually mean prefix sums, not windows.

    Recognition rule. Contiguous range + a constraint that only gets worse as the window grows (or only better) → expand right, shrink left, never move back.

    In-interview checklist

    • Fixed or variable? Longest or shortest?
    • What is the window state, and how is it updated on enter and leave?
    • Is validity monotone? Could negative values or "exactly" break it?
    • Where exactly is the answer recorded relative to the shrink loop?
    • Do I need the length or the actual window (track the start index)?

    Key distinction. Use a sliding window when validity is monotone in window size. Use prefix sums plus a hash map when the condition is an exact equality or the values can be negative.

    Part II · Pattern 03

    Fast and Slow Pointers: Cycle Detection / Linked Lists

    Two pointers traverse the same sequence at different speeds. The speed difference turns positional questions (where is the middle, does it loop, where does the loop start) into arithmetic on distances, using O(1) memory.

    3.1Pattern identity

    Primary purpose
    Detect cycles, find a cycle's entry, or locate fractional positions (middle, k-th from end) in a sequence that can only be walked forward, without extra memory.
    Typical input
    A singly linked list, or an implicit functional sequence x0, f(x0), f(f(x0)), … where every state has exactly one successor (array-as-pointer problems, digit transforms).
    Interview applications
    Linked list cycle / cycle entry, middle node, palindrome linked list (middle + reverse), reorder list, Happy Number, Find the Duplicate Number (LeetCode 287).
    Key insight
    Inside a cycle of length L the fast pointer gains one step per iteration on the slow one, so it must land on it within L iterations. The meeting point's distance arithmetic then locates the cycle entry.

    Key insight. Fast/slow works on any structure where each state has exactly one next state (a functional graph). Its paths look like the Greek letter ρ: a tail leading into one cycle. It does not apply to general graphs, where a node can have several neighbours.

    Classification note for this chapter. Of the four assigned problems, 876 and 142 are genuine linked-list fast/slow problems and 202 is fast/slow on an implicit sequence. 547 (Number of Provinces) is not a fast/slow problem: it is connected components in an undirected graph, where nodes have many neighbours and there is no "next" pointer. It is solved below with iterative BFS, the honest technique, and revisited with DFS in Ch. 9 and DSU in Ch. 17.

    3.2Recognition signals

    SignalStructural reason
    Linked list with possible cycle; "return where the cycle begins"Each node has one next, so the structure is a ρ shape and Floyd's arithmetic applies.
    Middle, or "split into halves", of a list of unknown lengthA 2:1 speed ratio places slow at n/2 when fast reaches the end, in a single pass.
    Repeatedly apply a deterministic function; "does it end at X or loop forever?"The sequence lives in a finite (or eventually bounded) state space, so it must become periodic.
    "O(1) extra space", "do not modify the list/array"Rules out a visited HashSet and in-place marking.
    Array of n+1 values in [1, n] treated as pointersi → a[i] is a function, and a duplicate value is a cycle entry (LeetCode 287).

    Ask yourself. "Does every state have exactly one successor, and am I asked about position, looping, or the loop's start?" If a state can have two successors, use graph traversal instead.

    When it is inappropriate.

    • General graphs (adjacency lists/matrices): use DFS colouring (directed) or a parent check, DSU or BFS (undirected).
    • When O(n) memory is fine and clarity matters: a HashSet of visited nodes is simpler and equally fast. Fast/slow earns its place through O(1) space.
    • Random access is available (arrays): the middle is just n / 2.
    Confused withHow to tell them apart
    Hash-set visitedSame O(n) time. The hash set uses O(n) space and finds the entry trivially. Floyd uses O(1) space but needs the second phase to find the entry.
    Two pointers with a gap"k-th from the end" uses equal speeds with a k-step head start, which is a fixed offset rather than a speed ratio.
    Directed-graph cycle detectionMultiple out-edges per node need DFS three-colour or Kahn's algorithm (Ch. 11).

    3.3Concepts and invariants

    Convergence. Once both pointers are in the cycle (length L), let the gap be d = (fast − slow) mod L. Each iteration fast moves 2 and slow moves 1, so the gap changes by exactly one each step. It therefore passes through 0 within L steps and the two meet, with no risk of fast "jumping over" slow. Detection costs O(μ + L), where μ is the tail length.

    Entry point derivation. Let μ = distance from head to entry, and suppose they meet k steps into the cycle.

    slow travelled s = μ + k (+ whole loops, absorbed below) fast travelled 2s = μ + k + m·L for some integer m ≥ 1 ⇒ s = m·L ⇒ μ + k = m·L ⇒ μ = m·L − k = (m − 1)·L + (L − k)

    From the meeting point, walking μ steps lands on k + μ ≡ 0 (mod L), which is the entry. So reset one pointer to the head and move both one step at a time; they meet exactly at the entry after μ steps.

    Midpoint conventions. With slow = fast = head and the loop guard fast != null && fast.next != null, slow ends at index ⌊n/2⌋ (0-based): the second middle for even n. With the guard fast.next != null && fast.next.next != null, slow ends at ⌊(n−1)/2⌋: the first middle, which is what you need to split a list before reversing its second half.

    Termination for implicit sequences (why Happy Number cannot run forever)

    Floyd needs the sequence to be eventually periodic. For the digit-square map f, a d-digit number n ≥ 10d−1 maps to at most 81d. For d ≥ 4, 81d < 10d−1, so f(n) < n whenever n ≥ 1000. The sequence therefore enters [1, 999] and stays inside a finite set (f(999) = 243), so by the pigeonhole principle it must repeat. 1 is a fixed point (f(1) = 1), so "happy" means the cycle reached is {1}.

    3.4Reusable Java templates

    Template A — middle node (both conventions).

    Template B — Floyd on any functional sequence. The same two phases work for list nodes, array indices (i → a[i]) or numbers (x → f(x)). Only next changes.

    3.5Complexity and pitfalls

    TimeO(μ + L) for detection and entry, O(n) for middle. Each pointer advances O(n) times.
    Auxiliary spaceO(1). The hash-set alternative is O(n).
    Termination conditionsCheck fast != null && fast.next != null before fast.next.next. The order of the two checks matters.
    Incorrect invariantStarting phase 1 with slow = head, fast = head.next shifts the meeting point, so the phase 2 "reset to head" no longer lands on the entry. Start both at head (or both one/two steps from x0, as in Template B).
    Breaks naive codeEmpty list, single node, a self-loop (head.next == head), a cycle that starts at the head (μ = 0).
    Interview follow-upsCycle length; Find the Duplicate Number via i → nums[i]; palindrome list in O(1) space (first middle + reverse + compare + restore); whether speed 3:1 also works (the gap changes by 2 per step, so with an even L and an odd initial gap the pointers never coincide; 2:1 always meets).

    3.6Pattern mastery checklist

    Essential takeaways

    • The pattern needs a functional structure: one successor per state.
    • The 2:1 speed makes the gap shrink by exactly one per step, so the pointers must meet.
    • The entry is μ steps from both the head and the meeting point, because μ ≡ L − k (mod L).
    • The loop guard selects which middle you get.
    • Implicit sequences need a termination argument (a bounded state space).

    Recognition rule. One-successor sequence + a question about looping or relative position + O(1) memory → tortoise and hare.

    In-interview checklist

    • Is this really a functional sequence, or a general graph?
    • Null-safe guards on fast and fast.next?
    • Do both pointers start at the same place for phase 2 to be valid?
    • Which middle (first or second) does the follow-up need?
    • Have I handled μ = 0 and a self-loop?

    Key distinction. Floyd detects a cycle in a single forward chain. Cycle detection in a general directed graph needs DFS colouring or Kahn's algorithm (Ch. 11), and an undirected graph needs DSU (Ch. 17).

    Approach
    1. slow = f(n), fast = f(f(n)); advance 1 and 2 steps until they meet.
    2. Return slow == 1.

    TimeO(log n) per step; O(log n) steps before reaching the bounded range, then O(1) (states < 1000)SpaceO(1)

    Pitfall. A HashSet<Integer> of seen values is an equally valid and simpler alternative (O(1) extra in practice, since the states are bounded). Mention it, then justify Floyd as the constant-memory version. Without the boundedness argument, "loop until 1" has no termination proof.

    Part II · Pattern 04

    Prefix Sum / Cumulative Sum

    Precompute cumulative aggregates so that any range aggregate is a difference of two prefixes. Combined with a hash map, the difference becomes an equation: "which earlier prefix makes this range satisfy the condition?"

    4.1Pattern identity

    Primary purpose
    Answer range-sum queries in O(1) after O(n) preprocessing, and count or optimise subarrays with an exact sum or modular condition in O(n).
    Typical input
    An integer array (possibly with negatives), a target k or modulus, or many offline range queries on static data. Also 2D grids (submatrix sums) and difference arrays for batch range updates.
    Interview applications
    Subarray sum equals k, continuous subarray sum (multiple of k), longest subarray with sum k, equal 0/1 counts (map 0 → −1), pivot/equilibrium index, product except self (prefix and suffix products), range-sum query, difference arrays.
    Key insight
    sum(i..j) = P[j+1] − P[i], so a condition on a subarray becomes a condition on a pair of prefixes. Scanning j and looking up the required earlier prefix in a hash map turns O(n²) pair enumeration into O(n).

    Key insight. Prefix sums make no monotonicity assumption, which is exactly why they work with negative values where a sliding window fails. The price is O(n) memory for the map of earlier prefixes.

    4.2Recognition signals

    SignalStructural reason
    "Number of subarrays with sum exactly k", values may be negativeExact equality is not monotone in window length, but P[j] − P[i] = k ⇔ P[i] = P[j] − k is a lookup.
    "Sum is a multiple of k" / "divisible by k"P[j] − P[i] ≡ 0 (mod k) ⇔ P[i] ≡ P[j] (mod k): group prefixes by remainder.
    Many range queries, no updatesO(n) build, O(1) per query. With updates, use Fenwick or segment trees (Ch. 20).
    Balance conditions: equal numbers of 0/1, vowels/consonants, left sum = right sumMap one class to +1 and the other to −1. "Balanced" becomes "range sum 0", i.e. equal prefixes.
    "Longest" or "shortest" subarray with an exact sumFor each j, the best i is the earliest (longest) or latest (shortest) index with the required prefix, so store first or last occurrence.

    Ask yourself. "Can the condition on sum(i..j) be rewritten as P[i] = g(P[j]) for a function g I can compute?" If yes, one pass with a map of earlier prefixes solves it.

    When it is inappropriate.

    • Inequalities ("sum ≥ k", "sum ≤ k"): a hash map answers equality only. With non-negative values use a sliding window. With negatives, use a monotonic deque over prefixes or a sorted structure / BIT over prefix values.
    • Range updates interleaved with queries: a static prefix array goes stale, so use a Fenwick or segment tree.
    • Non-invertible aggregates (max, min): max(i..j) is not a difference of prefixes. Use a sparse table, segment tree or deque.
    Confused withHow to tell them apart
    Sliding windowA window needs monotone validity (non-negative values, at-most constraints) and uses O(1)–O(σ) space. Prefix + map handles any signs with exact conditions in O(n) space.
    Fenwick treeA Fenwick tree is a prefix-sum array that supports point updates in O(log n). Prefix arrays are the static special case.
    KadaneMaximum subarray sum is max over j of (P[j] − min over i < j of P[i]), a running-minimum prefix argument. Kadane is the same thing in O(1) space (A5).

    4.3Concepts and invariants

    Indexing convention. Use a length-(n+1) array with an empty prefix:

    P[0] = 0, P[i+1] = P[i] + a[i] P[i] = sum of a[0..i−1] sum(a[l..r]) = P[r+1] − P[l] inclusive l..r, 0 ≤ l ≤ r < n 2D: S[i+1][j+1] = S[i][j+1] + S[i+1][j] − S[i][j] + g[i][j] sum(r1..r2, c1..c2) = S[r2+1][c2+1] − S[r1][c2+1] − S[r2+1][c1] + S[r1][c1]

    The extra slot P[0] = 0 represents the empty prefix. It is what allows subarrays starting at index 0 to be counted, and it is the reason hash-map solutions seed the map with {0: 1} (counting) or {0: −1} (index-based).

    Hash-map invariant. Process j = 0..n−1 with running prefix p = P[j+1]. Invariant: before handling j, the map contains exactly the prefixes P[0..j], which are the starts of subarrays ending at j. Therefore:

    1. Query first: count += map[p − k] counts subarrays (i..j) with i ≤ j.
    2. Then insert p, so it can serve as a start for later ends.

    Inserting before querying makes P[j+1] available as its own start, which pairs it with itself and counts the empty subarray whenever k = 0. That is the classic wrong-order bug.

    First vs last occurrence. For the longest subarray, store a prefix's first index and never overwrite it (use putIfAbsent). For the shortest, keep the latest index (overwrite). For counting, store frequencies.

    Prefix remainders and Java's negative modulo

    (P[j] − P[i]) mod k = 0 ⇔ P[i] mod k = P[j] mod k, so group prefixes by remainder. Java's % follows the sign of the dividend: −7 % 3 == −1. With negative values, normalise with ((x % k) + k) % k, or −1 and 2 land in different buckets despite being congruent. Also keep the running remainder in long when k can approach Integer.MAX_VALUE, because rem + a[i] can exceed 231 − 1.

    The number of pairs inside a remainder bucket of size c is c·(c−1)/2. Counting problems such as LeetCode 974 (Subarray Sums Divisible by K) either add the running bucket count during the scan or use this formula at the end.

    Difference arrays (the inverse operation). To add v to every element of a[l..r] for many updates, then read the array once: D[l] += v; D[r+1] −= v, and the final array is the prefix sum of D. This gives O(1) per update and O(n) to materialise.

    4.4Reusable Java templates

    Template A — static range sums (1D and 2D).

    Template B — prefix + hash map (count, longest, modular). Reusable: the scan, the seeding, and query-before-insert. Problem-specific: the key transform and the stored value.

    4.5Complexity and pitfalls

    TimeO(n) build, O(1) per static query; O(n) expected for hash-map scans (hashing is expected O(1)).
    Auxiliary spaceO(n) for the prefix array or the map (O(k) for remainder buckets). Running-prefix variants that only need the total use O(1).
    Off-by-oneMixing P[i] = sum(a[0..i]) (inclusive) with the formula P[r+1] − P[l]. Pick the empty-prefix convention and use it everywhere.
    Incorrect invariantInserting the current prefix before querying (counts empty subarrays); overwriting the first index in "longest" problems; forgetting the seed {0:1} or {0:−1}.
    OverflowPrefixes of 105 values of size 109 reach 1014, so use long. With Map<Long, …>, look up with long keys; map.get(intValue) boxes an Integer and silently misses.
    Breaks naive codek = 0; all zeros (many equal prefixes); negative values with %; length constraints such as "at least 2".
    Interview follow-upsReturn the subarray itself; 2D version (fix a row pair, then 1D on column sums: O(m²n)); streaming (the scan is already online); "sum ≥ k" with negatives (monotonic deque, LeetCode 862).

    4.6Pattern mastery checklist

    Essential takeaways

    • P[0] = 0 represents the empty prefix; seeding the map with it covers subarrays starting at 0.
    • Rewrite the subarray condition as an equation on two prefixes, then look up the earlier one.
    • Query before insert: the map must hold only prefixes strictly before the current end.
    • Store frequencies for counting, the first index for longest, the last index for shortest.
    • Normalise remainders and use long for sums.

    Recognition rule. Exact sum, balance or divisibility on a contiguous range, especially with negatives → prefix sums plus a hash map of earlier prefixes.

    In-interview checklist

    • What is the key: P, P − k, P mod k, or a ±1 balance?
    • What is stored: count, first index or last index?
    • Is the seed correct for the empty prefix?
    • Is the update order query → insert?
    • Do I need long and modulo normalisation?

    Key distinction. Use prefix sums for equality conditions with any signs. Use a sliding window for monotone inequality conditions on non-negative data.

    LC 724

    Find Pivot Index

    Easy

    Task. Return the leftmost index i where the sum strictly left of i equals the sum strictly right of i, or −1. Values may be negative.

    Key insight

    The right sum is total − left − nums[i], so a single running prefix and the total are enough. No array is needed.

    Why the pattern applies

    Each index needs two range sums (left and right). These are complementary prefix and suffix sums, derived from one prefix value and the total.

    Approach
    1. Compute total.
    2. Scan i with left = sum of nums[0..i−1]. If left == total − left − nums[i], return i. Otherwise left += nums[i].

    TimeO(n)SpaceO(1)

    Pitfall. Update left after the check: the pivot itself belongs to neither side. Index 0 is a valid pivot when the rest sums to 0 (e.g. [2, 1, −1]). Negative values rule out any two-pointer "balance" approach.

    LC 560

    Subarray Sum Equals K

    Medium

    Task. Count the contiguous non-empty subarrays whose sum equals k. Values are in [−1000, 1000].

    Key insight

    sum(i..j) = k ⇔ P[i] = P[j+1] − k. For each end j, the number of valid starts is the number of earlier prefixes equal to P[j+1] − k.

    Why the pattern applies

    Negative values make a sliding window invalid (see 2.2), and the condition is exact equality. This is the canonical prefix-frequency map (Template B, countSumK).

    Approach
    1. Seed {0: 1}.
    2. For each x: p += x; count += freq[p − k]; freq[p]++.

    TimeO(n) expectedSpaceO(n)

    Pitfall. Swapping the two lines inside the loop over-counts by one per element when k == 0 (the empty subarray). The count fits in int here because n ≤ 2·104 gives at most about 2·108 subarrays.

    LC 523

    Continuous Subarray Sum

    Medium

    Task. Return true if some subarray of length at least 2 has a sum that is a multiple of k. Here 0 ≤ nums[i] ≤ 109 and 1 ≤ k ≤ 231 − 1. Zero counts as a multiple.

    Key insight

    The sum of (i..j) is a multiple of k ⇔ P[i] ≡ P[j+1] (mod k). The length constraint j − i + 1 ≥ 2 means the two equal-remainder prefixes must be at least 2 positions apart, so keep the earliest index of each remainder.

    Why the pattern applies

    A modular equality on two prefixes, with a length condition, maps onto Template B with a first-occurrence map keyed by remainder.

    Approach
    1. Seed first[0] = −1 (the empty prefix sits before index 0).
    2. For each j: rem = (rem + nums[j]) mod k. If rem was seen at index i and j − i ≥ 2, return true. Otherwise store j only if rem is new.

    TimeO(n) expectedSpaceO(min(n, k))

    Pitfall. Overwriting the index on repeat breaks inputs such as [5, 0, 0], k = 3: each step sees its remainder only one position back and never reaches length 2. The earliest occurrence gives the longest candidate, and only length matters. int rem overflows when k is near 231 − 1 and nums[j] = 109. Two consecutive zeros always return true, and seeding with −1 handles them.

    LC 325

    Maximum Size Subarray Sum Equals k

    MediumPremium

    Task. Return the maximum length of a subarray summing to k, or 0 if none. Values may be negative (|nums[i]| ≤ 104, |k| ≤ 109, n ≤ 2·105).

    Key insight

    For end j, the longest valid subarray starts right after the earliest i with P[i] = P[j+1] − k. Keeping only first occurrences makes each lookup return the best start.

    Why the pattern applies

    Exact sum with negatives rules out a window, and maximal length means storing the first index. This is Template B, longestSumK.

    Approach
    1. Seed {0: −1}.
    2. For each j: update p; if p − k is present at i, best = max(best, j − i); then putIfAbsent(p, j).

    TimeO(n) expectedSpaceO(n)

    Pitfall. put instead of putIfAbsent keeps the latest index, which yields the shortest match. With a Map<Long, Integer>, pass a long key: first.get(p - k) works only because p is a long.

    Part II · Pattern 05

    Binary Search: Index / Sorted Array

    Binary search is not "find x in a sorted array". It finds the boundary of a monotone predicate over an index range. Sortedness is just the most common way such a predicate arises.

    5.1Pattern identity

    Primary purpose
    Locate a boundary (first index where a predicate becomes true) or an element in O(log n) by halving a search space whose invariant guarantees the answer stays inside.
    Typical input
    A sorted array (possibly with duplicates), a rotated sorted array, an array with a local-order property (peaks, slopes), or two sorted arrays whose combined order is implicit.
    Interview applications
    Exact search, lower/upper bound, first and last occurrence, insert position, rotated array search and minimum, peak finding, median of two sorted arrays, k-th smallest in a sorted matrix, sqrt(x).
    Key insight
    Every binary search is: "the predicate is false…false true…true on [lo, hi]; find the first true." Write the predicate down first. Mid-point updates then follow mechanically from the interval convention.

    Key insight. Correctness comes from one invariant: "the answer, if it exists, lies within my current interval". Each update must discard only indices that provably are not the answer, and the interval must strictly shrink.

    5.2Recognition signals

    SignalStructural reason
    Sorted input; "first", "last", "insert position", "count of x"a[i] ≥ x is monotone in i, so the first true is the lower bound.
    "O(log n)" required, or n up to 109 implicit indicesOnly halving fits the budget.
    Not sorted, but some local comparison tells you which half contains an answerPeaks: if a[m] < a[m+1], a peak exists to the right. That is a predicate, even without global order.
    Rotated sorted arraya[i] ≤ a[n−1] is false…false true…true, and its first true is the minimum.
    Two sorted arrays, a k-th element or medianSearch the partition point: "how many elements come from array A" is monotone with respect to the cross-boundary comparison.

    Ask yourself. "What exactly is my predicate p(i), and is it false…false true…true over the range?" If you cannot write p(i), you are guessing at the update rules.

    When it is inappropriate.

    • No monotone or locally decidable predicate (for example, an arbitrary unsorted array): a linear scan or a hash set is needed.
    • Linked lists: there is no O(1) random access, so "binary search" costs O(n) per probe.
    • Many queries with updates: maintain a balanced BST (TreeMap) or Fenwick tree instead of re-sorting.
    • The search space is the answer value, not an index: that is binary search on the answer (Ch. 6), where the predicate is a feasibility check.
    Confused withHow to tell them apart
    Two pointersPair search over sorted data is O(n) with two pointers, versus O(n log n) for "fix one, binary search the other". Binary search wins when only one boundary is needed or queries are repeated.
    Binary search on answerSame skeleton, but the predicate costs O(n) per evaluation and the range is the output domain.
    TreeMap floor/ceilingThe dynamic-set version of lower/upper bound: O(log n) with inserts and deletes.

    5.3Concepts and invariants

    Two interval conventions. Pick one per problem and never mix them:

    ConventionLoopShrink rulesExit state
    Inclusive [lo, hi]while (lo <= hi)lo = mid + 1 / hi = mid − 1Empty interval: lo = hi + 1. Use for exact match with early return.
    Half-open [lo, hi)while (lo < hi)lo = mid + 1 (pred false) / hi = mid (pred true)lo == hi == first true (or n if none). Use for boundaries.

    In the half-open form, hi = mid keeps a possible answer, and mid = lo + (hi − lo) / 2 < hi guarantees progress. If you need lo = mid (searching the last true), round the midpoint up (lo + (hi − lo + 1) / 2) or the loop can stall at a two-element interval.

    lowerBound(x) = first i with a[i] ≥ x (n if none) upperBound(x) = first i with a[i] > x (n if none) count(x) = upperBound(x) − lowerBound(x) last index of x = upperBound(x) − 1 (valid iff count > 0) mid = lo + (hi − lo) / 2 or (lo + hi) >>> 1 never (lo + hi) / 2 when lo + hi may overflow

    Duplicates. Exact-match search returns an occurrence, not a specific one. First/last occurrence must be phrased as a boundary (≥ x, > x), and then duplicates need no special handling.

    Binary search without global order: the slope predicate (peak finding)

    Let a[−1] = a[n] = −∞ and adjacent values be distinct. Define p(i) = a[i] > a[i+1] (descending at i). Claim: if a[m] < a[m+1], some peak lies in [m+1, n−1]. Walk right from m+1: either the values keep rising until index n−1, which is a peak because a[n] = −∞, or they first fall at some j, which is a peak. Symmetrically, a[m] > a[m+1] implies a peak in [0, m]. The interval always contains a peak, which is exactly the invariant binary search needs. p is not globally monotone, but the existence invariant is preserved, and that is sufficient.

    Partition search. For the median of A (size m ≤ n) and B (size n), choose i elements from A and j = ⌈(m+n)/2⌉ − i from B for the left half. The cut is valid iff A[i−1] ≤ B[j] and B[j−1] ≤ A[i]. If A[i−1] > B[j], i is too large; otherwise it is too small. So "i is too large" is a monotone predicate over i ∈ [0, m], and the search costs O(log min(m, n)).

    5.4Reusable Java templates

    Template A — exact match, inclusive interval.

    Template B — boundary search on a predicate, half-open interval. This one shape covers lower bound, upper bound, rotated minimum and "first bad version".

    Answer-recording variant. lastTrue uses the inclusive form with an ans variable. It avoids the round-up-midpoint subtlety entirely, at the cost of one extra variable. Many engineers use this form for every boundary search because it never stalls.

    5.5Complexity and pitfalls

    TimeO(log n) predicate evaluations; O(log min(m, n)) for the two-array partition.
    Auxiliary spaceO(1) iterative. Recursive versions use O(log n) stack.
    Off-by-oneUsing hi = n − 1 with while (lo < hi) means lower bound can never return n ("insert at end"). Mixing hi = mid − 1 into a half-open loop skips the answer.
    Infinite loopslo = mid with a round-down midpoint on a two-element interval never progresses.
    Overflow(lo + hi) / 2 overflows when both exceed 230 (implicit index spaces, answer spaces). Use lo + (hi − lo) / 2. Comparing a[m] + 1 or target + 1 near Integer.MAX_VALUE also overflows, so phrase bounds with > instead of ≥ x + 1.
    Breaks naive codeEmpty array; target outside [a[0], a[n−1]]; all equal; n = 1; duplicates (rotated search with duplicates degrades to O(n) worst case).
    Interview follow-upsFirst/last occurrence (bounds); count occurrences; rotated array (with or without duplicates); k-th smallest of two arrays; search in a 2D sorted matrix (treat as a 1D index space); prove why the loop terminates.

    5.6Pattern mastery checklist

    Essential takeaways

    • Write the predicate first; the code is just "first true".
    • Pick inclusive or half-open per problem and keep the updates consistent with it.
    • Duplicates are handled by searching boundaries, not values.
    • Global sortedness is not required, only an invariant that some answer stays in the interval.
    • Use an overflow-safe midpoint and guarantee the interval strictly shrinks.

    Recognition rule. An index space plus a predicate that splits it into "no" then "yes" (or tells you which side holds an answer) → halve it.

    In-interview checklist

    • What is p(i), and is it monotone (or answer-preserving)?
    • Inclusive or half-open? Initial hi = n − 1 or n?
    • Does every branch shrink the interval?
    • What is returned when the predicate is never true?
    • Check by hand on sizes 0, 1 and 2.

    Key distinction. Index binary search evaluates an O(1) predicate on positions. Binary search on the answer evaluates an O(n) feasibility predicate on candidate output values.

    Find First and Last Position of Element in Sorted Array

    Medium

    Task. In a non-decreasing array, return [first, last] indices of target, or [−1, −1], in O(log n).

    LC 162

    Find Peak Element

    Medium

    Task. Return the index of any element strictly greater than its neighbours, with nums[−1] = nums[n] = −∞ and adjacent elements distinct, in O(log n).

    Key insight

    The slope predicate nums[m] > nums[m+1] ("descending at m") tells you a peak exists in [lo, m]; otherwise one exists in [m+1, hi]. The array is unsorted, but the invariant "a peak lies in [lo, hi]" is preserved (proof in 5.3).

    Why the pattern applies

    This is a classification note in its own right: binary search here relies on a locally decidable, answer-preserving predicate, not on sortedness. The half-open-style shrink (hi = m keeps m) is Template B's shape.

    Approach
    1. lo = 0, hi = n − 1; while lo < hi: m = mid; if nums[m] > nums[m+1] then hi = m, else lo = m + 1.
    2. Return lo: the interval collapsed onto a peak.

    TimeO(log n)SpaceO(1)

    Pitfall. Do not compare with both neighbours and branch three ways. That requires boundary checks against the −∞ sentinels (and values may equal Integer.MIN_VALUE, so a numeric sentinel is unsafe). Comparing m with m+1 only, where m < hi guarantees m+1 exists, avoids both problems.

    LC 4

    Median of Two Sorted Arrays

    Hard

    Task. Return the median of the union of two sorted arrays of sizes m and n in O(log(m + n)).

    Key insight

    The median is defined by a partition: a left half of size ⌈(m+n)/2⌉ with every left element ≤ every right element. Choosing i elements from the shorter array fixes j = half − i from the other, so you are binary searching a single integer i ∈ [0, m].

    Why the pattern applies

    "i is too large" (A[i−1] > B[j]) is monotone in i. Increasing i adds larger A-elements to the left and removes B-elements, so the search space is the cut position, not a value. Searching the shorter array guarantees 0 ≤ j ≤ n for every i.

    Approach
    1. Ensure A is the shorter array. Let half = (m + n + 1) / 2.
    2. Binary search i in [0, m]; j = half − i. Use sentinels: Aleft = i == 0 ? −∞ : A[i−1], Aright = i == m ? +∞ : A[i], and similarly for B.
    3. If Aleft > Bright: hi = i − 1. Else if Bleft > Aright: lo = i + 1. Else the cut is valid: the median is max(Aleft, Bleft) for odd totals, or the average of max(lefts) and min(rights) for even totals.

    TimeO(log min(m, n))SpaceO(1)

    Pitfall. Searching the longer array lets j go negative or exceed n. Using Integer.MIN_VALUE/MAX_VALUE as sentinels is fine for this problem's value range, but long sentinels also stay correct if values can be extreme. Compute the even-case average in floating point (or long) to avoid int overflow. When one array is empty, i = 0 and the formulas reduce to the other array's median.

    Part II · Pattern 06

    Binary Search on Answer: Parametric Search

    Instead of searching the input, binary search the space of possible answers. This works when the question "can the target be met with value x?" is cheap to answer and monotone in x.

    6.1Pattern identity

    Primary purpose
    Turn an optimisation problem ("smallest x such that…", "minimise the maximum…") into O(log range) decision problems.
    Typical input
    An array of loads, sizes or piles, plus a budget (days, hours, threshold, number of parts). The answer is an integer in a bounded range.
    Interview applications
    Minimum speed or capacity, smallest divisor, split array largest sum, minimum days to make bouquets, aggressive cows / magnetic force (maximise the minimum), k-th smallest in a sorted matrix, median of large ranges.
    Key insight
    If feasible(x) implies feasible(x + 1), the feasible values form a suffix of the range. The answer is the boundary of that suffix, and binary search finds it with O(log R) calls to a usually greedy O(n) checker.

    Key insight. You do not need a formula for the optimum. You need (1) a range guaranteed to contain it, (2) a predicate that is monotone over that range, and (3) a fast, correct way to evaluate the predicate.

    6.2Recognition signals

    SignalStructural reason
    "Minimum X such that the task finishes within budget B" / "maximum X such that a constraint still holds"Relaxing X (more speed, more capacity) can only make the task easier, so the predicate is monotone.
    "Minimise the largest part" / "maximise the smallest gap"Min-max and max-min objectives are the classic parametric forms: fix the threshold, then check greedily.
    Answer is a number in [1, 109] while n ≤ 105O(n log R) ≈ 3 · 106 operations. Enumerating every candidate x is impossible.
    Checking a candidate is easy; constructing the optimum directly is hardThe decision version admits a greedy that the optimisation version does not obviously admit.

    Ask yourself. "If someone handed me the answer x, could I verify in O(n) whether it is achievable? And if x works, does x + 1 (or x − 1) also work?"

    When it is inappropriate.

    • Non-monotone predicates: e.g. "exactly k parts" when feasibility can flip. Reformulate as "at most k parts", which is monotone.
    • No cheap checker: if verifying x needs exponential search, binary search does not help.
    • A direct formula or a greedy optimum exists, such as the maximum of an array. Do not add a log factor for nothing.
    • Real-valued answers need iteration-count termination (e.g. 100 halvings), not lo < hi on doubles.
    Confused withHow to tell them apart
    Binary search on an index (Ch. 5)Index search looks for a position in a given array. Here the "array" is the virtual sequence feasible(lo..hi), which is never materialised.
    Dynamic programmingSplit Array Largest Sum has an O(k · n²) DP. Parametric search wins whenever the checker is greedy and the answer range is narrow in log terms.
    Greedy aloneThe greedy inside the checker answers "is x enough?". On its own it does not pick the optimal x.

    6.3Concepts and invariants

    Defining the answer space. Choose lo as a value that is certainly no larger than the answer and hi as a value that is certainly feasible. Good bounds come from the problem's extreme cases:

    Problemlo (lower bound)hi (always feasible)Why
    Koko (875)1max(piles)At speed max, each pile takes one hour and h ≥ n is guaranteed.
    Smallest divisor (1283)1max(nums)Every term ceil(v / max) = 1 and threshold ≥ n.
    Ship within D days (1011)max(weights)sum(weights)A package cannot be split, and one ship can take everything in one day.
    Split array (410)max(nums)sum(nums)Some part contains the largest element, and one part is always allowed.

    Monotone predicate and the boundary search. For minimisation, the predicate over [lo, hi] looks like F F F … F T T … T. Search the first T with the half-open discipline:

    Invariant: answer ∈ [lo, hi] and feasible(hi) is true. mid = lo + (hi − lo) / 2 (rounds down, so mid < hi and the loop always shrinks) feasible(mid) ⇒ hi = mid (mid may be the answer: keep it) otherwise ⇒ lo = mid + 1 (mid is infeasible, so everything ≤ mid is too) Loop while lo < hi; on exit lo == hi == answer.

    For maximisation (T T … T F F), search the last T. Round up, mid = lo + (hi − lo + 1) / 2, with lo = mid on success and hi = mid − 1 on failure. Rounding down here makes lo = mid loop forever when hi = lo + 1.

    Proving feasibility monotonicity (and the checker's greedy)

    Monotonicity. For capacity C, any shipping schedule valid under C is also valid under C + 1, since no day's load exceeds C < C + 1. Therefore minDays(C) is non-increasing in C, and "minDays(C) ≤ D" is a suffix property. The same one-line argument covers speed (hours are non-increasing in speed) and divisor (each ceil(v / d) is non-increasing in d).

    Greedy checker. "Given capacity C, fill each day as much as possible before starting a new one" minimises the number of days. Exchange argument: take any valid partition and the greedy one. Where the greedy's first day ends at or after the optimal first day's end, greedy has covered a prefix at least as long. By induction, after j days greedy covers at least as many items as any valid schedule, so it never uses more days.

    Assumption. The greedy relies on all items being non-negative. With negative weights, packing more could reduce a day's load, and "fill as much as possible" is no longer optimal.

    Integer ceiling without floating point. For positive a and b, ceil(a / b) = (a + b − 1) / b, or (a − 1) / b + 1 for a ≥ 1. The second form avoids overflow when a is near Integer.MAX_VALUE. Never use Math.ceil((double) a / b) in interviews: it is slow and, for large longs, inexact.

    Overflow. The checker's accumulator (total hours, total sum) can exceed 231−1. For Koko, 104 piles × 109 hours each overflows an int, so use long. Bounds like sum(nums) can also overflow int in general; LeetCode 410's constraints keep it within 109, but writing long costs nothing.

    Template A — minimise x subject to a monotone feasibility predicate. Reusable: the loop. Problem-specific: bounds and feasible.

    Template B — maximise x subject to a monotone predicate (max-min problems). Note the upward rounding.

    Template C — greedy partition checker, shared by 1011 and 410: "with segment-sum cap cap, how many contiguous segments are needed?"

    6.5Complexity and pitfalls

    TimeO(C(n) · log R), where C(n) is the checker cost (usually O(n)) and R = hi − lo + 1.
    Auxiliary spaceO(1) beyond the input for greedy checkers.
    Off-by-onePair lo < hi + hi = mid with floor; pair lo = mid with ceil. Mixing lo <= hi with hi = mid loops forever.
    Wrong boundslo = 0 for a divisor or speed (division by zero); lo = 1 for capacity (an infeasible region the checker may mis-evaluate, since a single item exceeds the cap).
    Overflow(lo + hi) / 2 on ints near 231; checker sums; (p + k − 1) when p ≈ 231 in int arithmetic.
    Breaks naive code"Exactly k" instead of "at most k" (non-monotone); a checker that greedily packs negative values; floating-point ceilings.
    Interview follow-upsProve monotonicity; give the DP alternative (410); handle real-valued answers (iterate ~60–100 times); return the actual partition; reduce the range with tighter bounds such as ceil(sum / D).

    6.6Pattern mastery checklist

    Essential takeaways

    • The three ingredients are a valid range, a monotone predicate, and a fast checker. Prove all three aloud.
    • Minimisation: floor mid, hi = mid. Maximisation: ceil mid, lo = mid.
    • Choose lo as the "physically necessary" lower bound (max element for unsplittable items).
    • Greedy checkers assume non-negative items. State that assumption.
    • Use long in the checker by default.

    Recognition rule. "Smallest / largest value such that a budget is respected" + an O(n) way to test one value → binary search the value.

    • What exactly is x, and is the predicate "x is enough" monotone?

    • Can the checker's accumulator overflow?

    Key distinction. In Chapter 5 the monotone sequence is the array. Here it is the implicit sequence feasible(lo), …, feasible(hi), and each probe costs O(n) instead of O(1).

    Part II · Pattern 07

    Merge Intervals: Sorting and Sweep

    Sort intervals so that overlap becomes a local relationship between neighbours. Then either merge them in one pass or sweep over their endpoints as events.

    7.1Pattern identity

    Primary purpose
    Compute unions, intersections, gaps or the maximum overlap of a set of intervals in O(n log n).
    Typical input
    int[][] of [start, end] pairs (possibly unsorted), or several already-sorted lists of disjoint intervals.
    Interview applications
    Merging calendars, inserting a booking, minimum meeting rooms or platforms, free time across schedules, total covered length, CPU or bandwidth peak load.
    Key insight
    After sorting by start, an interval can overlap the current merged block only if its start is ≤ the block's end. It never needs to be compared with earlier blocks, because they all end before the current block starts.

    Key insight. Sorting by start converts a pairwise O(n²) overlap relation into a single running value, the end of the current block. Counting overlaps instead requires splitting each interval into a +1 event and a −1 event and sweeping them in time order.

    7.2Recognition signals

    SignalStructural reason
    Input is a set of [start, end] pairs; output is merged ranges, gaps or a countThe interval graph's connected components are contiguous runs once sorted by start.
    "Minimum number of rooms / platforms / machines"The answer is the maximum depth of overlap at any instant: a sweep over events.
    Several schedules, each already sortedA k-way merge (heap) or a two-pointer walk replaces the global sort.
    "Remove the fewest to make non-overlapping", "maximum number of non-overlapping"That is selection, not merging: greedy by end time (Pattern 14).

    Ask yourself. "Am I combining intervals (merge), counting simultaneous intervals (sweep or heap), or choosing a subset of intervals (greedy)? And do touching endpoints overlap?"

    When it is inappropriate. Use a different structure when intervals arrive online and you need fast insert plus overlap queries (a TreeMap keyed by start, or a segment tree over compressed coordinates), when intervals carry weights and you select a subset (DP over sorted intervals plus binary search), or when the "intervals" are 2D rectangles (sweep plus a segment tree).

    Confused withHow to tell them apart
    Greedy interval scheduling (Ch. 14)Merging keeps all intervals and sorts by start. Scheduling discards some and sorts by end, because the earliest finish leaves the most room.
    Difference array / prefix sumIf coordinates are small integers, diff[s]++, diff[e]-- plus a prefix sum computes the depth directly. Sweep with sorting is the coordinate-free version.
    Two pointers (Ch. 1)Intersecting two sorted interval lists (LeetCode 986) is two pointers over lists; no merging happens.

    7.3Concepts and invariants

    Overlap conditions. Closed intervals [a, b] and [c, d] overlap iff max(a, c) ≤ min(b, d); they are disjoint iff b < c or d < a. For half-open [a, b) and [c, d), replace ≤ with <, so touching intervals do not overlap.

    Sweep-line invariant. Map each interval to events (start, +1) and (end, −1), and sort by time.     Essential takeaways

    Part II · Pattern 08

    Backtracking: DFS with Choices

    A depth-first walk over an implicit tree of partial solutions: make a choice, explore, undo it, and cut off subtrees that cannot lead to a valid answer.

    8.1Pattern identity

    Primary purpose
    Enumerate every configuration satisfying constraints (subsets, permutations, partitions, placements), or find one, when the output or search is inherently exponential.
    Typical input
    A small set of candidates (n ≤ 10–20), a target, a board, or a string to partition.
    Interview applications
    Subsets, permutations, combinations, combination sum, palindrome partitioning, word search, N-Queens, Sudoku, generating parentheses, letter combinations.
    Key insight
    Each recursion level makes one decision. The path from the root to a node is the partial solution, and restoring state after each child keeps one shared mutable path correct for every branch.

    Key insight. Correctness comes from two things: the choice tree generates every valid configuration exactly once (canonical ordering), and pruning removes only subtrees that provably contain no solution.

    8.2Recognition signals

    SignalStructural reason
    "Return all …" (subsets, permutations, partitions, boards)The output itself can be exponential, so no polynomial algorithm can do better than enumerating it.
    n ≤ 10 (permutations) or n ≤ 20 (subsets)n! ≈ 3.6 · 106 at n = 10; 220 ≈ 106.
    Constraint satisfaction: place items so that no two conflictPartial assignments can be checked incrementally and abandoned early.
    Decisions are sequential, and each depends on earlier choicesThat is a natural tree with "choose → explore → undo".

    Ask yourself. "Do I need the configurations themselves, or only how many or the best one?" If only a count or optimum is needed and subproblems repeat, switch to DP or memoisation.

    When it is inappropriate.

    • Counting or optimisation with overlapping states: the number of combinations summing to a target (Coin Change II) has polynomial DP; plain backtracking is exponential.
    • Large n with a smooth objective: use greedy, DP or a graph algorithm.
    • Shortest number of steps in a state space: BFS finds the minimum without exploring every path.
    Confused withHow to tell them apart
    Graph DFS (Ch. 9)DFS marks nodes visited permanently and visits each once. Backtracking unmarks on return, so the same node or element can appear on different paths.
    Top-down DPMemoised DFS caches results by state. Backtracking has no reusable results, because each path's output is distinct.
    BFS on statesBFS suits "fewest moves" questions. Backtracking suits "all solutions" or "any solution with deep pruning".

    8.3Concepts and invariants

    Choose → explore → undo. Maintain the invariant "on entry to dfs, the shared state equals exactly the choices on the current root-to-node path". Every mutation before the recursive call must be reversed after it. Copy the path into the output only when recording (new ArrayList<>(path)), because the path object keeps changing.

    Combinations vs permutations.

    Combination / subsetPermutation
    Order matters?No: {1,2} = {2,1}Yes
    Canonical generationA start index: only choose elements at positions ≥ start (increasing indices)A used[] array: any unused element at every level
    Reuse allowed (39)Recurse with i instead of i + 1Drop used[]
    Leaves / outputs2n subsets, C(n, k) of size kn! permutations
    CostO(n · 2n) including copyingO(n · n!)

    Duplicate avoidance with repeated values. Sort first. At one tree level (one loop over i), skip a value equal to its predecessor at that level:

    Combinations (Subsets II, Combination Sum II): if (i > start && a[i] == a[i−1]) continue; Permutations (Permutations II): if (i > 0 && a[i] == a[i−1] && !used[i−1]) continue; Meaning: among equal values, always pick them left to right. Choosing a later copy first would produce the same multiset or sequence again.

    Pruning. A prune is valid when it is sound, meaning no solution lies in the cut subtree. Typical sound prunes: remaining target < 0 (with positive candidates), sorted candidates with a[i] > remain → break (every later candidate is larger), and conflict checks in O(1) using auxiliary arrays (N-Queens columns and diagonals). Pruning does not change the worst case for output-bound problems, but it often decides whether a constraint-satisfaction search finishes at all.

    When the problem needs memoisation instead of plain backtracking

    Backtracking explores paths. If two different paths reach the same state and the rest of the computation depends only on that state, the subtree below it is solved repeatedly. Example: "number of combinations of coins summing to T" has state (index, remaining), with only n · T distinct states, but exponentially many paths reach them.

    • Test: can you write the function's result in terms of a few parameters only (index, remaining, mask), without the path contents? If so, memoise on those parameters.
    • Enumeration remains exponential even with memoisation, because the output size is exponential. Memoisation pays off for count / exists / best.
    • Hybrid: Word Break II memoises the list of sentences per suffix index; that still has exponential output, but avoids recomputing dead ends.

    Template A — combinations and subsets (start index, optional duplicate skip).

    Template B — permutations (used[] array, duplicate-safe).

    Template C — when only a count is needed: memoise the state, not the path.

    8.5Complexity and pitfalls

    Time(number of tree nodes) × (work per node). Subsets O(n · 2n); permutations O(n · n!); N-Queens O(n!) upper bound with heavy pruning.
    Auxiliary spaceO(depth) recursion + path. The output is not counted, but it dominates memory in practice.
    Off-by-oneRecursing with start + 1 instead of i + 1 (generates duplicates or misses some); recording before or after the base check inconsistently.
    Wrong invariantForgetting to undo (state leaks into sibling branches); adding path itself instead of a copy (every output ends up as the final, empty path).
    OverflowRarely relevant. Memoised counts can exceed int, so use long or the modulus the problem requires.
    Breaks naive codeDuplicate input values (needs sorting + level skip); break pruning on unsorted candidates (unsound); a target of 0.
    Interview follow-upsHandle duplicates (Subsets II, Permutations II, Combination Sum II); only count solutions (memoise or DP); iterative generation (bitmask for subsets, next-permutation); estimate the number of nodes visited.

    8.6Pattern mastery checklist

    Essential takeaways

    • Shared state must equal the current path on every entry: choose, explore, undo.
    • A start index gives combinations; used[] gives permutations; recursing with i allows reuse.
    • Sort plus a same-level skip removes duplicates without a set of results.
    • Prune only with provable bounds; break requires sorted candidates.
    • Count or optimise with repeated states → memoise (Template C) or bottom-up DP.

    Recognition rule. "Return all valid configurations" with small n → a choice tree with undo. "How many" with repeated states → memoised DFS.

    In-interview checklist

    • What is one decision per level, and what is the base case?
    • Combination (start index) or permutation (used[])? Reuse allowed?
    • Duplicates in the input? Sort + level skip.
    • Which prunes are sound?
    • Am I copying the path when recording?

    Key distinction. DFS on a graph visits each node once (visited persists). Backtracking revisits elements on different paths (state is undone). Using a permanent visited set in backtracking silently loses solutions.

    Pitfall. With duplicate values (LeetCode 47), this produces repeated permutations. Add sorting and the !used[i−1] skip from Template B. A swap-based in-place variant also exists, but its duplicate handling is harder to get right.

    Combination Sum

    Medium

    Task. Given distinct positive candidates and a target, return all unique combinations (each candidate reusable without limit) that sum to the target.

    Key insight

    Reuse is allowed, so recurse with the same index i. Uniqueness of combinations is still enforced by never going back to smaller indices.

    Why the pattern applies

    We need every combination, which is a classic choice tree. With sorted candidates, candidates[i] > remain lets us break: a sound prune, because all later candidates are larger.

    Approach
    1. Sort. dfs(start, remain): if remain == 0, record.
    2. For i ≥ start: if c[i] > remain, break; otherwise choose, recurse with (i, remain − c[i]), undo.

    TimeO(NT/m + 1) worst case (T target, m min candidate)SpaceO(T/m) recursion depth

    Pitfall. Looping from 0 instead of start produces [2,3] and [3,2] as separate answers. If the interviewer asks only for the number of combinations, switch to Template C or the coin-change DP. Exponential enumeration is then unnecessary.

    N-Queens

    Hard

    Task. Return all distinct placements of n non-attacking queens on an n × n board, as lists of strings.

    Key insight

    Place exactly one queen per row, so rows never conflict. A column, a "\" diagonal (r − c constant) or a "/" diagonal (r + c constant) is each a single index into a boolean array, which makes every conflict check O(1).

    Why the pattern applies

    This is constraint satisfaction with incremental checking. Most partial boards are rejected after a few rows, so the search tree is far smaller than nn.

    Approach

    2. Place the queen (set three flags and queenCol[row] = c), recurse to row + 1, then clear the flags.
    3. At row == n, render the board from queenCol.

    TimeO(n!) upper bound (+ O(n²) per solution to render)SpaceO(n) flags and recursion

    Pitfall. The "\" diagonal index r − c is negative without the + n − 1 offset. Scanning the board to check attacks costs O(n) per placement instead of O(1). For N-Queens II (count only) the same search applies; bitmasks make it faster, but counting still needs the search, because states do not repeat in a way memoisation can exploit.

    Part II · Pattern 09

    Recursion / DFS on Trees and Graphs

    Solve a structure by solving its substructures: a node's answer is computed from its children's answers. On graphs, a visited set ensures each node is processed once.

    9.1Pattern identity

    Primary purpose
    Compute tree aggregates (height, sums, best paths), validate tree properties, explore connected components, and detect reachability in grids and graphs.
    Typical input
    A TreeNode root, a 2D grid (an implicit graph with 4- or 8-neighbours), an adjacency matrix or list.
    Interview applications
    Depth, balance, diameter, LCA, path sums, serialisation, number of islands, flood fill, provinces, cycle detection, bipartiteness, clone graph.
    Key insight
    Decide what the recursive call returns (information flowing up to the parent) separately from what it records (a global answer that may combine both children). Most hard tree problems are this distinction.

    Key insight. Define the function's contract in one sentence, for example "gain(node) = the best downward path sum starting at node". Then trust it for the children. Correctness follows by structural induction: if the contract holds for the children, the combination step makes it hold for the node.

    9.2Recognition signals

    SignalStructural reason
    Answer for a tree = f(answers for its subtrees)Trees are recursively defined, so postorder computes children first.
    "Number of islands / regions / provinces / groups"Count the connected components: one DFS launch per unvisited node.
    Reachability, "can we get from A to B", flood a regionDFS visits the full component of the start node. Order and distances are irrelevant.
    Path-shaped answers in trees (max path, diameter)Every path has a unique highest node, so enumerate paths by their apex during the postorder.

    Ask yourself. "What must each child tell its parent, and does the final answer need more than that (a global)?" On graphs: "When do I mark visited, and can the recursion get too deep?"

    When it is inappropriate. Use BFS for fewest steps in unweighted graphs, since DFS finds a path, not the shortest. Use DSU for connectivity under incremental edge additions with many queries. Avoid deep recursion on inputs that allow O(n) depth with n around 105–106 (a skewed tree, a snake-shaped grid); switch to iteration.

    Confused withHow to tell them apart
    Backtracking (Ch. 8)DFS marks visited permanently: each node is processed once, O(V + E). Backtracking unmarks and explores paths, which is exponential.
    BFS (Ch. 10)Both traverse components in O(V + E). Only BFS gives shortest unweighted distances; DFS gives pre/post order, which matters for topological order and tree DP.
    Union-Find (Ch. 17)For a static graph DFS is simplest. DSU is better when edges arrive over time or the question is only "same component?".

    9.3Concepts and invariants

    Traversal order is a modelling choice.

    OrderWork happens…Use when
    PreorderBefore the children; passes information down (depth, path so far, bounds)Path sum from the root, BST validation with (lo, hi) bounds, serialisation
    InorderBetween the childrenBSTs: visits keys in sorted order (k-th smallest, validate BST)
    PostorderAfter the children; aggregates information upHeight, diameter, max path sum, subtree sums, tree DP

    Return value vs global state. For Binary Tree Maximum Path Sum the parent can only extend a downward path, one that uses at most one child, so that is what gain() returns. The best path through a node may use both children, but it cannot be extended upward, so it is recorded in a global maximum. The same split appears in diameter, longest univalue path and house robber III, where the returned value is a pair.

    gain(v) = v.val + max(0, gain(v.left), gain(v.right)) (returned: extendable) best = max over v of v.val + max(0, gain(v.left)) + max(0, gain(v.right)) (recorded) gain(null) = 0

    Visitation rules on graphs. Mark a node visited when you first reach it (before or as you recurse), never after processing it. Otherwise two neighbours may both start on the same node, and cycles recurse forever. In grids you may mark in place (e.g. overwrite '1' with '0'), which saves memory but destroys the input. Say so, or copy the grid.

    Connected components. The outer loop over all nodes launches one DFS per unvisited node. The number of launches equals the number of components, and each node and edge is touched O(1) times, so the total is O(V + E): O(n²) for an adjacency matrix, O(mn) for an m × n grid.

    Recursion depth and iterative alternatives

    Java's default thread stack (often 512 KB–1 MB) holds roughly 104–105 frames, depending on frame size. A skewed tree with 105 nodes, or a 300 × 300 grid of land in a snake pattern (90,000 cells), can therefore overflow with StackOverflowError.

    • Explicit stack (ArrayDeque): push the start, pop, and push unvisited neighbours, marking them when pushed. This handles preorder-style processing directly.
    • Postorder iteratively: push (node, state) pairs, or use two stacks (reverse of root-right-left preorder), or keep a "children done" flag. This is needed for tree DP without recursion.
    • BFS is a drop-in replacement whenever order does not matter (counting components, flood fill).
    • Larger stack: new Thread(null, task, "dfs", 1 << 26).start() is a valid engineering fix, but interviewers usually prefer the iterative form.

    LeetCode's limits for 104, 200, 547 and 124 are within what recursive Java normally handles, so the solutions below are recursive and Template B shows the iterative grid version.

    9.4Reusable Java templates

    Template A — tree DFS: return what the parent needs, record the global answer (illustrated with the tree diameter).

    Template B — grid DFS, recursive and iterative. The iterative version is the safe default for very large grids.

    Template C — components of an undirected graph given as an edge list (adjacency list + recursive DFS).

    9.5Complexity and pitfalls

    TimeTrees O(n). Graphs O(V + E) with an adjacency list, O(V²) with an adjacency matrix. Grids O(m · n).
    Auxiliary spaceRecursion O(h) for trees (h = n when skewed, log n when balanced); O(V) visited plus O(V) worst-case stack for graphs; O(mn) for grids.
    Off-by-oneBounds checks after array access (g[r][c] before r >= 0); counting depth in edges vs nodes (104 counts nodes).
    Wrong invariantReturning the two-sided path to the parent (124); marking visited after the recursion (infinite loops on cycles).
    OverflowPath sums with values up to 1000 and 3 · 104 nodes fit in int. Initialise the global max to Integer.MIN_VALUE, not 0, when all values may be negative.
    Breaks naive codeAn empty tree; all-negative values (124); a single-cell grid; self-loops in isConnected (diagonal = 1); a skewed tree that overflows the stack.
    Interview follow-upsMake it iterative; don't mutate the input; return the path itself (store parent pointers or the argmax); handle 8-directional grids; count island shapes (canonical path encoding).

    9.6Pattern mastery checklist

    Essential takeaways

    • Write the function contract first, then trust it for the children (structural induction).
    • Separate the returned value (extendable) from the recorded global (complete).
    • Mark visited on first contact; one outer-loop launch per component.
    • Know the recursion-depth risk and have the explicit-stack version ready.
    • Pick pre, in or post order by the direction information flows.

    Recognition rule. The answer at a node is composed from its children, or the question is about components or reachability, so use DFS with a clear return contract and a visited set.

    In-interview checklist

    • What does the call return? Is there a separate global?
    • What are the base cases (null, out of bounds, visited)?
    • When is a node marked visited? Is mutating the input acceptable?
    • What is the maximum recursion depth for the given constraints?
    • Adjacency matrix or list, and what does that do to the complexity?

    Key distinction. DFS gives connectivity and structural aggregates but not shortest distances. The moment the question says "minimum number of steps", reach for BFS (Ch. 10).

    LC 124

    Binary Tree Maximum Path Sum

    Hard

    Task. A path is any sequence of adjacent nodes, each used at most once, with at least one node. Return the maximum path sum; values may be negative.

    Key insight

    Every path has a unique highest node (its apex). At the apex the path is val + left downward gain + right downward gain, where a negative gain is replaced by 0 (don't take that branch). The parent, however, can only extend a single downward chain.

    Why the pattern applies

    This is postorder tree DP with the return-versus-global split (see 9.3): gain() returns the one-sided chain and best records the two-sided path.

    Approach

    TimeO(n)SpaceO(h) recursion

    Pitfall. Initialising best = 0 returns 0 for an all-negative tree such as [-3], but a path must contain at least one node, so the answer is −3.     Part II · Pattern 10

    BFS and Level Order: Shortest Path in Unweighted Graphs

    Breadth-first search explores states in non-decreasing order of edge count. When every edge costs the same, the first time a state is reached is along a shortest path. Grids, word transformations and puzzle states are all graphs, even when no adjacency list is given.

    10.1Pattern identity

    Primary purpose
    Minimum number of steps (edges) from one or many sources; level-by-level processing; reachability with bounded memory per layer.
    Typical input
    Grid (4- or 8-directional moves), explicit adjacency list, or an implicit state space with a neighbour generator (words differing by one letter, lock combinations, board states).
    Interview applications
    Shortest path in a maze, spreading processes (rot, fire, infection), distance to nearest X, word ladder, tree level-order / right-side view, minimum moves in puzzles, bipartiteness check.
    Key insight
    A FIFO queue processes all states at distance d before any at distance d + 1. With unit weights, a state's first discovery fixes its shortest distance, so marking it visited at enqueue time is both correct and minimal.

    Key insight. BFS is Dijkstra with a priority queue that happens to be FIFO, which works only because every edge adds exactly 1. Change one weight and the guarantee disappears.

    10.2Recognition signals

    SignalStructural reason
    "Minimum number of moves / steps / transformations"Each move is one unweighted edge, so the answer is the BFS layer of the target.
    "After how many minutes does everything …" / simultaneous spreadingAll sources expand in lock-step, so this is a multi-source BFS whose level count is the elapsed time.
    "Distance from each cell to the nearest X"Reverse the direction: start from every X at once. One BFS gives all distances in O(cells).
    States are generated by small local editsAn implicit graph: the neighbour generator replaces an adjacency list.
    Level-wise output for treesSnapshot queue.size() to delimit levels.

    Ask yourself. "Does every move cost the same, and do I need the fewest moves (or everything in layer order)?" If yes, BFS. If moves have different costs, it is not BFS.

    When it is inappropriate.

    • Weighted edges with different weights: use Dijkstra (Pattern 18). With weights in {0, 1}, use 0-1 BFS (a deque: push-front for 0, push-back for 1).
    • Pure reachability / component work (flood fill, islands): BFS works but carries no extra benefit over DFS. Pick whichever avoids recursion-depth risk.
    • Counting all paths or enumerating them: BFS finds distances, not all paths. You need backtracking or DP over the BFS DAG.
    • Huge branching with a known target: consider bidirectional BFS, which reduces bd to about 2·bd/2.
    Confused withHow to tell them apart
    DFSDFS reaches every node too, but in an order unrelated to distance. Its first visit is not the shortest path. Use DFS for structure (components, cycles, subtree aggregates) and BFS for distance.
    DijkstraDijkstra generalises BFS to non-negative weights at a log-factor cost. On unit weights both give identical distances, so BFS is the simpler choice.
    DP on a gridIf moves are restricted to right/down (a DAG), DP in row-major order is simpler. If moves go in all four directions (cycles), you need BFS.

    10.3Concepts and invariants

    The layer invariant. At any moment the queue contains nodes from at most two consecutive layers, d and d + 1, with every layer-d node ahead of every layer-(d+1) node.

    Claim: when node v is first enqueued from u, dist(v) = dist(u) + 1. Proof sketch: nodes are dequeued in non-decreasing dist order (layer invariant). If a shorter path to v existed, its predecessor w would have dist(w) < dist(u) and was dequeued earlier, so it would already have enqueued v. Contradiction.

    Visited-state timing. Mark a node visited when it is enqueued, not when it is dequeued. Marking at dequeue lets the same node be enqueued many times by different neighbours in the same layer. Distances stay correct, but the queue can grow to O(E), or exponentially in implicit graphs, and lead to TLE or MLE. The exception is weighted search (Dijkstra), where the distance is final only at dequeue time.

    Level boundaries. Two equivalent techniques:

    • Size snapshot: for (int k = q.size(); k > 0; k--) processes exactly one layer, and the loop counter is the level.
    • Distance array: store dist[v] = dist[u] + 1 at enqueue time; no layer loop is needed. This is more flexible (multi-source, and the visited test becomes dist[v] == -1).

    Multi-source BFS. Enqueue all sources with distance 0 before starting. This is the same as adding a virtual super-source S with a 0-weight edge to each real source, then running BFS from S. The result is dist[v] = min over sources s of dist(s, v) in a single O(V + E) pass, compared with O(k · (V + E)) for k separate BFS runs.

    Implicit graph modelling: how to design the state

    A state must contain everything that affects future moves. In a grid with keys, the state is (row, col, keysMask). With a limit on wall breaks, it is (row, col, breaksLeft). The visited set is over states, not cells. The BFS cost is O(#states × branching), so estimate it before coding.

    For word problems, the neighbour generator is either "all words at Hamming distance 1", generated by trying 26 letters at each position (O(L · 26) per word with a hash-set lookup), or pattern buckets like h*t that map to the words matching them. For dictionaries of size N with word length L, generation by letter substitution costs O(N · L · 26 · L) including string building and hashing.

    10.4Reusable Java templates

    Template A — single/multi-source BFS on a grid with a distance array. Reusable: queue, directions, bounds check, enqueue-time marking. Problem-specific: what counts as passable, and which cells are sources.

    Template B — level-order BFS with a size snapshot (adjacency list or implicit graph).

    10.5Complexity and pitfalls

    TimeO(V + E); grid O(m · n); implicit graph O(#states × cost of generating neighbours).
    Auxiliary spaceO(V) for visited plus the queue (the widest layer, up to O(V)).
    Off-by-oneIs the answer the number of edges or the number of nodes on the path? Word Ladder counts words, which is edges + 1. Rotting Oranges counts minutes, which is the last layer index, not the number of layers.
    Wrong invariantMarking visited at dequeue (duplicates); mixing levels when multi-source cells are added mid-search.
    OverflowEncoding r * n + c fits easily; encoding states with masks can need long.
    Breaks naive codeNo sources (answer 0 or −1?), unreachable targets, source equal to target, a start cell that is itself blocked.
    Interview follow-upsReconstruct the path (store parents); all shortest paths (BFS DAG + backtracking); bidirectional BFS; 0-1 BFS; obstacles you may remove (state expansion).

    10.6Pattern mastery checklist

    Essential takeaways

    • BFS distance is optimal only on unit (equal) weights.
    • Mark visited when enqueuing; otherwise the queue can blow up.
    • Multi-source BFS = one virtual super-source; seed all sources at distance 0.
    • "Nearest X from every cell" → BFS outward from all X, not from every cell.
    • Design the state to include everything that changes future moves.

    Recognition rule. Fewest equal-cost moves, or simultaneous spreading → BFS (multi-source when there are many starts).

    In-interview checklist

    • What is a node (state), and how are neighbours generated?
    • Are all edges the same cost?
    • Single or multi-source? Should I reverse the direction?
    • Do I need layer counts (size snapshot) or per-node distances (dist array)?
    • Edges vs nodes in the answer; unreachable case.

    Key distinction. DFS answers "is it connected / what is the structure?"; BFS answers "how far?". Only BFS's first discovery is a shortest path.

    Part II · Pattern 11

    Topological Sort: DFS / Kahn's Algorithm

    A topological order lists the vertices of a directed graph so that every edge points forward. It exists exactly when the graph is acyclic, so every topological-sort algorithm is also a directed-cycle detector.

    11.1Pattern identity

    Primary purpose
    Order tasks under "u must come before v" constraints, decide whether such an order exists, and run DP over a DAG in dependency order.
    Typical input
    n items plus a list of directed pairs (prerequisites, build dependencies, precedence derived from sorted data).
    Interview applications
    Course schedules, build systems and package managers, task scheduling with dependencies, alien dictionary, longest path in a DAG, detecting deadlock or terminal (safe) nodes.
    Key insight
    A vertex with no remaining incoming edges can be placed next; removing it may free others (Kahn). Equivalently, in DFS a vertex finishes only after everything reachable from it, so reverse finishing order is topological.

    Key insight. Ordering is possible if and only if there is no directed cycle. Kahn's algorithm detects a cycle when it emits fewer than n vertices; DFS detects one when it meets a gray (in-progress) vertex.

    11.2Recognition signals

    SignalStructural reason
    "Prerequisite", "depends on", "must happen before"Each constraint is a directed edge; the question is about a linear extension of a partial order.
    "Is it possible to finish all …"Existence of a topological order is equivalent to the graph being acyclic.
    Order must be inferred from sorted examplesAdjacent pairs in sorted data reveal precedence edges (alien dictionary).
    Nodes whose every path ends in a terminal / never reaches a cycleTopological processing on the reversed graph peels off terminal nodes.
    Longest or shortest path / DP on a DAGProcessing in topological order guarantees predecessors are final before use.

    Ask yourself. "Is this a directed relation where something must precede something else, and do I need an order or a cycle verdict?"

    When it is inappropriate.

    • Cyclic dependency structures: a topological order does not exist. The algorithms can only report the cycle. Strongly connected components (Tarjan/Kosaraju) are needed to condense cycles into a DAG first.
    • Undirected graphs: "ordering" is meaningless. Undirected cycle detection uses DSU or DFS with a parent check, not indegrees.
    • Weighted shortest paths on general graphs: use Dijkstra. Topological-order relaxation works only on DAGs, though there it handles negative weights in O(V + E).
    Confused withHow to tell them apart
    BFS (Pattern 10)Kahn's algorithm uses a queue but processes vertices when their indegree reaches zero, not when first discovered. It computes no distances.
    Plain DFS visited setTwo states (visited / not) cannot tell a back edge (cycle) from a cross edge to a finished vertex. Three colours are required in directed graphs.
    Union-FindDSU ignores direction. It cannot detect directed cycles or produce orders.

    11.3Concepts and invariants

    Kahn's invariant. The queue holds exactly the vertices whose indegree has dropped to 0 and which have not yet been emitted. Every emitted vertex has had all its predecessors emitted before it.

    indeg(v) = number of edges (u → v) with u not yet emitted Emit u ⇒ for each u → v: indeg(v)--, and enqueue v when indeg(v) becomes 0 Termination: emitted == n ⇔ graph is a DAG If a cycle exists, no vertex on it can ever reach indegree 0 (each has a predecessor on the cycle).

    DFS colouring. White = unvisited, gray = on the current recursion stack, black = finished (all descendants explored).

    • An edge to a gray vertex is a back edge, which proves a directed cycle.
    • An edge to a black vertex is safe: that vertex's subtree is complete and acyclic.
    • When a vertex turns black, every vertex reachable from it is already black. Appending on finish gives reverse topological order, so reverse the list (or prepend).
    Why reverse postorder is a valid topological order

    Take any edge u → v. When DFS explores this edge, v is either white (then v is visited and finished inside u's call, so finish(v) < finish(u)), black (already finished, so finish(v) < finish(u)), or gray (a back edge, meaning a cycle, which a DAG excludes). In a DAG, therefore, finish(v) < finish(u) for every edge, and sorting by decreasing finish time puts u before v.

    Choosing between them. Kahn is iterative (no recursion-depth risk), naturally gives a lexicographically smallest order with a priority queue, and supports "process in parallel rounds" questions (the number of BFS layers is the minimum number of semesters). DFS is shorter when you already have a recursive traversal, and its colour states answer "which nodes can reach a cycle?" (Problem 802).

    Alien dictionary: special constraints
    • Only the first differing character of two adjacent words gives information; later characters are unconstrained.
    • If word A is a proper extension of word B but appears before B (e.g. "abc" before "ab"), no ordering is valid, so return "".
    • Comparing only adjacent pairs is sufficient: sorted order is transitive, so non-adjacent constraints are implied.
    • Every letter that appears must be output, including letters with no constraints.
    • Several valid orders may exist; any one is accepted.

    11.4Reusable Java templates

    Template A — Kahn's algorithm (BFS on indegrees). Directed graph: edges[i] = {u, v} means u → v (u before v). Returns an order, or an empty array if there is a cycle.

    Template B — DFS with three colours and reverse postorder. Iterative alternatives exist, but recursion is the interview norm. Note that the depth can reach V.

    11.5Complexity and pitfalls

    TimeO(V + E) for both algorithms; O(V log V + E) for the lexicographic Kahn variant with a heap.
    Auxiliary spaceO(V + E) for the adjacency list; O(V) for indegrees or colours; DFS recursion O(V) in the worst case.
    Edge directionLeetCode 207/210 give [a, b] meaning "to take a you must first take b", so the edge is b → a. Reversing it silently yields a reversed order (accepted for 207, wrong for 210).
    Wrong invariantA two-state visited array in directed DFS reports false cycles (cross edges) or misses real ones (if visited is reset incorrectly).
    Breaks naive codeDisconnected components (start DFS from every vertex / seed every indegree-0 vertex); duplicate edges (each must increment indegree, which is fine if counted consistently); self-loops (immediate cycle).
    Interview follow-upsLexicographically smallest order (heap); minimum number of semesters (count Kahn layers); is the order unique (queue size always 1); longest path in a DAG; parallel scheduling with durations.

    11.6Pattern mastery checklist

    Essential takeaways

    • Topological order exists ⇔ the directed graph is acyclic.
    • Kahn: emitted count < n ⇒ cycle. DFS: an edge to a gray vertex ⇒ cycle.
    • DFS order is reverse postorder; forgetting to reverse is the classic bug.
    • Get edge direction right from the problem's wording before writing code.
    • Reverse the graph to ask "which nodes only lead to terminals?".

    Recognition rule. Directed "before/after" constraints + "find an order" or "is it possible" → topological sort (and its built-in cycle check).

    In-interview checklist

    • Which way do the edges point?
    • Kahn (iterative, layers, lexicographic) or DFS (colour states)?
    • Are all vertices covered, including isolated ones?
    • What is returned for a cycle: false, empty array, or ""?
    • Are there duplicate edges or self-loops?

    Key distinction. Kahn's queue releases a node when its last dependency is satisfied; BFS releases a node when its first neighbour is seen.

    Course Schedule

    Medium

    Key insight

    Why the pattern applies

    This is the cycle-detection half of topological sort. It is solved here with Template B (the DFS variant) for contrast with 210. Direction does not affect the verdict, because reversing all edges preserves cycles.

    LC 802

    Find Eventual Safe States

    Medium

    Task. In a directed graph (graph[i] lists i's successors), a node is safe if every path from it ends at a terminal node (out-degree 0). Return all safe nodes in ascending order.

    Key insight

    A node is safe ⇔ it cannot reach a cycle. Terminal nodes are safe; a node becomes safe once all its successors are known safe. That is Kahn's algorithm on the reversed graph, driven by out-degrees.

    Why the pattern applies

    Peeling off nodes whose remaining out-degree is 0 is a topological sort from the sinks backwards. Nodes on or leading into cycles never reach out-degree 0. (The DFS alternative: a node is safe ⇔ its DFS finishes black without meeting gray.)

    Approach
    1. Build reverse edges v → u for each u → v, and outdeg[u] = graph[u].length.
    2. Queue all terminals. Popping v marks it safe and decrements outdeg of each predecessor u; enqueue u when it hits 0.
    3. Collect safe nodes by scanning 0..n−1 (ascending without sorting).

    TimeO(V + E)SpaceO(V + E)

    Pitfall. A node pointing to itself (a self-loop) is unsafe; its out-degree never reaches 0, so this is handled automatically. The recursive DFS version can hit about 104 depth, while the Kahn version is iterative.

    LC 269

    Alien Dictionary

    HardPremium

    Task. Given words sorted lexicographically in an unknown alphabet, return a string of all letters that appear, in any order consistent with the sorting. Return "" if no valid order exists.

    Key insight

    Each adjacent pair of words gives at most one edge: at the first differing position, w1[j] → w2[j]. A word followed by its own proper prefix is a contradiction no alphabet can fix.

    Why the pattern applies

    The inferred precedences form a directed graph on letters. A valid alphabet is any topological order, and a cycle means the input is inconsistent.

    Approach
    1. Register every letter that appears, with indegree 0.
    2. For each adjacent pair, find the first mismatch and add that edge, deduplicated so indegrees stay consistent. If there is no mismatch and w1 is longer, return "".
    3. Run Kahn over the present letters. If fewer letters are emitted than are present, return "".

    TimeO(C + 26²), where C is the total number of charactersSpaceO(26²) = O(1) alphabet-bounded

    Pitfall. Three classic bugs: (1) comparing beyond the first mismatch; (2) missing the invalid-prefix check; (3) counting duplicate edges twice in the indegree without adding them twice to the adjacency, or the reverse. Either inconsistency corrupts Kahn's count.

    Part II · Pattern 12

    Dynamic Programming: 1D

    One-dimensional DP indexes subproblems by a single position (a prefix, a suffix or an amount). The hard part is not the loop but the state definition: a sentence describing exactly what dp[i] means, which makes the recurrence almost write itself.

    12.1Pattern identity

    Primary purpose
    Count ways or optimise over a sequence of decisions where each decision's future depends only on a single index (or one scalar resource).
    Typical input
    An array or string processed left to right (or right to left); an integer target or amount; a set of items with a single capacity.
    Interview applications
    Stairs / tiling, house robber, decode ways, word break, coin change, LIS (O(n²) form), string partitioning with a validity rule, 0/1 and unbounded knapsack (compressed).
    Key insight
    If the best (or the number of ways) for position i can be built from a bounded set of smaller positions, and those answers do not depend on how they were reached, then each subproblem is solved once and the exponential recursion tree collapses to O(n · transitions).

    Key insight. A correct state answers "what does the rest of the problem need to know about the past?". If two different histories with the same i can lead to different futures, the state is missing a dimension.

    12.2Recognition signals

    SignalStructural reason
    "Number of ways" (often mod 109+7)Counting overlapping decompositions: the sum rule over disjoint last choices.
    "Maximum / minimum total" over choices with local constraints (no two adjacent)The optimal substructure: best(i) = best over last choice of (best(earlier) + gain).
    A brute-force recursion that recomputes the same argumentsOverlapping subproblems; memoise the arguments, and they become the state.
    Splitting a string/array into valid piecesdp over prefix (or suffix) length; transition = length of the last (or first) piece.
    Pick a subset hitting a sum, small totalPseudo-polynomial knapsack: state = (item, sum), compressed to sum.

    Ask yourself. "If I knew the answers for all smaller indices, could I compute this one with a constant or small number of choices, and does the answer for index j depend only on j?"

    When it is inappropriate.

    • A greedy choice is provably safe (for example, interval scheduling by earliest end): DP is correct but slower and wordier.
    • The state needs two indices (two strings, a grid, a range [i, j]): that is Pattern 13 or interval DP. Forcing 1D gives wrong answers.
    • All solutions must be listed: DP counts them, but listing requires backtracking (possibly guided by DP).
    • Values are huge (sum up to 109): a sum-indexed DP array is infeasible, so look for another structure.
    Confused withHow to tell them apart
    GreedyGreedy commits to one choice per step; DP keeps the best over all choices. A counter-example to greedy (coin denominations {1, 3, 4}, amount 6) means DP.
    BacktrackingSame recursion tree; DP adds memoisation keyed by a small state. If the "path so far" cannot be summarised by a small key, memoisation does not help.
    Prefix sumsPrefix sums aggregate a fixed function; DP chooses among options at each position.

    12.3Concepts and invariants

    The four parts of a DP. Write each down before coding:

    1. State: a precise sentence, e.g. "dp[i] = number of ways to split the suffix s[i..n−1]".
    2. Transition: case analysis on the last (or first) decision. The cases must be disjoint for counting and exhaustive for both counting and optimisation.
    3. Base case: the empty prefix or suffix. In counting DP the empty problem has exactly 1 way, not 0.
    4. Order: compute every dependency before its use (increasing i for prefix states, decreasing i for suffix states).
    Counting : dp[i] = Σ over disjoint last choices c dp[prev(i, c)] (sum rule) Optimising : dp[i] = max over last choices c ( dp[prev(i, c)] + gain(c) ) House Robber: dp[i] = max(dp[i−1], dp[i−2] + a[i−1]) over prefix length i (skip house i−1) (rob house i−1, so house i−2 must be skipped)

    State dependencies and space optimisation. If dp[i] reads only dp[i−1] and dp[i−2], keep two variables: O(1) space. If it reads a window of size w (a piece of at most w digits), keep a circular buffer of size w + 1. The rolling update must read the old values before overwriting them.

    Counting vs optimisation. Counting needs disjoint cases (no double counting) and a modulus. Optimisation tolerates overlapping cases (max is idempotent) but needs a sentinel such as Integer.MIN_VALUE / 2 or −∞ for impossible states, so that adding to it does not overflow.

    When a 1D array is really a compressed 2D state (knapsack)

    In 0/1 knapsack the true state is dp[i][s] = ways using the first i items to reach sum s:

    dp[i][s] = dp[i−1][s] + dp[i−1][s − w_i]

    Row i reads only row i−1, so one array suffices, if dp[s − w_i] still holds the row-(i−1) value when dp[s] is updated. Iterating s in decreasing order guarantees this, because smaller indices have not yet been overwritten. Iterating in increasing order lets item i be used again: that is the unbounded knapsack recurrence dp[i][s] = dp[i−1][s] + dp[i][s − w_i]. Loop direction therefore encodes the problem's semantics.

    Top-down vs bottom-up. Memoised recursion is quicker to derive and visits only reachable states, but costs O(depth) stack. Bottom-up allows space compression and avoids stack overflow. Interviewers accept either, as long as you can state the complexity as (#states × transition cost).

    12.4Reusable Java templates

    Template A — prefix-indexed optimisation with rolling variables.

    Template B — counting partitions of a sequence (suffix DP, modulo). Reusable: the suffix loop and modular sum. Problem-specific: which pieces s[i..j] are valid.

    Template C — 0/1 knapsack count, 2D state compressed to 1D.

    12.5Complexity and pitfalls

    Time(#states) × (cost per transition): O(n) for stairs and robber; O(n · L) for partitions with piece length ≤ L; O(n · S) for knapsack with sum S (pseudo-polynomial).
    Auxiliary spaceO(n) table, O(1) with rolling variables, O(L) with a circular buffer, O(S) for compressed knapsack. Memoised recursion adds O(depth) stack.
    Off-by-oneMixing "dp over prefix length i" (size n + 1, element a[i−1]) with "dp over index i" (size n). Pick one and say it aloud.
    Base casesThe empty sequence counts as 1 way; for climbing stairs, dp[0] = dp[1] = 1. Wrong base values shift every answer.
    OverflowCounts grow exponentially, so take the modulus at each addition and accumulate in long. Climbing stairs with n ≤ 45 fits in int; n = 92 is the limit for long.
    Breaks naive codeLeading zeros in digit partitions; zero-weight items in knapsack (they double the count, which is correct); negative targets; n = 0 or 1.
    Interview follow-upsReconstruct the choices (store argmax or walk back); reduce space; convert to matrix exponentiation for Fibonacci-like recurrences with n ≈ 1018 (O(log n)); circular variants (House Robber II: run twice).

    12.6Pattern mastery checklist

    Essential takeaways

    • Write the state as a sentence before anything else.
    • Derive the transition from the last (or first) decision; for counting, cases must be disjoint.
    • The empty problem has one way (counting) or value 0 / −∞ (optimisation), whichever is semantically correct.
    • Compress space only after the full-table version is correct, and mind the loop direction.
    • If histories with the same index diverge, add a dimension (Pattern 13).

    Recognition rule. Exponential recursion + small repeated arguments → memoise; the arguments are the state.

    In-interview checklist

    • State definition: prefix length, index or amount?
    • Transition cases: disjoint and exhaustive?
    • Base case and answer location (dp[n] or dp[0])?
    • Fill order matches the dependencies?
    • Modulus / sentinel / overflow handled; space reducible?

    Key distinction. 1D DP works when one index summarises the past. The moment you need "position in A and position in B", or "index and remaining capacity" without a safe compression, you are in 2D.

    Approach

    LC 494

    Target Sum

    Medium

    Task. Assign + or − to each of nums (n ≤ 20, 0 ≤ nums[i], Σ ≤ 1000) and count the assignments whose total equals target.

    Classification note. The natural DP state is two-dimensional, (index, running sum). This is a 0/1 knapsack, solved here in its compressed 1D form. The single array is a rolling row of the 2D table, which is why the loop direction is decisive.

    Key insight

    Let P be the elements given +, N the elements given −. Then P − N = target and P + N = total, so P = (total + target) / 2. The problem reduces to counting subsets with sum P.

    sum(P) − sum(N) = target sum(P) + sum(N) = total ⇒ sum(P) = (total + target) / 2 Feasible only if |target| ≤ total and (total + target) is even.
    Why the pattern applies

    Counting subsets by sum is the 0/1 knapsack count (Template C). The state space is O(n · P) instead of the 2n sign assignments.

    Approach
    1. Check the parity and range conditions; return 0 if they fail.
    2. dp[0] = 1; for each x, for s from P down to x: dp[s] += dp[s − x].

    TimeO(n · (total + target)/2)SpaceO(total)

    Pitfall. Increasing iteration over s turns this into an unbounded knapsack and over-counts. Forgetting the parity check gives answers for an impossible half-integer P. The memoised (index, sum) recursion is also accepted; offset the sum by total to index an array.

    Part II · Pattern 13

    Dynamic Programming: 2D

    Two-dimensional DP appears when one index cannot summarise the past: a cell of a grid (row and column), or a pair of prefixes from two sequences. The table is a DAG of subproblems, and the work is choosing transitions, initialising the borders, and filling in an order that respects every dependency.

    13.1Pattern identity

    Primary purpose
    Count or optimise paths on a grid with monotone moves; align, compare or transform two sequences.
    Typical input
    An m × n grid with right/down moves; two strings or arrays of lengths m and n (m, n ≤ a few thousand).
    Interview applications
    Unique paths (with obstacles), minimum path sum, dungeon game, LCS, edit distance, distinct subsequences, interleaving strings, regex / wildcard matching, longest common substring.
    Key insight
    For two sequences, define dp[i][j] over the prefixes a[0..i) and b[0..j). The last characters either match, or one of them is dropped or edited. Every alignment decision is local to (i, j) and the three neighbours (i−1, j), (i, j−1), (i−1, j−1).

    Key insight. Use prefix lengths (an (m+1) × (n+1) table), not indices. Row 0 and column 0 then represent empty prefixes, the base cases become explicit, and the boundary ifs disappear.

    13.2Recognition signals

    SignalStructural reason
    Grid with moves only right/down (or any acyclic move set)The cell graph is a DAG, so row-major order is a topological order. Each cell combines its predecessors.
    Two strings: "common subsequence", "minimum operations to convert", "match pattern"An alignment of two sequences decomposes on the last pair of characters.
    "Subsequence" (not substring) of two inputsCharacters may be skipped independently in each sequence, so there are two indices.
    m, n ≤ 103–5 · 103An O(m · n) table fits in the time budget.
    1D attempt fails because the future depends on progress in two thingsA missing state dimension.

    Ask yourself. "What are the last decisions I could make at (i, j), and which smaller (i', j') does each one lead to?"

    When it is inappropriate.

    • Grids with moves in all four directions contain cycles; there is no fill order. Use BFS (unit cost) or Dijkstra (weighted), Patterns 10 / 18.
    • Substring (contiguous) problems on one string are often better served by a sliding window or by expanding around centres.
    • Very long sequences (105 each): O(mn) is infeasible. Look for special structure (LCS of permutations reduces to LIS in O(n log n)).
    Confused withHow to tell them apart
    1D DPIf the state needs two independent positions, it is 2D. A 1D array can still implement it via a rolling row, but the state is two-dimensional.
    Interval DPdp[i][j] over a single sequence's range [i, j], filled by increasing length (palindromes, burst balloons). Prefix-pair DP is filled row by row.
    BFS on gridsBFS handles arbitrary moves with unit cost. Grid DP handles monotone moves with arbitrary cell costs and counting.

    13.3Concepts and invariants

    Grid DP. With moves right/down, every path to (i, j) enters from (i−1, j) or (i, j−1):

    Count: paths[i][j] = paths[i−1][j] + paths[i][j−1] (0 for blocked cells) Minimise: cost[i][j] = grid[i][j] + min(cost[i−1][j], cost[i][j−1]) Borders: first row / column have a single predecessor

    Two-sequence DP. On prefixes of lengths i and j:

    LCS: L[i][j] = L[i−1][j−1] + 1 if a[i−1] == b[j−1] = max(L[i−1][j], L[i][j−1]) otherwise L[0][j] = L[i][0] = 0 Edit: D[i][j] = D[i−1][j−1] if a[i−1] == b[j−1] = 1 + min( D[i−1][j], // delete a[i−1] D[i][j−1], // insert b[j−1] D[i−1][j−1] ) // replace a[i−1] by b[j−1] D[i][0] = i, D[0][j] = j // convert to / from the empty string
    Why taking the diagonal on a match is always safe

    LCS: if a[i−1] == b[j−1], some optimal common subsequence uses both characters as its last pair. Take any optimal one. If it uses neither, appending the pair makes it longer, a contradiction. If it uses only one of them (say a[i−1] matched to some earlier b[k]), swap that partner to b[j−1]; the length is unchanged. So L[i−1][j−1] + 1 is optimal and the other two options never beat it. The same exchange argument justifies the free diagonal in edit distance (matching costs 0, which is never worse than editing).

    Traversal order. Each cell must be computed after its dependencies. For dependencies on up, left and up-left, row-major order (i ascending, j ascending) works. For dependencies on down/right (such as Dungeon Game), fill from the bottom-right.

    Space compression. If row i depends only on rows i and i−1, keep one row:

    • Up and left only (grid DP): dp[j] = f(dp[j] /*up, old*/, dp[j−1] /*left, new*/), with no extra variable.
    • Also up-left (LCS, edit distance): the old dp[j−1] is overwritten before cell (i, j) is computed, so save it in a variable diag before each overwrite.
    • Compress along the shorter dimension to get O(min(m, n)) space. You lose the ability to reconstruct the alignment unless you use Hirschberg's divide-and-conquer.

    13.4Reusable Java templates

    Template A — grid DP with a rolling row (monotone moves right/down).

    Template B — two-sequence DP on prefix lengths (full table). Reusable: the table shape, the borders and the fill order. Problem-specific: the match and mismatch transitions.

    Template C — rolling row that also needs the diagonal. This is the compression pattern for LCS, edit distance and similar recurrences.

    13.5Complexity and pitfalls

    TimeO(m · n) states × O(1) transitions.
    Auxiliary spaceO(m · n) full table; O(min(m, n)) with a rolling row (alignment reconstruction is then lost).
    Off-by-oneIn prefix-length tables, character i of the prefix is a.charAt(i − 1). Mixing index and length conventions is the most common bug.
    InitialisationEdit distance borders are i and j, not 0. Grid borders have only one predecessor. Obstacle grids zero out everything after a blocked border cell.
    OverflowUnique paths for 100 × 100 is about 2.3 × 1058, but LeetCode 62 guarantees the answer ≤ 2 · 109 for its inputs. The binomial approach needs long intermediates.
    Rolling-row bugsReading dp[j − 1] expecting the old row (it is already new), or forgetting to save the diagonal.
    Interview follow-upsReconstruct the LCS or the edit script (walk back from (m, n)); obstacles; only O(n) memory; weighted edit operations; LCS of k strings (k-dimensional state).

    13.6Pattern mastery checklist

    Essential takeaways

    • Index by prefix lengths; row 0 and column 0 are the empty prefixes.
    • Transitions come from the last pair of characters: match, skip in a, skip in b (or edit).
    • Fill order must follow the dependency arrows.
    • Compress to one row; keep a diag variable when up-left is needed.
    • Four-directional grids are graphs, not DPs.

    Recognition rule. Two sequences compared position by position, or a grid with monotone moves → a (prefix × prefix) or (row × column) table.

    In-interview checklist

    • What do i and j mean: lengths or indices?
    • What are the base row and column values?
    • Which neighbours does a cell read, and does my loop order compute them first?
    • Can I compress, and do I still need the reconstruction?
    • Are empty strings or 1 × 1 grids handled?

    Key distinction. LCS maximises matches (mismatch = skip, cost 0); edit distance minimises edits (mismatch = replace, cost 1, plus insert and delete). The same table shape is used with different transition semantics.

    13.7Assigned problems

    LC 62

    Unique Paths

    Medium

    Task. Count the paths from the top-left to the bottom-right of an m × n grid moving only right or down.

    Key insight

    Paths into a cell arrive from above or from the left, and the two sets are disjoint, so the counts add. Equivalently, a path is a sequence of (m−1) downs and (n−1) rights, giving C(m+n−2, m−1).

    Why the pattern applies

    This is counting grid DP on a DAG (row-major order). A rolling row gives O(n) space.

    Approach
    1. Row 0 is all ones.
    2. For each later row: dp[j] += dp[j−1] (old dp[j] = from above, new dp[j−1] = from the left).

    TimeO(m · n)SpaceO(n)

    Pitfall. The binomial version computes res = res * (n − 1 + i) / i for i = 1..m−1 in long. Each partial product is itself a binomial coefficient, so the division is exact, but computing the full factorial first overflows. With obstacles (63), blocked cells reset dp[j] = 0 and the first row is no longer all ones.

    LC 64

    Minimum Path Sum

    Medium

    Task. Find the minimum sum of a right/down path from the top-left to the bottom-right of a non-negative grid.

    Key insight

    The best path to (i, j) extends the cheaper of the best paths to its two possible predecessors (optimal substructure, since costs add).

    Why the pattern applies

    This is optimisation grid DP (Template A). Dijkstra would also work, but monotone moves make the DP strictly simpler and O(mn) without a log factor.

    Approach
    1. Initialise the first row and column as running sums.
    2. dp[j] = min(dp[j], dp[j−1]) + grid[i][j].

    TimeO(m · n)SpaceO(n), or O(1) by writing into grid (mutating the input)

    Pitfall. Initialising dp to 0 and taking min for border cells picks up a phantom 0-cost predecessor outside the grid. Handle borders explicitly or initialise outside cells to +∞.

    LC 1143

    Longest Common Subsequence

    Medium

    Task. Return the length of the longest common subsequence of two strings (lengths ≤ 1000).

    Key insight

    Look at the last characters of the two prefixes. If they match, they can be paired (the exchange argument above). Otherwise at least one of them is unused, so drop one and take the better result.

    Why the pattern applies

    Two independent sequence positions give a 2D state over prefix lengths (Template B). Brute force over subsequences is 2m.

    Approach
    1. Use a (m+1) × (n+1) table with zero borders.
    2. Fill row-major using the LCS recurrence; the answer is dp[m][n].

    TimeO(m · n)SpaceO(m · n); O(min(m, n)) with a rolling row and a diagonal variable

    Pitfall. Confusing subsequence with substring. Longest common substring resets to 0 on a mismatch and takes a global max, rather than carrying max(up, left). To reconstruct the LCS, walk back from (m, n): go diagonal on a match, otherwise toward the larger neighbour.

    LC 72

    Edit Distance

    Medium

    Task. Return the minimum number of single-character insertions, deletions and replacements to turn word1 into word2 (lengths ≤ 500).

    Key insight

    In an optimal edit script, the last characters are either matched for free, or the last operation is a delete of a[i−1], an insert of b[j−1], or a replace. Each option leaves a smaller prefix pair. Borders are the cost of building from or reducing to the empty string.

    Why the pattern applies

    This is sequence-vs-sequence alignment DP. Each of the three neighbours corresponds to exactly one operation, which makes reconstruction straightforward.

    Approach
    1. dp[i][0] = i, dp[0][j] = j.
    2. On a match, dp[i][j] = dp[i−1][j−1]; otherwise 1 + min(delete, insert, replace).

    TimeO(m · n)SpaceO(m · n); O(min(m, n)) with Template C

    Pitfall. Zero borders (copied from LCS) are wrong here: converting "abc" to "" costs 3. When compressing, the diagonal must be saved before each overwrite (Template C). Follow-ups: one edit away (161: O(n) two-pointer check) and weighted operations (change the 1s).

    Part II · Pattern 14

    Greedy: Interval Scheduling / Local Optimality

    Make the locally best irrevocable choice, then prove with an exchange argument that some optimal solution makes the same choice. On intervals the hard part is usually not the loop but picking the right sort key.

    14.1Pattern identity

    Primary purpose
    Solve optimisation problems in one pass after sorting, by committing to a choice that never needs to be revisited.
    Typical input
    Intervals [start, end], jobs with deadlines, points on a line, or a sequence where every prefix decision can be fixed immediately.
    Interview applications
    Maximum set of non-overlapping intervals, minimum arrows or removals, meeting-room feasibility, jump game, gas station, task scheduling, partition labels.
    Key insight
    For unweighted interval scheduling, the interval that ends earliest leaves the most room for everything else. Any optimal schedule can swap its first interval for that one without losing size.

    Key insight. A greedy algorithm is only as good as its proof. State the choice ("take the compatible interval with the smallest end") and the exchange ("replacing OPT's first interval with mine keeps OPT feasible and the same size"). If the exchange fails on some example, switch to DP.

    14.2Recognition signals

    SignalStructural reason
    "Maximum number of non-overlapping…", "minimum removals so that none overlap", "minimum arrows"Unweighted selection: every interval is worth 1, so only room for future intervals matters. That is exactly what the earliest end maximises.
    "Can one person attend all…?"After sorting by start, the only possible conflict is between neighbours.
    n up to 105 intervalsBudget is O(n log n): one sort plus a linear scan. Interval DP at O(n²) will not fit.
    A choice made now restricts the future only through one scalar (last end, farthest reach)The state collapses to a single number, so no table is needed.

    Ask yourself. "After my choice, is the remaining problem the same kind of problem, and is my choice's effect on it never worse than any alternative's?" The second half is the exchange argument.

    When it is inappropriate.

    • Weighted intervals (maximise total profit, LeetCode 1235): one heavy long interval can beat two light short ones. Sort by end, then DP with binary search for the last compatible interval.
    • Choices interact through more than one scalar (knapsack, coin change with arbitrary coins): local optimality fails on small counterexamples.
    • You need the structure of the union (merged ranges, free time, room counts): this is sweeping or merging (Pattern 7), not selection.
    Confused withHow to tell them apart
    Merge Intervals (Pattern 7)Merging keeps all intervals and computes their union; sort by start. Scheduling discards intervals to keep a compatible subset; sort by end.
    Sweep line / heap (Meeting Rooms II)Counting the maximum simultaneous overlap is a sweep over events. No interval is chosen or rejected.
    Dynamic programmingIf you need to compare "take" against "skip" with different payoffs, it is DP. Greedy is the special case where "take the earliest-ending one" is always at least as good.

    14.3Concepts and invariants

    Exchange argument for earliest end. Sort intervals by end. Let g1 be the first interval with the smallest end and let OPT = o1, o2, … be an optimal compatible set sorted by end.

    end(g₁) ≤ end(o₁) (g₁ has the globally smallest end) o₂ starts at or after end(o₁) ≥ end(g₁) ⇒ {g₁, o₂, o₃, …} is still compatible |{g₁, o₂, …}| = |OPT| ⇒ some optimal solution contains g₁ Induct on the intervals compatible with g₁ ⇒ greedy is optimal.

    The same argument, phrased as "greedy stays ahead", says that after k picks the greedy's k-th end is ≤ OPT's k-th end, so greedy can never fall behind.

    Why sort by end and not by start. Sorting by start and taking the earliest-starting interval fails on [1,100], [2,3], [4,5]: you take one long interval instead of two short ones. Sorting by length fails on [1,5], [4,7], [6,10]: the shortest, [4,7], blocks both others. The end time is the only key whose exchange argument works.

    Boundary convention. LeetCode 435 and 252 treat touching intervals ([1,2] and [2,3]) as compatible, which means half-open semantics. LeetCode 56 and 986 use closed intervals, where touching intervals overlap or intersect at a point. Write the comparison (>= vs >) as a deliberate decision.

    Counting removals is the complement of scheduling

    "Minimum intervals to remove so the rest are non-overlapping" equals n − (maximum compatible subset). Removing a set R leaves a compatible set S = all − R, so minimising |R| is the same as maximising |S|. This reduction is the whole of LeetCode 435. Minimum arrows (452) is the same algorithm with closed intervals: one arrow at the end of each greedy pick bursts every balloon overlapping it.

    When the greedy view is not the full story. Merging (56) and intersecting lists (986) are often filed under greedy because each step commits to something permanently. Their correctness comes from sortedness plus a sweep or two-pointer invariant, not from an exchange argument. The assigned problems below label this explicitly.

    14.4Reusable Java templates

    Template A — maximum compatible subset (earliest end). Reusable: sort by end, keep lastEnd. Problem-specific: the compatibility test (>= for half-open, > for closed).

    Template B — neighbour conflict check after sorting by start.

    14.5Complexity and pitfalls

    TimeO(n log n) for the sort plus an O(n) scan.
    Auxiliary spaceO(log n) to O(n): sorting an int[][] uses TimSort (object array), which can allocate up to n/2 references. A copy via clone() costs O(n) references.
    Off-by-one>= vs > for touching endpoints. Read the problem's convention; 435 says [1,2] and [2,3] do not overlap.
    Wrong invariantSorting by start (or by length) for selection; updating lastEnd on rejected intervals.
    OverflowComparator (x, y) -> x[1] - y[1] overflows when endpoints span more than 231. 435 allows −5·104…5·104 (safe), but other problems allow ±231. Always use Integer.compare.
    Breaks naive codeEmpty input, nested intervals (one inside another), identical intervals, negative coordinates, and lastEnd initialised to 0 instead of the first end.
    Interview follow-upsWeighted version (DP + binary search); return the removed intervals; minimum arrows (452); online arrival of intervals (balanced BST or sweep); proof of optimality.

    14.6Pattern mastery checklist

    Essential takeaways

    • Selection problems sort by end; union or structure problems sort by start.
    • Write the exchange argument in two lines before coding; it doubles as your explanation to the interviewer.
    • "Minimum removals" = n − "maximum kept".
    • Touching endpoints are a per-problem convention; encode it in a single comparison.
    • If intervals carry weights or profits, greedy is wrong; use DP.

    Recognition rule. Unweighted "keep as many as possible" over intervals → sort by end, take each one that fits.

    In-interview checklist

    • Is every interval worth the same? (If not, DP.)
    • Which endpoint is the sort key, and what is my exchange argument?
    • Do touching endpoints overlap in this problem?
    • Is my comparator overflow-safe?
    • Do I mutate the input order, and is that allowed?

    Key distinction. Greedy selection rejects intervals to keep a compatible subset (sort by end). Merging keeps every interval and builds their union (sort by start, Pattern 7).

    LC 252

    Meeting Rooms

    EasyPremium

    Task. Given meeting intervals [start, end], decide whether one person can attend all of them. A meeting ending at time t and another starting at t do not conflict.

    Key insight

    After sorting by start, if any two meetings overlap then some adjacent pair overlaps. Checking neighbours is enough.

    Why the pattern applies

    This is the feasibility special case of scheduling: can we keep all n? The earliest-start order is the order the person would attend them, so each meeting must start no earlier than the previous one ends (Template B).

    Approach
    1. Sort by start with Integer.compare.
    2. Return false if any a[i][0] < a[i−1][1].

    TimeO(n log n)SpaceO(n) worst case for the object-array sort

    Pitfall. Why is the neighbour check sufficient? If meetings i < j overlap (start(j) < end(i)), then start(i+1) ≤ start(j) < end(i), so meeting i+1 already overlaps meeting i. Use <, not <=: back-to-back meetings are fine.

    LC 435

    Non-overlapping Intervals

    Medium

    Task. Return the minimum number of intervals to remove so the rest do not overlap. Touching intervals ([1,2], [2,3]) do not overlap.

    Key insight

    Minimum removals = n − maximum number of compatible intervals, and the maximum is achieved by repeatedly keeping the compatible interval with the earliest end.

    Why the pattern applies

    This is unweighted interval scheduling exactly (Template A). The exchange argument in 14.3 proves the earliest-end greedy keeps a maximum set.

    Approach
    1. Sort by end.
    2. Keep an interval if its start is >= lastEnd, otherwise count it as removed. A rejected interval ends no earlier than lastEnd, so keeping the current one is never worse.

    TimeO(n log n)SpaceO(n) worst case (sort)

    Pitfall. A common alternative sorts by start and, on conflict, keeps the interval with the smaller end (lastEnd = min(lastEnd, end)). That is also correct, but forgetting the min is a frequent bug. Sorting by end avoids the issue entirely.

    LC 56

    Merge Intervals

    Medium

    Task. Merge all overlapping closed intervals (touching ones such as [1,4] and [4,5] merge) and return the disjoint result.

    Classification note. Merge Intervals is a sort-and-sweep problem, not greedy selection: nothing is discarded and there is no exchange argument. It fits this chapter only in the weak sense that each closed group is committed permanently. Chapter 7 solves it with the standard "sort by start, extend the last group" sweep (7 · LC 56). This chapter uses a different technique, the separate-endpoint sweep, which is worth knowing because it also drives room counting and coverage problems.

    Key insight

    Sort starts and ends independently. In sorted order, a merged group ends exactly at position i when starts[i+1] > ends[i]: the i+1 smallest ends all come before the next start.

    Why the technique works

    Let x = ends[i], the (i+1)-th smallest end. Every interval ending by x also starts by x, so the set E of intervals with end ≤ x (size ≥ i+1) is contained in the set S of intervals with start ≤ x. If starts[i+1] > x, then |S| ≤ i+1, so E = S: exactly i+1 intervals lie entirely in (−∞, x] and every other interval starts after x. That is a genuine gap. Conversely, if a gap exists after the first i+1 intervals by start, all of them end before the next start, so their i+1 ends are the smallest i+1 ends and ends[i] < starts[i+1]. The group's end is ends[i] (its largest end) and its start is the first start after the previous cut.

    Approach
    1. Copy starts and ends into two arrays and sort both (primitive sort, no comparator).
    2. Scan i; when i == n−1 or starts[i+1] > ends[i], emit [groupStart, ends[i]] and set groupStart = starts[i+1].

    TimeO(n log n)SpaceO(n) for the two endpoint arrays

    Pitfall. The pairing between a start and its own end is deliberately lost. That is fine for the union, but this technique cannot report which original intervals formed each group. Use the Chapter 7 sweep when you need that.

    LC 986

    Interval List Intersections

    Medium

    Task. Two lists of closed intervals, each pairwise disjoint and sorted, are given. Return their intersection.

    Classification note. The primary technique is two pointers over two sorted lists, essentially a merge step. The greedy element is the advance rule: discard the interval that ends first, because it cannot intersect anything later in the other list.

    Key insight

    Two closed intervals intersect in [max(starts), min(ends)] when that range is non-empty. Whichever interval ends first is exhausted: every later interval in the other list starts after the current one, and the current one already started no later than this end.

    Why the pattern applies

    Both lists are sorted and disjoint, so each pair of current intervals is examined once and one pointer advances per step, which gives O(m + n). This "advance the one that ends earliest" rule is the same earliest-end reasoning as scheduling.

    Approach
    1. lo = max(a.start, b.start), hi = min(a.end, b.end); if lo <= hi, record [lo, hi] (a single point counts).
    2. Advance the pointer whose interval has the smaller end. On a tie, either one may move; the other is advanced on the next step.

    TimeO(m + n)SpaceO(1) auxiliary (output excluded)

    Pitfall. Advancing by the earlier start is wrong: a long interval in one list can intersect several intervals in the other. Either list may be empty; the loop condition handles that.

    Part II · Pattern 15

    Heap / Priority Queue: Top-K and Streaming

    A heap answers one question cheaply and repeatedly: "what is the current extreme?" Use it when the set changes between questions. If the set never changes, sorting or selection is usually simpler.

    15.1Pattern identity

    Primary purpose
    Maintain the minimum or maximum of a dynamic multiset with O(log n) insert and extract and O(1) peek. Bound the heap at size k to select top-k in O(n log k).
    Typical input
    A stream or array where the answer depends only on extremes: k largest, k closest, k most frequent, the next event to process, or a running median.
    Interview applications
    Kth largest, top-k frequent, k closest points, merge k sorted lists, task scheduler, meeting rooms, median of a stream, sliding-window median, Dijkstra.
    Key insight
    To keep the k largest elements, use a min-heap of size k: its root is the weakest member of the current top-k, which is exactly the element to evict when something better arrives.

    Key insight. The heap type is the opposite of the goal for bounded top-k. The root must be the element you are ready to throw away. For k largest that is the smallest element kept, so use a min-heap.

    15.2Recognition signals

    SignalStructural reason
    "k-th largest/smallest", "top k", "k closest"Only the boundary of the top-k set matters; a size-k heap tracks that boundary in O(log k) per element.
    Data arrives online ("stream", add/find API)A full sort per query is impossible; the heap is maintained incrementally.
    Repeatedly take the best, modify it, and put it backSimulation with a changing extreme (stones, tasks, events) needs log-time re-insertion.
    Median or percentile of a dynamic setSplit the set at the median: max-heap for the lower half, min-heap for the upper half.
    k ≪ n, or memory bounded by kO(n log k) time and O(k) space beat sorting's O(n log n) and O(n).

    Ask yourself. "Does each step only need the current minimum or maximum of a changing set?" If yes, use a heap. If you need the nearest larger element by position, use a monotonic stack. If you need arbitrary deletions or order statistics, use a TreeMap or a balanced BST.

    When it is inappropriate.

    • Static data, one query: quickselect gives expected O(n). Sorting is fine when n log n fits and you want simplicity.
    • Arbitrary removal (sliding-window maximum): PriorityQueue.remove(Object) is O(k). Use a monotonic deque, lazy deletion, or a TreeMap.
    • Values in a small range (frequencies ≤ n): bucket sort gives O(n).
    Confused withHow to tell them apart
    SortingSort when everything is known up front and you need a full order. Use a heap when elements arrive over time or only k matter.
    Monotonic stack/dequeA deque keeps candidates in position order with amortised O(1) per element. A heap orders by value only.
    TreeMap / ordered multisetSupports removal of any key and floor/ceiling queries in O(log n). Heavier, but needed for sliding-window medians with removals.

    15.3Concepts and invariants

    Heap invariant. Every parent compares ≤ its children under the comparator, so the root is the extreme. Java's PriorityQueue is a binary min-heap by natural order. Pass a comparator for anything else.

    OperationPriorityQueue costNote
    offer / pollO(log n)Sift up / sift down
    peek, sizeO(1)
    remove(Object), containsO(n)Linear scan; avoid in hot loops
    Build from a collectionO(n)new PriorityQueue<>(collection) heapifies bottom-up
    Iteration orderNot sortedOnly the root is guaranteed; poll repeatedly for sorted output

    Bounded top-k invariant. After processing a prefix, the size-k min-heap holds the k largest elements of that prefix. A new element x enters only if x > heap.peek(), and then evicts the root. Cost: O(n log k) time, O(k) space.

    Two-heaps median invariant.

    lo = max-heap (smaller half), hi = min-heap (larger half) (1) every x in lo ≤ every y in hi ⇔ lo.peek() ≤ hi.peek() (2) |lo| = |hi| or |lo| = |hi| + 1 median = lo.peek() if sizes differ = (lo.peek() + hi.peek()) / 2.0 otherwise

    Insert into lo, move lo's maximum to hi (restores (1)), and if hi becomes larger move its minimum back (restores (2)). Each add is three heap operations, O(log n).

    Comparator correctness: never subtract

    (a, b) -> a - b is wrong whenever a − b can overflow. For a = Integer.MAX_VALUE and b = −1 the difference wraps to a negative number and the heap silently orders them backwards. Use Integer.compare(a, b), Comparator.comparingInt(...), or Collections.reverseOrder(). A comparator must also be consistent: ties should return 0, and for deterministic output add a tie-breaker (for example, by value when frequencies are equal).

    Duplicates. Heaps are multisets: equal values coexist and are popped in an unspecified order among themselves. Count-based problems (top-k frequent) should push one entry per distinct key, not per occurrence.

    15.4Reusable Java templates

    Template A — bounded top-k (k largest by a key). Reusable: the size-k min-heap and eviction rule. Problem-specific: the key and the comparator.

    Template B — two heaps for a running median.

    15.5Complexity and pitfalls

    TimeO(log n) per offer/poll; O(n log k) for bounded top-k; O(n) to heapify a collection.
    Auxiliary spaceO(k) for bounded heaps; O(n) for the full heap or the two median heaps.
    Off-by-one"k-th largest" with a size-k min-heap is peek(), not the k-th poll. Check whether k is 1-based.
    Wrong invariantMax-heap for k largest (keeps n elements and loses the O(k) bound); forgetting to rebalance median heaps.
    OverflowSubtraction comparators; summing two ints for a median.
    Breaks naive codeTies in frequency, duplicates, k = n, negative values, an empty heap on peek() (returns null and then NPE on unboxing).
    Interview follow-upsQuickselect for expected O(n); bucket sort for frequencies; remove arbitrary elements (lazy deletion with a "to delete" map); medians where 99% of values lie in [0, 100] (counting array plus overflow heaps).

    15.6Pattern mastery checklist

    Essential takeaways

    • k largest → min-heap of size k; k smallest → max-heap of size k.
    • Two heaps split a set at a rank, with sizes balanced within one.
    • Never write subtraction comparators; tie-break when output order matters.
    • PriorityQueue removal of an arbitrary element is O(n). Plan for lazy deletion if you need it.
    • For a single static query, compare against quickselect and bucket sort before reaching for a heap.

    Recognition rule. Repeatedly need the extreme of a changing set → heap. Need only the top k → bound the heap at k with the opposite order.

    In-interview checklist

    • Min-heap or max-heap, and why?
    • Is the heap bounded? What is evicted?
    • Comparator overflow-safe and consistent on ties?
    • What do I push: values, indices, or (key, value) pairs?
    • Would quickselect or bucket sort be asymptotically better here?

    Key distinction. Heap = extreme by value in O(log n). Monotonic stack = nearest qualifying element by position in amortised O(1).

    Bit Manipulation

    Treat an integer as 32 independent boolean lanes. Problems become easy when the condition decomposes per bit, or when an algebraic identity such as x ⊕ x = 0 cancels everything you do not care about.

    16.1Pattern identity

    Primary purpose
    Achieve O(1) extra space or O(log V) time by working on the binary representation: cancellation (XOR), per-bit counting, masks as sets, and isolating or clearing specific bits.
    Typical input
    Arrays where elements appear a fixed number of times except a few; integer ranges; subsets of a small universe (n ≤ 20) encoded as masks; power-of-two and parity questions.
    Interview applications
    Single Number I/II/III, missing number, counting bits, power of two, reverse bits, subset enumeration, bitmask DP, Gray code, bitwise AND/OR of ranges, maximum XOR pair (with a trie).
    Key insight
    XOR is addition modulo 2 in every bit lane at once, so paired values cancel. When pairs become triples, you need a counter modulo 3 per lane, which is still a constant number of ints.

    Key insight. Ask what happens in a single bit position. If the answer's bit i depends only on the inputs' bit i (counts, parity, common prefix), solve the one-bit problem and apply it to all 32 lanes.

    16.2Recognition signals

    SignalStructural reason
    "Every element appears twice/three times except…" with O(1) extra spaceMultiplicities reduce modulo 2 or 3 in each bit lane; a hash map would be O(n) space.
    AND/OR/XOR over a numeric rangeThe result is decided bit by bit; AND of a range keeps only the common binary prefix.
    n ≤ 20 and "all subsets" or "visited set" stateA mask is a compact set: 220 ≈ 106 states fit in an array.
    Power of two, lowest set bit, parityTwo's-complement identities (x & (x−1), x & −x) answer these in O(1).

    Ask yourself. "Is there an operation under which the unwanted elements cancel, or a per-bit statistic that reveals the answer?"

    When it is inappropriate.

    • Multiplicities are arbitrary (find any duplicate, most frequent element): parity says nothing. Use hashing, sorting, or Floyd's cycle trick (LeetCode 287).
    • Readability over micro-optimisation: replacing % 2 with & 1 earns nothing in an interview unless the problem is about bits.
    • Values exceed 64 bits or are floating point: use BitSet or other techniques.
    Confused withHow to tell them apart
    Hash map countingSame answer with O(n) space. Bit tricks win only when the multiplicity structure is fixed and known.
    Math (sum formulas)Missing number via the sum n(n+1)/2 can overflow; XOR of 0..n cannot.
    Trie on bitsMaximum XOR pair needs a greedy walk over a binary trie (Pattern 19), not a single XOR fold.

    16.3Concepts and invariants

    IdentityMeaning / use
    x ^ x = 0, x ^ 0 = x, XOR is associative and commutativeThe order of folding does not matter; pairs cancel.
    x & (x − 1)Clears the lowest set bit. Used in Kernighan popcount (loop runs once per set bit) and the power-of-two test x > 0 && (x & (x−1)) == 0.
    x & −xIsolates the lowest set bit, since −x = ~x + 1. Drives Fenwick trees (Pattern 20) and Single Number III.
    (x >> i) & 1, x | (1 << i), x & ~(1 << i), x ^ (1 << i)Get, set, clear and toggle bit i.
    for (s = m; s > 0; s = (s − 1) & m)Enumerates all non-empty submasks of m in decreasing order. Over all m this totals O(3n).

    Java's fixed-width integers. int is 32-bit two's complement, long is 64-bit; there are no unsigned types.

    • >> is an arithmetic shift (copies the sign bit): −8 >> 1 == −4. >>> is a logical shift (fills with 0): −8 >>> 1 == 2147483644. A loop while (x != 0) x >>= 1 never terminates for negative x; use >>>.
    • Shift distances are taken modulo the width: 1 << 32 == 1 for an int, and 1 << 31 == Integer.MIN_VALUE. Use 1L << i for 64-bit masks.
    • Integer.MIN_VALUE is its own negation: −MIN_VALUE == MIN_VALUE. Therefore MIN_VALUE & −MIN_VALUE == MIN_VALUE, which is still the correct lowest set bit (bit 31).
    • Built-ins: Integer.bitCount, Integer.numberOfTrailingZeros, Integer.highestOneBit, Integer.lowestOneBit, Integer.toBinaryString (shows negatives as 32 bits).
    Per-bit counting modulo k: the general Single Number method

    If every value appears exactly k times except one value that appears once, then for each bit i the number of inputs with bit i set is k·c + bi, where bi is the unique value's bit. So bi = counti mod k. Setting bit 31 rebuilds negative numbers correctly, because two's complement is just the bit pattern. This costs O(32·n) time and O(1) space and works for any k. The constant-time state machine for k = 3 (LeetCode 137) is this counter compressed into two ints.

    Template B — per-bit counting modulo k. Problem-specific: k, and whether a different multiplicity (other than 1) must be extracted.

    16.5Complexity and pitfalls

    TimeO(n) for XOR folds; O(32·n) = O(n) for per-bit counting; O(log V) for range/prefix problems; O(2n) for mask enumeration.
    Auxiliary spaceO(1) for the folds and counters; O(2n) for mask DP tables.
    Off-by-oneBit positions run 0..31; 1 << 31 is negative; looping bit <= 32 wraps to bit 0.
    Wrong invariantUsing >> on negatives in a "while non-zero" loop; testing (x & mask) == 1 instead of != 0.
    OverflowMasks wider than 31 bits need long and 1L << i. Math.abs(Integer.MIN_VALUE) is still negative.
    Precedence== binds tighter than &, ^, |. x & 1 == 0 does not compile in Java (int & boolean). Always parenthesise.
    Interview follow-upsGeneralise to "appears k times"; find two missing numbers; maximum XOR of two numbers (bit trie); count bits for 0..n in O(n) via bits[i] = bits[i >> 1] + (i & 1).

    16.6Pattern mastery checklist

    Essential takeaways

    • XOR cancels pairs; per-bit counts modulo k handle k-fold repetition.
    • x & (x−1) clears the lowest set bit; x & −x isolates it.
    • Use >>> when walking the bits of possibly negative values.
    • Range AND = common binary prefix; anything below the first differing bit becomes 0.
    • Parenthesise every bitwise expression inside a comparison.

    Recognition rule. Fixed multiplicities + O(1) space → XOR or per-bit counting. Range bitwise op → think about the common prefix.

    In-interview checklist

    • Does the condition decompose per bit?
    • Which identity cancels the noise (XOR, AND with x−1, lowbit)?
    • Signed shifts, bit 31, and Integer.MIN_VALUE handled?
    • Is int wide enough, or do I need long masks?
    • Would a hash map be clearer, and is O(1) space actually required?

    Key distinction. Bit tricks rely on exact, known multiplicities. Hash counting handles arbitrary multiplicities at O(n) space.

    Single Number

    Easy

    Task. Every element appears twice except one. Find it in O(n) time and O(1) extra space.

    Key insight

    XOR of all elements: each pair contributes x ^ x = 0, and order does not matter, so only the single value survives.

    Why the pattern applies

    Approach
    1. Fold XOR over the array.

    TimeO(n)SpaceO(1)

    Pitfall. Negative values need no special handling; XOR works on the raw bit patterns. A sum-based trick (2·sum(set) − sum) uses O(n) space and can overflow.

    LC 137

    Single Number II

    Medium

    Task. Every element appears three times except one, which appears once. Find it in linear time and constant space.

    Key insight

    In each bit lane, the count of ones is 3c + b, where b is the answer's bit. Keep a counter modulo 3 per lane. Two ints ones and twos store the counter's two bits for all 32 lanes simultaneously.

    Why the pattern applies

    The condition decomposes per bit with a fixed multiplicity. Template B solves it in O(32n). The state machine below does the same in O(n) with a few operations per element.

    Approach
    per-lane state (twos, ones): 00 → 01 → 10 → 00 on each incoming 1-bit ones = (ones ^ x) & ~twos toggle into 'one' unless already at 'two' twos = (twos ^ x) & ~ones toggle into 'two' unless we just moved to 'one' after all input: lanes holding count ≡ 1 (mod 3) are exactly the set bits of 'ones'

    TimeO(n)SpaceO(1)

    Pitfall. The update order matters: twos must use the new ones. If you cannot derive the state machine under pressure, Template B (count each of the 32 bits modulo 3) is equally linear, easier to defend, and handles negatives because bit 31 is rebuilt directly.

    LC 260

    Single Number III

    Medium

    Task. Exactly two elements appear once and all others appear twice. Return the two singles, in any order, in O(n) time and O(1) space.

    Key insight

    The XOR of everything is a ^ b ≠ 0. Any set bit of it, for example the lowest via d & −d, is a position where a and b differ. Splitting the array by that bit puts a and b in different groups, while each duplicate pair stays together. Each group is then a Single Number I.

    Why the pattern applies

    XOR cancellation plus lowest-set-bit isolation turns one problem with two unknowns into two problems with one unknown each.

    Approach
    1. d = XOR of all; mask = d & −d.
    2. XOR separately the elements with (v & mask) != 0 and those without.

    TimeO(n)SpaceO(1)

    Pitfall. In languages with overflow traps, −diff for diff = INT_MIN is undefined. In Java it wraps to itself and the mask is still the correct bit 31. Test (v & mask) != 0, not == 1: the mask is usually not bit 0.

    LC 201

    Bitwise AND of Numbers Range

    Medium

    Task. Given 0 ≤ left ≤ right ≤ 231 − 1, return the AND of every integer in [left, right].

    Key insight

    The result is the common binary prefix of left and right followed by zeros. Below the highest bit where they differ, the range contains a number ending in 0111… followed by one ending in 1000…, so every lower bit is 0 somewhere in the range.

    Why the pattern applies

    AND decomposes per bit: bit i survives only if it is 1 for every number in the range. Consecutive integers sweep through all patterns below the first differing bit, so only the shared prefix survives.

    Approach
    1. Shift both right until equal, counting the shifts.
    2. Shift the common prefix back left.

    TimeO(log right) ≤ 31 iterationsSpaceO(1)

    Pitfall. Looping from left to right and ANDing is O(range) and times out for ranges of 231. An equivalent loop is while (right > left) right &= right − 1;, which clears right's low bits one at a time until it falls to or below left.

    Part II · Pattern 17

    Union-Find / Disjoint Set Union

    A forest of parent pointers that answers "are these two in the same group?" and "merge these groups" in near-constant amortised time. It is the tool for connectivity that grows over time and never shrinks.

    17.1Pattern identity

    Primary purpose
    Maintain a partition of elements under union(a, b) and find(a) in O(α(n)) amortised time per operation.
    Typical input
    A list of edges or equivalence relations ("a is connected to b", "a == b", "these two accounts share an email"), processed in any order, often with queries interleaved.
    Interview applications
    Number of components, cycle detection in undirected graphs, redundant connection, accounts merge, Kruskal's MST, equations satisfiability, islands with incremental land (305), grid percolation.
    Key insight
    Each group is identified by a single representative (its root). Two elements are connected exactly when their roots are equal. Path compression and union by size keep the trees almost flat.

    Key insight. DSU does not store how elements are connected, only whether they are. If you need paths, distances or edge directions, traverse the graph instead. If you only need connectivity under insertions, DSU is the simplest correct tool.

    17.2Recognition signals

    SignalStructural reason
    Edges or equivalences arrive one by one with connectivity queries in betweenOnline incremental connectivity: re-running BFS per query would cost O(V+E) each.
    "Which edge creates a cycle?" in an undirected graphAn edge (u, v) closes a cycle iff u and v already share a root before the union.
    Grouping by a shared attribute (email, value, row/column)Transitive equivalence: union every item with the first item that has the same attribute.
    Count groups or componentsStart with n components and decrement on each successful union.
    Kruskal MST, processing edges in sorted orderAccept an edge iff it joins two different components.

    Ask yourself. "Do I only ever merge groups and ask whether two items share a group?" If yes, use DSU. If groups must split, or the question involves paths or directions, use something else.

    When it is inappropriate.

    • Deletions or splits: DSU cannot undo a union efficiently. Offline tricks exist (process deletions in reverse as insertions; rollback DSU without path compression), but standard DSU cannot split a component.
    • Directed reachability: union is symmetric, so it loses edge direction. Use DFS/BFS, topological sort, or strongly connected components.
    • Shortest paths or actual paths: DSU keeps no path information.
    Confused withHow to tell them apart
    DFS/BFS componentsThe same O(V+E) for a static graph given up front. DFS is natural when you also need component contents or paths; DSU wins for online edges and for edges given as an unordered list.
    Topological sort / directed cycleDSU detects only undirected cycles. A directed cycle needs colouring or Kahn's algorithm.
    Hash-map groupingA map groups by one exact key. DSU merges transitively across different keys (a~b via email 1, b~c via email 2).

    17.3Concepts and invariants

    Representation. parent[x] is x's parent and roots satisfy parent[r] == r. Invariant: following parents from any element reaches its component's unique root.

    Two heuristics, used together.

    • Union by size (or rank): attach the smaller tree under the larger root. A node's depth increases only when its tree at least doubles in size, so depth ≤ log2 n even without compression.
    • Path compression: during find, point visited nodes (all of them, or every other one with path halving) closer to the root, flattening future queries.
    With both heuristics: m operations on n elements cost O(m · α(n)) (Tarjan) α = inverse Ackermann; α(n) ≤ 4 for any n that fits in memory → "effectively constant" Union by size alone: O(log n) per find. Compression alone: O(log n) amortised.

    Cycle detection. Process undirected edges in order. If find(u) == find(v) before the union, a u–v path already exists, so adding (u, v) closes a cycle. This is also Kruskal's rejection rule.

    Component counting. components = n − (number of successful unions), because each successful union merges exactly two components.

    Recursive vs iterative find

    Recursive full compression (parent[x] = find(parent[x])) is concise, but on a long chain built without union by size the first call recurses to depth n and can overflow the stack. With union by size the depth is at most log n, so recursion is safe. Iterative path halving (parent[x] = parent[parent[x]] inside the loop) has the same amortised bound and no recursion at all, which is why the template uses it.

    17.4Reusable Java templates

    Template A — array DSU over 0..n−1. Reusable as is. Problem-specific: what counts as an edge, and what you do when union returns false.

    Template B — DSU over arbitrary keys. For strings or sparse integers (emails, coordinates), map keys to ids lazily.

    Note: parent.get(x) != x compares an Integer with an int, which unboxes, so the comparison is numeric and correct. Comparing two Integer objects with != would compare references and break above 127.

    17.5Complexity and pitfalls

    TimeO(α(n)) amortised per operation with both heuristics; O(n + m α(n)) total. Building from E edges: O(V + E α(V)).
    Auxiliary spaceO(n) for parent and size.
    Off-by-one1-indexed vertices (684 uses 1..n): allocate n + 1 or subtract 1 consistently.
    Wrong invariantparent[a] = b instead of parent[find(a)] = find(b), which links non-roots and corrupts components. Comparing parent[a] == parent[b] instead of roots.
    BoxingInteger reference comparison in map/list-based DSUs (see note above).
    Breaks naive codeSelf-loops (u == v: union returns false, which is correctly a cycle), duplicate edges, isolated vertices (count them as components), and deep recursion without union by size.
    Interview follow-upsWeighted DSU (ratios, LeetCode 399); DSU with rollback; offline deletions in reverse; component sizes; why DSU cannot detect directed cycles.

    17.6Pattern mastery checklist

    Essential takeaways

    • Always link roots: parent[find(a)] = find(b).
    • Union by size + path compression → effectively O(1) amortised.
    • union returning false is your cycle detector and Kruskal filter.
    • Components = n − successful unions.
    • No splits, no directions, no paths: those need other tools.

    Recognition rule. Undirected relations merging over time + "same group?" or "how many groups?" → DSU.

    In-interview checklist

    • What are the elements, and how do I map them to 0..n−1?
    • What triggers a union? What does a failed union mean here?
    • 0- or 1-indexed?
    • Are isolated elements counted?
    • Does the problem ever need a split or edge direction? (If so, not DSU.)

    Key distinction. DSU answers connectivity online under insertions. DFS/BFS answers richer questions (paths, order, distances) on a static graph.

    LC 684

    Redundant Connection

    Medium

    Task. A tree on n nodes (labelled 1..n) had one extra edge added. Return an edge whose removal leaves a tree; if several qualify, return the one that occurs last in the input.

    Key insight

    Scan edges in order. The first edge whose endpoints are already connected closes the (unique) cycle. Every other cycle edge appears earlier, so this edge is the last cycle edge in the input, which is exactly the required answer.

    Why the pattern applies

    This is undirected cycle detection on edge insertion: union returns false exactly at the redundant edge.

    Approach
    1. DSU over 1..n (allocate n + 1).
    2. For each edge, if union fails, return it.

    TimeO(n·α(n))SpaceO(n)

    Pitfall. Why is the first failing edge the last cycle edge in input order? Before it, the edges seen form a forest, so no cycle edge has failed. It is the first moment the cycle is complete, so all other cycle edges came earlier. The directed variant (685) is different: DSU alone is not enough, because nodes with two parents need separate handling.

    Medium

    Task. Given an n × n symmetric adjacency matrix isConnected, count the connected components.

    Key insight

    Start with n components and decrement on each successful union over the upper triangle of the matrix.

    Why the pattern applies

    This is undirected component counting, DSU's "components = n − successful unions" invariant. The same problem appears with BFS in Chapter 3 and recursive DFS in Chapter 9. All three are O(n²) because the input matrix itself has n² cells.

    Approach
    1. For each pair i < j with isConnected[i][j] == 1, union them.
    2. Return the remaining component count.

    TimeO(n²·α(n))SpaceO(n)

    Pitfall. Counting distinct values of parent[i] at the end is wrong without a final find on each element, because non-roots may point to stale intermediate parents. Maintaining the counter during unions avoids this.

    Part II · Pattern 18

    Shortest Path: Dijkstra's Algorithm

    A priority queue settles vertices in non-decreasing order of distance. With non-negative weights, the first time a vertex leaves the queue its distance is final.

    18.1Pattern identity

    Primary purpose
    Single-source shortest paths when edges have different non-negative costs, or more generally when path cost never decreases as a path is extended.
    Typical input
    An edge list [u, v, w] (directed or undirected), a weighted grid where moving between cells has a cost, or an implicit state graph (node + extra resource).
    Interview applications
    Network delay, cheapest route, minimum-effort grid path, maximum-probability path, counting shortest paths, shortest path with a resource limit (expanded state).
    Key insight
    Among the unsettled vertices, the one with the smallest tentative distance cannot be improved later. Every other route to it passes through an unsettled vertex whose distance is already at least as large, and non-negative edges can only add.

    Key insight. Dijkstra is BFS with a priority queue instead of a FIFO queue. It needs exactly one property: extending a path never makes it cheaper. Sums of non-negative weights have it; so do the maximum edge on a path and the product of probabilities ≤ 1. Negative edges do not.

    18.2Recognition signals

    SignalStructural reason
    "Minimum cost / time / effort to reach…" with edge-specific costsEdge weights differ, so the FIFO order of BFS no longer matches distance order.
    All weights ≥ 0 (check the constraints line explicitly)Required for the settle-once invariant.
    One source (or a virtual super-source), many targetsDijkstra computes the full shortest-path tree from one source in a single run.
    Path cost is a max, min or product rather than a sumStill works if the cost is monotone along the path (bottleneck, probability). Check this, do not assume it.
    An extra limit (≤ K edges, fuel, stops)Distance alone is no longer a sufficient state. Expand the state to (vertex, resource) or switch to bounded Bellman–Ford.
    V up to ~105, E up to ~2·105The O((V+E) log V) budget fits; Bellman–Ford's O(VE) does not.

    Ask yourself. "If I extend a path by one edge, can its cost decrease, and does the cheapest path to a vertex remain the best prefix for every continuation?" Two yeses (no decrease, cheapest prefix still best) mean Dijkstra on the plain vertex graph. If the cheapest prefix might be the wrong one because of a constraint, the state is too small.

    When it is inappropriate.

    • Unweighted or unit-weight graphs: BFS gives the same answer in O(V+E) without the log factor (Pattern 10).
    • 0/1 weights: 0-1 BFS with a deque is O(V+E).
    • Negative edge weights: the settled-is-final invariant fails. Use Bellman–Ford (A7), or SPFA with care. Negative cycles make shortest paths undefined.
    • Only reachability is asked: BFS, DFS or DSU (see 1971).
    • All-pairs on small graphs (V ≤ ~400): Floyd–Warshall's O(V³) is simpler.
    • DAGs: relaxing in topological order is O(V+E) and allows negative weights.
    Confused withHow to tell them apart
    BFSBFS is Dijkstra in the special case where all weights are equal. If weights differ, BFS's first visit is not the shortest.
    Bellman–FordHandles negative weights and edge-count limits through repeated rounds of relaxing every edge. It is slower: O(VE).
    Prim's MSTSame code shape, but Prim keys a vertex by one edge weight, while Dijkstra keys by the whole path cost. They produce different trees.
    A*Dijkstra plus an admissible heuristic. Rare in interviews; Dijkstra is A* with h = 0.

    18.3Concepts and invariants

    Relaxation. For edge (u, v, w): if dist[u] + w < dist[v], set dist[v] = dist[u] + w and push (dist[v], v). Every algorithm in this family is a schedule of relaxations. Dijkstra's schedule relaxes the outgoing edges of each vertex exactly once, in order of final distance.

    Invariant: when u is popped with d == dist[u], dist[u] = δ(s, u) (true shortest distance) Proof sketch: let P be a shortest s→u path, and let (x, y) be its first edge with x settled, y not. dist[y] ≤ δ(s, x) + w(x, y) = δ(s, y) ≤ δ(s, u) (prefix of a shortest path; w ≥ 0) u was chosen as the minimum ⇒ dist[u] ≤ dist[y] ≤ δ(s, u) ≤ dist[u] ⇒ equality. The step δ(s, y) ≤ δ(s, u) is exactly where non-negative weights are used.

    Stale entries (lazy deletion). java.util.PriorityQueue has no efficient decrease-key, so push a new entry on every improvement. Old entries stay in the heap. When popped, an entry whose d > dist[u] is stale and is skipped. The heap holds at most O(E) entries, so each operation costs O(log E) = O(log V), because E ≤ V².

    Total: O((V + E) log V) time, O(V + E) space (adjacency list + up to E heap entries) Dense graphs (E ≈ V²): the array version (scan for the minimum) is O(V²) and beats the heap.

    Why negative weights break it. Take the edges s→a (2), s→b (5) and b→a (−4). Dijkstra settles a at distance 2, but the true distance is 1 via b. Once a is settled, its outgoing edges were relaxed with the wrong value, so the error propagates. Adding a constant to every edge does not fix it, because paths with more edges are penalised more.

    Generalised path costs. Dijkstra works for any cost that satisfies (1) monotonicity: cost(P + e) ≥ cost(P), and (2) isotonicity: if cost(P) ≤ cost(Q) for two paths to the same vertex, then cost(P + e) ≤ cost(Q + e). Bottleneck max(cost, w) (LC 1631) and the probability product with factors in [0, 1] under a max-heap (A2) both qualify.

    State expansion. When a constraint makes "cheapest so far" insufficient (for example, a cheap path that has used too many edges), encode the constraint in the state: vertex v becomes (v, edgesUsed). The expanded graph has V·(K+2) states, and Dijkstra applies unchanged. The first time the target appears at the top of the heap, in any layer, its cost is optimal.

    Grid graphs and representation choices
    • Grid: vertex = cell (r, c), encoded as r * cols + c. There are 4 implicit neighbours and the weight is computed on the fly (for example |ha − hb|), so no adjacency list is needed. V = R·C and E ≈ 4V.
    • Adjacency list: List<int[]>[] with {to, w}. For undirected edges add both directions. Always check whether the problem is 0- or 1-indexed.
    • Distance type: use long when V·maxW can exceed 231−1. When the sum is used as a comparator key, compare with Long.compare, never by subtraction.
    • Early exit: for a single target, return when the target is popped (not when it is first pushed).

    18.4Reusable Java templates

    Template A — adjacency-list Dijkstra with lazy deletion. Reusable: everything. Problem-specific: graph construction (directed or undirected, index base) and what you read from dist.

    Template B — grid Dijkstra with a pluggable path-cost rule. The combine line is the only problem-specific part: d + w for sums, Math.max(d, w) for bottleneck costs.

    Template C — Dijkstra on an expanded state (vertex, resource used). Use it when a limit such as "at most K edges" makes the cheapest prefix insufficient.

    18.5Complexity and pitfalls

    TimeO((V + E) log V) with a binary heap and lazy deletion; O(V²) with the array version on dense graphs; expanded state: O(K·E·log(K·E)).
    Auxiliary spaceO(V + E): adjacency list, dist, and up to O(E) heap entries.
    Off-by-one1-indexed vertices (LC 743) sized as n instead of n + 1; "K stops" means K + 1 edges.
    Wrong invariantMarking a vertex visited when it is pushed (that is the BFS habit). In Dijkstra a vertex is final only when popped with d == dist[u].
    OverflowInteger.MAX_VALUE + w wraps negative and wins every comparison. Use long with INF = Long.MAX_VALUE / 4, or check for INF before adding. Never write the comparator as a[0] - b[0] on large values.
    Breaks naive codeNegative weights; zero-weight cycles (fine for Dijkstra, but they defeat naive "visit count" hacks); multiple edges between the same pair (keep all of them, since relaxation handles it); disconnected targets (return −1 / INF).
    Interview follow-upsReconstruct the path (store parent[v] on relaxation); count shortest paths (A2 · 1976); multi-source (push every source at distance 0); a K-edges limit (state expansion or Bellman–Ford); negative weights (Bellman–Ford, A7).

    18.6Pattern mastery checklist

    Essential takeaways

    • Correctness rests on one property: extending a path never lowers its cost.
    • Lazy deletion with the d > dist[u] check is the standard Java implementation; never skip that check.
    • A vertex is final when popped, not when pushed.
    • If a constraint makes "cheapest so far" insufficient, expand the state.
    • Use BFS for unit weights, Bellman–Ford for negative weights, and the plain array version for dense graphs.

    Recognition rule. Weighted edges + non-negative costs + "minimum total" from a source → Dijkstra. Before coding, ask whether the vertex alone is a sufficient state.

    In-interview checklist

    • Directed or undirected? 0- or 1-indexed?
    • Are all weights ≥ 0? Is the cost a sum, a max or a product?
    • Does the vertex alone determine the future, or do I need (vertex, resource)?
    • Distance type: does V·maxW fit in an int?
    • What is returned for unreachable targets?

    Key distinction. BFS settles by number of edges and Dijkstra by total weight. If all weights are equal, use BFS; if any weight is negative, use neither.

    LC 1971

    Find if Path Exists in Graph

    Easy

    Task. Given an undirected graph on n vertices (0-indexed edge list), decide whether source can reach destination.

    Classification note. This is not a Dijkstra problem. Edges carry no weights and only existence is asked, so any traversal answers it in O(V + E). Dijkstra would also be correct, since it degenerates to BFS, but it adds a log factor and signals that you have not looked at the structure. The DSU solution appears in Chapter 17.

    Key insight

    Reachability depends only on connectivity. The first time BFS reaches destination is enough; distances are irrelevant.

    Why the pattern applies

    It belongs here as a contrast case. Recognising that weights are absent is the shortest-path decision: no weights → BFS/DFS/DSU; weights ≥ 0 → Dijkstra.

    Approach
    1. Build an undirected adjacency list.
    2. BFS from source, marking vertices when they are enqueued; return true as soon as destination is reached.

    TimeO(V + E)SpaceO(V + E)

    Pitfall. With n up to 2·105, recursive DFS can overflow the Java stack on a path-shaped graph. BFS, iterative DFS or DSU avoid this. Handle source == destination (including graphs with no edges).

    LC 743

    Network Delay Time

    Medium

    Task. Directed edges times[i] = [u, v, w] on nodes 1..n. A signal starts at k. Return the time until all nodes have received it, or −1 if some node is unreachable.

    Key insight

    A node receives the signal at its shortest-path distance from k, and all nodes are done at the maximum of those distances.

    Why the pattern applies

    This is a classic single-source shortest path: directed graph, non-negative weights (0 ≤ w ≤ 100), and the full distance array is needed. Template A applies directly.

    Approach
    1. Adjacency list sized n + 1 (1-indexed).
    2. Run Dijkstra from k; answer = max over dist[1..n], or −1 if any is INF.

    TimeO((V + E) log V)SpaceO(V + E)

    Pitfall. The answer is the maximum distance, not the sum. Distances are at most (n−1)·100 here, so int is safe. Only finite d values reach the relaxation line, so d + w cannot overflow. With n ≤ 100, Bellman–Ford or Floyd–Warshall are also acceptable; say so.

    LC 1631

    Path With Minimum Effort

    Medium

    Task. In a height grid, a route's effort is the maximum absolute height difference between consecutive cells. Minimise the effort of a route from the top-left to the bottom-right cell (4-directional moves).

    Classification note. This is a bottleneck (minimax) shortest path, not a sum. Dijkstra remains correct because max(cost, w) ≥ cost (monotone) and max preserves order (isotone). Two equally valid alternatives: binary search on the answer (Pattern 6), where feasible(E) asks whether BFS can reach the target using only edges ≤ E, for O(RC log H); and DSU / Kruskal, which adds edges in increasing weight until the corners connect (Pattern 17, A4).

    Key insight

    Replace dist[v] = dist[u] + w with dist[v] = max(dist[u], w). The first time the target is popped, no other route can have a smaller bottleneck.

    Why the pattern applies

    It is an implicit grid graph with non-negative weights and a monotone path cost. Template B with bottleneck = true is exactly this problem.

    Approach
    1. The state is a cell id; edge weight is |h[a] − h[b]|.
    2. Pop the minimum effort; relax neighbours with max; return when the target is popped.

    TimeO(RC · log(RC))SpaceO(RC)

    Pitfall. A 1×1 grid has effort 0; the early return handles it because cell 0 is the target. Plain DFS with backtracking is exponential, and BFS with a visited set is wrong because the first visit is not the minimum-effort visit.

    LC 787

    Cheapest Flights Within K Stops

    Medium

    Task. Directed flights [from, to, price] (price ≥ 1). Return the cheapest price from src to dst using at most k stops (that is, at most k + 1 flights), or −1.

    Classification note. Plain vertex Dijkstra is incorrect here. It keeps only the cheapest way to reach each city, but a cheap route that has used too many flights can block a slightly more expensive route with stops to spare. Example: with k = 1, edges 0→1 (1), 1→2 (1), 2→3 (1), 0→2 (5), the best route is 0→2→3 = 6. Vertex Dijkstra settles city 2 at cost 2 via two flights, and from there it cannot take 2→3 within budget. The fix is to make the stop count part of the state. The bounded Bellman–Ford solution is in A7.

    Key insight

    Run Dijkstra on states (city, flightsUsed). In the expanded graph the cheapest prefix is once again sufficient, because two states with the same city and flight count have identical futures.

    Why the pattern applies

    Prices are positive, so the cost is monotone. The constraint is captured by enlarging the state space to n · (k + 2) states (Template C).

    Approach
    1. best[city][f] = cheapest cost reaching city with exactly f flights.
    2. Pop the cheapest state; if its city is dst, return its cost. This is optimal across all flight counts, because the heap is ordered by cost.
    3. Expand only if f < k + 1.

    TimeO(K·E · log(K·E))SpaceO(n·K + K·E) states and heap entries

    Pitfall. The usual mistakes are treating "stops" as edges (k stops = k + 1 edges) and keeping only dist[city]. A valid alternative prune keeps, per city, the fewest flights seen at any popped cost, and skips a state unless it improves on that. The 2D best table is easier to justify. Bellman–Ford with k + 1 rounds and a snapshot array (A7) is O(K·E) and is the most common interview answer.

    Part II · Pattern 19

    Trie / Prefix Tree

    A rooted tree whose edges are characters, so every node is a prefix. Words that share a prefix share the same path, which lets one traversal answer questions about many words at once.

    19.1Pattern identity

    Primary purpose
    Answer prefix questions (does any word start with p, which dictionary word is a prefix of s, which words match a partial pattern) in time proportional to the query length, independent of the dictionary size.
    Typical input
    A dictionary of strings over a small alphabet (usually lowercase letters), followed by many queries, or a search space (a grid or a sentence) that must be matched against all words at once.
    Interview applications
    Autocomplete, spell check, prefix counting, wildcard search, shortest-root replacement, multi-word grid search, maximum XOR (binary trie), streaming suffix matching.
    Key insight
    A hash set checks one whole word at a time. A trie checks a prefix and keeps going, so when a prefix is absent you stop immediately, and a single walk discovers every word on the path.

    Key insight. Use a trie when you need to ask "can this partial string still become a word?" while building the string one character at a time. That early "no" is what prunes backtracking in Word Search II.

    19.2Recognition signals

    SignalStructural reason
    "starts with", "prefix", "autocomplete", "shortest root"Prefix relationships are paths from the root; the answer is found by walking down.
    Many words searched in one structure (a grid, a text)Separate searches repeat shared prefixes. One trie walk serves all words with that prefix.
    Wildcards that match a single characterA wildcard at depth d branches over the children of the current node only. Without a trie you would scan every word.
    Design problem with insert and search / startsWithThe operation set itself describes a trie.
    Maximise XOR of pairs (numbers as bit strings)A binary trie greedily chooses the opposite bit from the most significant bit down.

    Ask yourself. "Do I need to stop early on a dead prefix, or ask a question about every word sharing a prefix?" If you only ever test complete words, a HashSet is simpler and usually faster.

    When it is inappropriate.

    • Exact membership only: a HashSet<String> is O(L) per lookup with less memory and code.
    • Substring (not prefix) queries over one long text: KMP (A6), Z-function, rolling hashes or suffix structures fit better. A trie of all suffixes is O(n²) memory.
    • Huge alphabets with sparse use: 26-slot arrays waste memory; use a HashMap for children, or reconsider the approach.
    • Lexicographic ordering of a static list: sorting is enough.
    Confused withHow to tell them apart
    Hash set of wordsWhole-word lookups only. A set of all prefixes works for prefix tests but costs O(ΣL²) to build, and it cannot report which word ends where.
    Sorting + binary searchPrefix existence can be found by binary-searching the insertion point in a sorted list. That works for static dictionaries, but not for incremental character-by-character walks or wildcards.
    Backtracking aloneWord Search I (one word) needs no trie. With many words, the trie turns per-word searches into one shared, pruned search.

    19.3Concepts and invariants

    Structural invariant. The path from the root to node x spells a unique string prefix(x). Node x exists if and only if some inserted word has prefix(x) as a prefix. x.end (or a stored word) is true if and only if prefix(x) itself was inserted.

    insert(w), search(w), startsWith(p): O(L) time, L = query length Total nodes ≤ 1 + Σ |w_i| (one node per distinct prefix) Memory (array children): nodes · alphabet · reference size ≈ ΣL · 26 · 4–8 bytes

    End-of-word markers. Prefix and word are different questions. After inserting "apple", search("app") is false while startsWith("app") is true. Storing the full word at the terminal node (String word instead of boolean end) avoids rebuilding strings during DFS, which is standard in Word Search II.

    Node design choices.

    Children storeProsCons
    Node[26]O(1) child access, fastest, simplest26 references per node even when sparse
    HashMap<Character, Node>Any alphabet, proportional memoryHashing and boxing overhead; slower constants
    Flat arrays int[nodes][26]Cache-friendly, no object headersMust pre-size the node count (≤ ΣL + 1)

    Counters on nodes. A pass count (how many words go through a node) answers "how many words have prefix p" in O(|p|) and supports deletion. Decrement along the path, and a node with pass == 0 can be detached.

    Wildcard search cost. A '.' at depth d explores every existing child, so the worst case for a pattern of length L is O(26k · L) for k wildcards, bounded by the number of trie nodes at those depths. The trie does not make wildcards cheap; it confines branching to prefixes that actually exist.

    Trie-guided backtracking: pruning that makes Word Search II feasible

    Searching each of W words separately on an R×C board costs O(W · RC · 4·3L−1). With a trie, a single DFS from each cell advances one trie node per step, and three prunes stack:

    1. Dead prefix: if node.next[c] == null, stop. No word continues this path.
    2. Found-word removal: after reporting node.word, set it to null so it is not reported twice (no result set needed).
    3. Leaf pruning: after returning from a child that now has no children and no word, detach it. Later searches stop earlier, which matters on boards full of repeated letters.

    Mark the board in place (board[r][c] = '#') and restore on return. This is the choose → explore → undo loop from Pattern 8.

    19.4Reusable Java templates

    Template A — array-children trie with prefix counts. Reusable: the node layout and walk. Problem-specific: what is stored at nodes (end, word, counts).

    Template B — map-children trie for arbitrary alphabets, with shortest-prefix lookup.

    19.5Complexity and pitfalls

    TimeInsert / search / prefix: O(L). Build: O(ΣL). Wildcard search: up to O(nodes) in the worst case. Word Search II: O(RC · 4·3L−1) worst case, far less with pruning.
    Auxiliary spaceO(ΣL · σ) for array children (σ = alphabet size), O(ΣL) for map children; plus O(L) recursion depth for DFS operations.
    Off-by-oneReturning the prefix length vs the index; checking end before vs after stepping into the child (the root represents the empty string).
    Wrong invariantTreating "node exists" as "word exists": search must check the end marker.
    Overflow / memory3·104 words × length 10 × 26 references is about 7.8M slots, which is fine. Million-word dictionaries with array children can exhaust memory; use maps or flat arrays.
    Breaks naive codeDuplicate words (count them, or report a found word once); words that are prefixes of other words ("app" and "apple"); the empty string; uppercase or non-letter input that breaks c − 'a'.
    Interview follow-upsDelete a word; top-k autocomplete (store a small sorted list or a heap per node); streaming suffix queries (insert reversed words, LC 1032); maximum XOR pair (binary trie, LC 421).

    19.6Pattern mastery checklist

    Essential takeaways

    • A node is a prefix; an end marker makes it a word. Keep the two questions separate.
    • The trie's value is the early stop on a dead prefix, which multiplies inside backtracking.
    • Store the full word at terminal nodes when the search builds paths (grids, DFS).
    • Pick array children for small fixed alphabets and maps otherwise; state the memory trade-off.
    • For a single exact lookup, use a hash set.

    Recognition rule. Many words + prefix questions or character-by-character construction → trie. One word or only whole-word membership → hash set.

    In-interview checklist

    • What is the alphabet and its size? Array or map children?
    • What does each node need: an end flag, the stored word, a pass count?
    • Where does the walk stop early, and what is returned then?
    • How are duplicates and word-is-prefix-of-word cases handled?
    • What is the recursion depth (the word length) for DFS operations?

    Key distinction. A trie answers prefix questions across many words. KMP answers substring questions for one pattern in one text.

    LC 648

    Replace Words

    Medium

    Task. Replace each word of a sentence with the shortest dictionary root that is a prefix of it; leave words with no root unchanged.

    Key insight

    Walking a word down the trie meets candidate roots in increasing length, so the first end marker on the path is the shortest root. The walk stops at that marker or at a dead prefix.

    Why the pattern applies

    This is prefix-based replacement: each word is a query that asks which inserted word is its prefix. A hash set would test all L prefixes of each word, costing O(L²) per word because of substring creation. The trie costs O(L).

    LC 212

    Word Search II

    Hard

    Task. Return all words from a list that can be traced on an m×n letter board through 4-directionally adjacent cells, without reusing a cell within one word.

    Key insight

    Search the board once for all words together. The DFS carries a trie node, and a missing child ends the branch immediately. Removing words once found, and pruning emptied leaves, keeps later searches short.

    Why the pattern applies

    This is trie-guided backtracking. Backtracking explores the paths; the trie supplies the "can this path still become a word?" test and the multi-word sharing. Searching each word separately (up to 3·104 words) times out.

    Approach
    1. Build a trie and store each word at its terminal node.
    2. From every cell, run dfs(r, c, parent). Step into parent.next[ch]; if it is null, return. If node.word != null, record the word and clear it.
    3. Mark the cell '#', recurse into the 4 neighbours, then restore it. Detach the child if it is now empty (leaf pruning).

    TimeO(RC · 4 · 3L−1) worst case, L ≤ 10; build O(ΣL)SpaceO(ΣL · 26) trie + O(L) recursion

    Pitfall. Without clearing node.word, a word reachable along several paths is reported several times. Without leaf pruning, adversarial boards (all 'a', with words "aaaa…b") stay exponential. The '#' check must happen before indexing next['#' − 'a']; here it is done at the neighbour check.

    Part II · Pattern 20

    Segment Tree / Fenwick Tree (Binary Indexed Tree)

    These structures keep precomputed aggregates over O(n) intervals, so any range can be answered by combining O(log n) of them, and a point change touches only O(log n) of them.

    20.1Pattern identity

    Primary purpose
    Answer range-aggregate queries (sum, count, min, max, gcd and similar) interleaved with updates, each in O(log n). Prefix sums handle queries only; updates would cost O(n) each.
    Typical input
    An array plus a stream of operations ("update index i", "query [l, r]"), or an offline problem that sweeps an axis and asks "how many / what is the best among values seen so far in this value range?"
    Interview applications
    Mutable range sums, counting inversions or smaller-after-self, LIS variants with value windows, interval stacking (falling squares), calendar booking, k-th order statistics over counts.
    Key insight
    Any range [l, r] splits into O(log n) canonical blocks whose aggregates are stored. If the operation is associative, combining the blocks gives the answer. A segment tree stores the blocks explicitly as a tree. A Fenwick tree stores prefix blocks implicitly by low-bit arithmetic and needs an invertible operation to turn prefixes into ranges.

    Key insight. Two questions decide the structure. (1) Is the merge operation invertible (sum, xor, counts)? If yes and updates are point updates, a Fenwick tree is enough. (2) Do you need non-invertible aggregates (max, min) over arbitrary ranges, range assignments, or custom merges? Then use a segment tree, with lazy propagation if updates cover ranges.

    20.2Recognition signals

    SignalStructural reason
    Queries and updates interleave, with both up to 105 operationsStatic prefix sums cost O(n) per update. Recomputing per query costs O(n) per query. Both are O(n·q) ≈ 1010.
    "Count elements smaller/greater than x to the left/right"Sweep positions and keep a frequency array indexed by value. Each query is a prefix count, which suits a Fenwick tree over (compressed) values.
    DP of the form dp[i] = 1 + best over j with value in a windowIndex the structure by value and query the best dp in a value range: a range-max segment tree.
    Intervals painted, stacked or booked; values up to 108–109Range updates plus range queries over a huge axis: coordinate compression plus a lazy segment tree.
    The aggregate is associative but not invertible (max, min, gcd)Prefix differences are impossible, so a range query must be decomposed into tree nodes.

    Ask yourself. "What are my update type (point or range) and query type (point or range), and is the operation invertible?" The answer table in 20.3 then chooses the structure for you.

    When it is inappropriate.

    • No updates: prefix sums (Pattern 4) for sums; a sparse table for static range min/max in O(1).
    • Only global min/max with inserts and deletes: a heap or TreeMap is simpler.
    • A sliding-window maximum: a monotonic deque does it in O(n) total.
    • Few operations (n·q ≤ 107): brute force is acceptable and much less error-prone.
    • Operations that are not associative (median of a range, mode of a range): neither structure supports them without fundamentally different techniques (merge-sort trees, Mo's algorithm, persistent trees).
    Confused withHow to tell them apart
    Prefix sumPrefix sums are a Fenwick tree with no updates: O(1) query, O(n) update.
    TreeMap / ordered setHandles predecessor and successor queries and order statistics poorly (Java's TreeMap has no rank query). Use a Fenwick tree over compressed values for "how many ≤ x".
    Merge sort countingInversion-style counts (LC 315, 493) can be done offline by merge sort in O(n log n). A Fenwick tree is usually shorter and also works online.

    20.3Concepts and invariants

    Segment tree — array representation. Node 1 is the root and covers the whole input range [0, n−1]. Node x covering [l, r] has children 2x covering [l, mid] and 2x+1 covering [mid+1, r], with mid = (l + r) >>> 1.

    Invariant: tree[x] = merge(tree[2x], tree[2x+1]), leaves hold a[i] Height h = ⌈log₂ n⌉, so indices are < 2^(h+1) ≤ 4n ⇒ allocate 4n Query [ql, qr]: at most 2 nodes per level are partially covered ⇒ O(log n) nodes visited Point update: one root-to-leaf path, then recompute ancestors ⇒ O(log n) Build: each of the < 2n real nodes is computed once ⇒ O(n)

    The segment tree needs only an associative merge with an identity element for ranges that fall outside the query (0 for sum, Integer.MIN_VALUE for max, +∞ for min). Commutativity is not required as long as left and right are merged in order. That is what allows merges such as "max subarray sum within a range" that store a tuple per node.

    Bottom-up (iterative) segment tree. Leaves live at [n, 2n) and node x has children 2x and 2x+1. A query over the half-open range [l, r) walks both bounds upward. It is short and fast, and its natural convention is half-open. The 2407 solution uses it; the recursive Template A uses inclusive bounds. Never mix the two conventions inside one implementation.

    Lazy propagation (range updates). A range update would touch O(n) leaves, so instead store a pending tag on each fully covered node and push it to the children only when a later operation needs to descend. This requires (1) a tag that can be applied to a node aggregate in O(1) (add: sum += tag · length; assign: max = value), and (2) tags that compose (add then add equals one add; assign overrides an earlier assign or add). If you cannot define both, lazy propagation does not apply as written.

    Fenwick tree — the low-bit structure. Internally 1-based. bit[i] stores the sum of the half-open range (i − lowbit(i), i], where lowbit(i) = i & −i is the value of i's lowest set bit.

    Two's complement: −i = ~i + 1. Below the lowest set bit, ~i has 1s and adding 1 carries through them, flipping back exactly that bit. Above it, i and ~i differ, so i & −i keeps only the lowest set bit. e.g. i = 12 = 1100₂, −i = …0100₂, i & −i = 4 prefix(i) = bit[i] + prefix(i − lowbit(i)) → strip low bits: ≤ log₂ n steps update(i, δ): bit[i] += δ; i += lowbit(i) → climb to every block containing i rangeSum(l, r) = prefix(r) − prefix(l − 1) → requires an inverse ("−") Index 0 is unusable: lowbit(0) = 0, so update(0) would loop forever. Hence 1-based.

    Zero-based input vs one-based internals. Keep the public API 0-based, matching LeetCode, and shift once at the boundary (i + 1) inside add and prefix. Shifting by hand at call sites is where off-by-one bugs come from.

    Why Fenwick fails for range max. With max you cannot recover max(l..r) from max(1..r) and max(1..l−1); the larger prefix hides the window. A Fenwick "prefix max" works only for prefix queries with increase-only updates. LC 2407 needs a window [x−k, x−1], so it needs a segment tree.

    Choosing by update/query type
    UpdatesQueriesStructure
    nonerange sumPrefix sums, O(1) query
    point (add / set)range sum / count / xorFenwick (set = add the difference; keep a copy of the array), or a segment tree
    range addpoint valueFenwick over the difference array: add at l, subtract at r+1; the point value is a prefix sum (Template E)
    range addrange sumLazy segment tree (Template C), or two Fenwick trees
    point setrange max / min / gcdSegment tree (recursive or bottom-up)
    range assignrange maxLazy segment tree with an assign tag (LC 699)
    Coordinate compression: shrinking a 109 axis to n slots

    Value-indexed structures need an array as large as the value range. When only relative order matters, map each distinct value to its rank among the sorted distinct values. This preserves comparisons (x < y ⇔ rank(x) < rank(y)) and the structure needs only m ≤ n slots.

    • Point values (LC 315): sort a copy, deduplicate, and look up the rank with Arrays.binarySearch. Equal values share a rank, which matters for "strictly smaller".
    • Intervals (LC 699): compress endpoints, and let slot i stand for the half-open cell [xs[i], xs[i+1]). An interval [a, b) covers slots rank(a) … rank(b) − 1. Compressing only starts would merge cells that must stay distinct.
    • Offline requirement: all coordinates must be known before building. For online problems with unknown coordinates, use a dynamic (pointer-based) segment tree.

    Breaks naive codeThe Fenwick set operation (needs the old value: add val − a[i] and store a[i] = val); duplicates in compressed ranks for strict comparisons; n = 0 or 1.
    Interview follow-upsk-th smallest via Fenwick binary lifting; a 2D Fenwick for matrix sums (LC 308); a dynamic segment tree for online coordinates; why Fenwick cannot do range max; persistence and offline queries.

    20.6Pattern mastery checklist

    Essential takeaways

    • Segment tree: associative merge + identity; range [l, r] splits into O(log n) canonical nodes.
    • Fenwick: bit[i] covers (i − (i & −i), i]; updates climb, queries descend; ranges need an inverse.
    • Range updates need lazy tags that apply in O(1) and compose. If they don't, find another approach.
    • Index structures by value (after compression) to answer "how many / best among values in a range so far".
    • Fix one bound convention per implementation and convert at the API boundary.

    Recognition rule. Interleaved updates and range queries over the same array (or value axis) → Fenwick if the operation is invertible and updates are point updates; otherwise a segment tree, lazy if updates cover ranges.

    In-interview checklist

    • Update type: point add, point set, range add, range assign?
    • Query type: point or range; sum, count, max, or a custom merge?
    • Is the merge invertible? Associative? What is its identity?
    • Index domain: positions or values? Does it need compression?
    • Bounds: inclusive or half-open; 0-based API vs 1-based internals?

    Key distinction. A Fenwick tree is smaller and simpler but limited to invertible prefix-style aggregates with point updates (or the difference-array dual). A segment tree is the general tool for associative range aggregates and range updates.

    Range Sum Query - Mutable

    Medium

    Task. Implement NumArray(nums), update(index, val) (sets a value) and sumRange(left, right) (inclusive), with up to 3·104 calls.

    Key insight

    Static prefix sums make each update O(n). Storing O(log n)-sized block sums makes both operations logarithmic. Sum is invertible, so either structure works; this is the problem to practise both.

    Why the pattern applies

    Point updates are interleaved with inclusive range-sum queries, which is the defining case. Version 1 is a segment tree (Template A, specialised). Version 2 is a Fenwick tree (Template B), which needs the old value to turn a set into an add.

    Approach
    1. Segment tree: build O(n); update resets a leaf and recomputes its ancestors; sumRange merges the canonical nodes.
    2. Fenwick: keep nums; update adds val − nums[i]; sumRange = prefix(r) − prefix(l − 1).

    Timebuild O(n); update and query O(log n)SpaceO(n) (4n segment tree, n + 1 Fenwick)

    Pitfall. In the Fenwick version, update is a set. Adding val directly double-counts the old value. Keeping nums in sync is mandatory. Sums are at most 3·104 × 100 in magnitude, so int suffices. Use long in general.

    LC 315

    Count of Smaller Numbers After Self

    Hard

    Task. For each i, count the indices j > i with nums[j] < nums[i]; n ≤ 105, values in [−104, 104].

    Key insight

    Sweep from right to left while maintaining frequencies of the values already seen (exactly those with j > i). The answer for i is the count of seen values whose rank is smaller than rank(nums[i]): a prefix sum over the value axis.

    Why the pattern applies

    Each step does one point update (+1 at a value) and one prefix query. Counts are invertible, so a Fenwick tree is the natural fit. Values are compressed to ranks so the tree has m ≤ n slots and negative values need no offset.

    Approach
    1. Compress: sorted distinct values; rank(v) via binary search.
    2. For i = n−1 down to 0: ans[i] = prefix(rank − 1) (strictly smaller), then add(rank, 1).

    TimeO(n log n)SpaceO(n)

    Pitfall. "Strictly smaller" means querying ranks 0..rank−1, which is prefix(rank − 1) in 0-based terms. The inner loop starts at k = rank because internal index = 0-based index + 1. Querying before inserting nums[i] excludes i itself. An equally valid alternative is merge sort that counts the right-half elements moved before each left element.

    LC 2407

    Longest Increasing Subsequence II

    Hard

    Task. Find the longest strictly increasing subsequence in which adjacent elements differ by at most k; n, values, k ≤ 105.

    Key insight

    Let best[v] be the longest valid subsequence seen so far that ends with value v. Processing left to right, len(x) = 1 + max(best[v] for v in [x − k, x − 1]). That is a range-max query on the value axis followed by a point update best[x] = max(best[x], len).

    Why the pattern applies

    The DP transition is an aggregate over a window of values, and the window moves with x. Max is not invertible, so a Fenwick prefix-max cannot answer [x−k, x−1]. A segment tree over values 1..maxV does both operations in O(log V). This solution uses the bottom-up variant with half-open queries.

    Approach
    1. Size = next power of two ≥ maxV + 1; leaves at [size, 2·size); leaf v stores best[v].
    2. For each x: q = max over [max(1, x−k), x); len = q + 1; update leaf x with max; track the overall answer.

    TimeO(n log V)SpaceO(V)

    Pitfall. Strictly increasing means the window excludes x itself, so the query is [x−k, x). A previous occurrence of x must not extend itself. The classic patience-sorting LIS (binary search over tails) does not handle the "difference ≤ k" constraint. The update keeps a maximum (max(best[x], len)) because a later, shorter subsequence ending at x must not overwrite a longer one.

    LC 699

    Falling Squares

    Hard

    Task. Squares [left, side] fall one by one and land on the highest square they overlap (touching edges do not count). After each drop, report the tallest stack height. Coordinates go up to 108; up to 1000 squares.

    Key insight

    A square occupies the half-open interval [left, left + side). Its landing height is max(height over that interval) + side, and afterwards the whole interval has exactly that height. That is a range-max query followed by a range assignment, on a compressed axis.

    Why the pattern applies

    Range updates are combined with non-invertible range queries, which calls for a lazy segment tree with an assign tag. Assign tags compose (the later assign wins), and applying one to a node sets its max directly. The 108 axis is compressed to at most 2000 endpoints.

    Approach
    1. Collect all left and left + side, sort and deduplicate into xs. Slot i is the cell [xs[i], xs[i+1]).
    2. A square covers slots rank(left) … rank(left + side) − 1, so touching squares share no slot.
    3. h = queryMax(range) + side; assign(range, h); running answer = max(answer, h).

    TimeO(n log n)SpaceO(n)

    Pitfall. Treating squares as closed intervals [left, left + side] makes edge-touching squares stack, which is wrong. The half-open cell mapping prevents it. Heights reach about 1000 × 106 = 109, which still fits in an int; use long if constraints grow. With n ≤ 1000, an O(n²) interval scan is also accepted. Mention it, then present the segment tree as the scalable answer.

    Part III · Algorithm A1

    Monotonic Stack

    A stack whose contents stay sorted. Each element is pushed once and popped once, and the moment it is popped is exactly when you learn its nearest greater (or smaller) neighbour.

    A1.1Purpose and practical applications

    Purpose
    For every index, find the nearest index to the left or right whose value is greater (or smaller), all in O(n) total.
    Applications
    Next greater element, daily temperatures, stock span, largest rectangle in a histogram, maximal rectangle in a binary matrix, trapping rain water (layer by layer), sum of subarray minimums/maximums, remove-k-digits and other "smallest lexicographic subsequence" problems.
    Key insight
    An element that is dominated (a smaller value to the left of a larger one, when searching for "next greater") can never be the answer for anything further right, so it can be discarded permanently.

    A1.2Recognition signals

    • The answer for position i is the first element to its left or right satisfying a comparison with a[i]: "next warmer day", "previous smaller bar", "how far can this extend".
    • You need, for each element, the maximal range in which it is the minimum (or maximum). This is contribution counting: Σ a[i] · (#subarrays where a[i] is the minimum).
    • A greedy that "removes earlier elements while the new one is better" (e.g. build the smallest number by deleting digits).
    • n up to 105 with an obvious O(n²) "scan outward from each i".

    Ask yourself. "When a new element arrives, which earlier elements can never again be an answer?" If those elements always form a suffix of what you are holding, the structure is a monotonic stack.

    Not appropriate when you need the global extreme of a changing set (use a heap), the extreme of a sliding window (use a monotonic deque, which also evicts from the front), or the k-th nearest rather than the nearest.

    A1.3Core concept and invariant

    Goal (scanning left → right)Stack order bottom → topPop while…
    Next greater elementDecreasinga[top] < a[i]: i is top's next strictly greater
    Next greater or equalStrictly decreasinga[top] <= a[i]
    Next smaller elementIncreasinga[top] > a[i]
    Previous smaller (after pops)IncreasingPop a[top] >= a[i]; the new top is the previous strictly smaller element

    Invariant (next-greater form). After processing index i, the stack holds exactly the indices j ≤ i that do not yet have a next greater element, and their values are non-increasing from bottom to top. A popped index has found its answer, and that answer is final: i is the first index after it with a larger value, because every index between them was either smaller (popped earlier, or never above it) or is still on the stack above it, which contradicts the order.

    Index vs value storage. Store indices. They give you the distance (i − top), the value (a[top]) and a write position in the answer array. Store values only when positions never matter (e.g. remove-k-digits builds the output directly).

    Amortised O(n). Each index is pushed exactly once and popped at most once, so the inner while loop runs at most n times in total across all iterations, even though a single iteration may pop many.

    A1.4Important formulas and derivations

    For contribution counting, let L[i] be the index of the previous element strictly smaller than a[i] (or −1), and R[i] be the index of the next element smaller or equal (or n). Then a[i] is the minimum of every subarray [l, r] with L[i] < l ≤ i ≤ r < R[i]:

    count(i) = (i − L[i]) · (R[i] − i) Σ over subarrays of min = Σᵢ a[i] · (i − L[i]) · (R[i] − i) Why one side strict and the other non-strict: with duplicates, a subarray such as [2, 2] has two positions holding its minimum. Making exactly one side non-strict assigns it to exactly one of them (here the rightmost occurrence), so nothing is double-counted or missed.

    A1.5Reusable Java implementation

    Template A — next greater (right) and previous smaller (left). ArrayDeque used as a stack: push/peek/pop act on the head.

    Template B — contribution boundaries in one pass. An index is popped by the first element to its right that is ≤ it (right boundary, non-strict), and the element below it on the stack is its previous strictly smaller element (left boundary). A sentinel of −∞ at position n flushes the stack.

    A1.6Time and space complexity

    TimeO(n) amortised: n pushes, at most n pops.
    Auxiliary spaceO(n) for the stack in the worst case (monotone input never pops), plus the answer array.

    A1.7Common pitfalls

    • Strict vs non-strict. < vs <= decides whether equal values resolve each other. For "next strictly warmer", equal temperatures must not pop. For contribution counting, exactly one side must be non-strict.
    • Forgetting the leftovers. Indices still on the stack at the end have no answer. Pre-fill with −1/0/n or use a sentinel.
    • Overflow. In contribution counting, a[i] · left · right can reach 3·104 · (3·104)² ≈ 2.7·1013: compute in long and take the modulus only at the end of each product.
    • Using Stack<Integer>. It is synchronised and slower. Prefer ArrayDeque, or a plain int[] with a top pointer for speed.
    • Circular arrays (Next Greater Element II): iterate i from 0 to 2n−1 using i % n, and push only during the first pass.

    Daily Temperatures

    Medium

    Task. For each day, return how many days you must wait for a strictly warmer temperature (0 if never).

    Key insight

    "Next strictly greater element to the right", with the answer expressed as an index distance. A day is popped exactly when its first warmer day arrives.

    Why the algorithm applies

    The answer is the nearest qualifying element by position, and a colder day sitting to the left of a warmer one can never be the answer for later days.

    Approach
    1. Keep a stack of indices with non-increasing temperatures.
    2. For each i, pop every index with a strictly smaller temperature and set ans[j] = i − j.
    3. Push i. Remaining indices keep the default 0.

    TimeO(n) amortisedSpaceO(n) stack

    Pitfall. Using <= in the pop condition would treat an equal temperature as "warmer". An alternative O(1)-extra-space solution scans right-to-left and jumps along already computed answers (j += ans[j]), but the stack form is the one to know.

    LC 907

    Sum of Subarray Minimums

    Medium

    Task. Return the sum of min(sub) over every contiguous subarray, modulo 109+7.

    Key insight

    Instead of enumerating O(n²) subarrays, count how many subarrays each element is the minimum of: (i − L[i]) · (R[i] − i), with one strict and one non-strict boundary so that duplicates are counted once.

    Why the algorithm applies

    L[i] (previous strictly smaller) and R[i] (next smaller-or-equal) are both nearest-smaller queries, which a single increasing stack answers at pop time (Template B).

    Approach
    1. Scan i = 0..n with a sentinel at n; pop while arr[top] >= cur.
    2. For the popped mid: left boundary = new top (or −1), right boundary = i.
    3. Add arr[mid] · (mid − left) · (i − mid) in long, reducing modulo 109+7.

    TimeO(n)SpaceO(n)

    Pitfall. Making both boundaries strict double-counts subarrays with repeated minima (e.g. [1,1]); making both non-strict misses them. Also, (mid − left) · (i − mid) can reach 9·108 and its product with arr[mid] exceeds the int range, so cast to long before multiplying. The sentinel value 0 is valid only because the constraints guarantee arr[i] ≥ 1.

    Dijkstra's Algorithm

    Greedy single-source shortest paths for non-negative weights: always finalise the closest unfinished vertex. Chapter 18 covers the pattern and its problem shapes. This chapter covers the proof, the exact conditions under which the greedy step stays valid, and two generalisations: multiplicative path values and counting shortest paths.

    A2.1Purpose and practical applications

    Purpose
    Compute dist[v], the minimum total weight of a path from a source s to every vertex v, when every edge weight is ≥ 0.
    Applications
    Network delay, routing, grid paths with costs, minimum-effort and minimax paths, maximum-reliability paths (products of probabilities ≤ 1), counting shortest paths, shortest paths on expanded state graphs (node, fuel), (node, stops), (cell, keys).
    Key insight
    With non-negative weights a path never gets cheaper as it grows, so the cheapest frontier vertex cannot be improved by any route through vertices that are farther away.

    A2.2Recognition signals

    • A shortest, cheapest, fastest or most reliable route on a graph or grid whose edges have different, non-negative costs.
    • The path cost is built by an operation that is monotone along the path: sum of non-negative weights, maximum of edge weights, product of factors in [0, 1] (maximised).
    • Single source (or a super-source for multi-source), V and E up to about 105.
    • A state richer than a vertex is fine, provided the state space stays small enough: Dijkstra runs on any graph whose vertices are states.

    Ask yourself. "Can extending a path ever make it better?" If no, a greedy settle-the-best-first order is valid. If yes (negative weights, or a bonus for longer paths), Dijkstra is invalid.

    A2.3Core concept and invariant

    Relaxation. For an edge u → v with weight w: if dist[u] + w < dist[v] then dist[v] = dist[u] + w. Every shortest-path algorithm is a strategy for ordering relaxations. Dijkstra orders them by settling vertices in increasing distance, so each edge is relaxed once from its final source distance.

    Invariant. Let S be the set of settled vertices. (1) For every v ∈ S, dist[v] equals the true distance δ(s, v). (2) For every v ∉ S, dist[v] is the shortest path to v that uses only vertices of S before its last edge.

    Proof that the popped vertex is final

    Let u be the unsettled vertex with the smallest tentative dist[u] = d. Take any s → u path P. P starts inside S and ends outside it, so it has a first vertex x outside S, reached by an edge y → x with y ∈ S. By invariant (2), the prefix of P up to x costs at least dist[x] ≥ d (u was the minimum). The rest of P, from x to u, has weight ≥ 0. So cost(P) ≥ d, and no path beats dist[u]. Settling u preserves (1), and relaxing u's edges restores (2).

    The step "the rest of P has weight ≥ 0" is exactly where negative weights break the proof.

    Why negative weights break it. Edges s→a (2), s→b (3), b→a (−2). Dijkstra settles a at distance 2 before it settles b. The true distance is 3 + (−2) = 1, found only after a has been finalised. With lazy re-insertion some implementations happen to recover in this case, but then the "settled once" guarantee and the complexity bound both disappear, and negative cycles make the answer undefined. Use Bellman–Ford (A7).

    Stale entries. Java's PriorityQueue has no decrease-key. Push a new (dist, v) entry on every improvement and, when popping, skip any entry whose distance is larger than the current dist[v]. The heap holds at most E + 1 entries.

    A2.4Important formulas and derivations

    Generalised condition: path value f(P · e) is computed from f(P) and w(e) by an operation ⊕ that is (a) monotone: a ≤ b ⇒ a ⊕ w ≤ b ⊕ w (b) non-improving: a ⊕ w ≥ a (for minimisation) Sum with w ≥ 0 : a ⊕ w = a + w ✓ Bottleneck (LC 1631) : a ⊕ w = max(a, w) ✓ Reliability (LC 1514) : a ⊕ p = a · p, p ∈ [0, 1] ✓ (maximise; value never increases) Sum with w < 0 : violates (b) ✗ → Bellman–Ford Counting shortest paths (weights > 0): ways[s] = 1 ways[v] = Σ ways[u] over edges u → v with dist[u] + w(u, v) = dist[v]

    The counting recurrence is evaluated correctly in pop order because every predecessor u on a shortest path to v has dist[u] < dist[v] when weights are strictly positive. So all of v's contributors are settled, and their counts are final, before v itself is popped. With zero-weight edges this ordering argument fails and the counting needs extra care: zero-weight ties may be popped in either order.

    A2.5Reusable Java implementation

    Template A — lazy Dijkstra with path reconstruction. Directed edges {u, v, w} with w ≥ 0; add the reverse edge for undirected graphs. Distances are long because sums of int weights overflow.

    Template B — dense-graph Dijkstra, O(V²), no heap. When E ≈ V² (a complete graph or adjacency matrix), a linear scan for the minimum beats a heap's O(E log V).

    A2.6Time and space complexity

    Binary heap, lazy deletionO((V + E) log E) = O((V + E) log V), since E ≤ V². Space O(V + E): adjacency lists plus up to E heap entries.
    Array scan (dense)O(V² + E) time, O(V) extra space. Better when E = Θ(V²).
    Fibonacci heap (theory)O(E + V log V). Not used in interviews.

    A2.7Common pitfalls

    • No stale check. Without if (d > dist[u]) continue, the code stays correct but may re-expand vertices many times. For counting problems it double-counts ways.
    • Marking visited on push (BFS habit). The first push is not necessarily the shortest, so a vertex is final only when popped.
    • int distances. 105 edges × 109 weight overflows int. Use long, an INF with headroom, and Long.compare in the comparator.
    • Comparator subtraction (a, b) -> (int)(a[0] − b[0]) truncates and overflows. Never use it.
    • Early exit on popping the target is safe; exiting when the target is first pushed is not.
    • Directed vs undirected. Check the statement; LC 743 is directed, LC 1514 and 1976 are undirected.

    LC 1514

    Path with Maximum Probability

    Medium

    Task. In an undirected graph whose edges carry success probabilities in [0, 1], return the maximum probability of a path from start_node to end_node, or 0 if no path exists.

    Key insight

    Path value is a product of factors in [0, 1], so extending a path never increases its value. That is the mirror image of "never decreases the cost", which makes greedy settle-the-most-probable-first valid with a max-heap.

    Why the algorithm applies

    The monotone, non-improving condition from A2.4 holds with ⊕ = multiplication and the order reversed. Equivalently, minimise Σ −log p, which has all weights ≥ 0. Multiplying directly avoids floating-point log error.

    Approach
    1. Build an undirected adjacency list with probabilities.
    2. best[start] = 1; max-heap on probability; skip stale entries where p < best[u].
    3. Relax best[v] = max(best[v], best[u] · p); return when end is popped.

    TimeO((V + E) log E)SpaceO(V + E)

    Pitfall. A min-heap (copied from shortest-path code) silently settles the least probable path first. Edges with probability 0 never improve best[v] from 0 and are correctly ignored. The node id is stored in a double slot, which is exact for integers far beyond n ≤ 104.

    LC 1976

    Number of Ways to Arrive at Destination

    Medium

    Task. In an undirected graph with positive travel times, count the shortest-time paths from intersection 0 to n − 1, modulo 109+7.

    Key insight

    Shortest-path counting is DP over the shortest-path DAG, and Dijkstra's pop order is a topological order of that DAG when weights are strictly positive. Count while relaxing: a strict improvement resets the count, and an equal distance adds to it.

    Why the algorithm applies

    Weights are positive (time ≥ 1), so the recurrence from A2.4 is complete for v when v is popped. Distances reach about 200 × 109, so they need long.

    Approach
    1. dist[0] = 0, ways[0] = 1.
    2. Pop (d, u); skip stale entries. For each edge (u, v, t): if d + t < dist[v], set dist[v], ways[v] = ways[u], push; else if equal, ways[v] += ways[u].
    3. Return ways[n−1].

    TimeO((V + E) log E)SpaceO(V + E)

    Pitfall. Without the stale check, a vertex popped twice at the same distance would push its ways into neighbours twice. Using int distances overflows at about 2.1·109. The edge case n = 1 returns ways[0] = 1.

    Union-Find / Disjoint Set Union

    A forest of parent pointers that answers "are x and y in the same group?" while groups only ever merge. Chapter 17 applies it to connectivity problems. This chapter covers why the two optimisations matter, what the amortised bound really means, a weighted extension, and the counting arguments that recur in DSU problems.

    A3.1Purpose and practical applications

    Purpose
    Maintain a partition of n elements under union(x, y) and find(x) (the canonical representative), in near-constant amortised time per operation.
    Applications
    Connected components with edges arriving online, cycle detection in undirected graphs, Kruskal's MST (A4), equivalence constraints (a == b), account/email merging, percolation, "number of islands II", offline connectivity queries sorted by threshold, and ratio or parity constraints (weighted DSU).
    Key insight
    Only the identity of each group matters, not its shape. That freedom lets you flatten trees aggressively (path compression) and attach small trees under large ones (union by size), keeping every tree almost flat.

    A3.2Recognition signals

    • Relations that are reflexive, symmetric and transitive (equivalence): "connected", "same account", "equal", "friends of friends".
    • Edges or relations arrive over time, interleaved with "same group?" or "how many groups?" queries.
    • Counting components, or counting the edges that are redundant within a component.
    • Detecting the first edge that closes a cycle in an undirected graph.

    Ask yourself. "Do groups only merge, and do I only need membership, not paths?" If you need splits (edge deletion), paths, distances or directed reachability, DSU is the wrong tool.

    A3.3Core concept and invariant

    Representation. parent[x] points toward the root of x's tree, and a root has parent[r] = r. Two elements are in the same set exactly when their roots coincide. The invariant to preserve: every element's parent chain ends at its own set's root. A union only re-points one root, so it never breaks the chains of other elements.

    • Path compression: during find, point visited nodes directly (or every other node, for path halving) at the root. Membership is unchanged; only the shape changes.
    • Union by size / rank: attach the root of the smaller tree under the root of the larger. A node's depth grows only when its tree at least doubles in size, so depth ≤ log₂ n even without compression.

    A3.4Important formulas and derivations

    Union by size alone : height ≤ ⌊log₂ n⌋ ⇒ find is O(log n) worst case Path compression alone : O(log n) amortised per operation (m ≥ n operations) Both together (Tarjan) : O(m · α(n)) for m operations; α(n) ≤ 4 for any n < 2^65536 Components after processing edges: components = n − (number of successful unions) Redundant edges : redundant = E − (number of successful unions) Connecting k components needs exactly k − 1 additional edges.

    Why size beats rank in interviews. Both give the same bound. Size has a direct meaning: it answers "how large is x's group?" with size[find(x)] at no extra cost.

    A3.5Reusable Java implementation

    Template A — DSU with path halving and union by size. The iterative find avoids recursion depth issues for n up to 106.

    Template B — weighted DSU (potential to the root). This stores w[x] = value(x) − value(parent[x]), so constraints such as value(b) − value(a) = d can be merged and checked. It is the basis of LC 399 (Evaluate Division, in multiplicative form) and of parity problems.

    Template B uses recursion and no union by size, to keep the offset algebra readable. Its depth is O(log n) amortised but can be O(n) on a single first call, so add union by size (the offset formula is symmetric) when n is large.

    A3.6Time and space complexity

    TimeO(α(n)) amortised per find/union with both optimisations; O(n) to initialise.
    SpaceO(n) for parent and size.
    Without optimisationsO(n) per operation worst case (a chain), so O(n · m) total.

    A3.7Common pitfalls

    • Comparing parents instead of roots. parent[x] == parent[y] is wrong; always compare find(x) == find(y).
    • Updating size on the wrong root, or reading size[x] for a non-root x.
    • Recursive find on 105+ elements with no union by size can overflow the stack on the first call.
    • Labels that are not 0..n−1 (strings, coordinates, 1-indexed cities): map them to dense ids first, or size the array n + 1.
    • Expecting deletions. DSU cannot split a set. For offline problems, process in reverse (deletions become unions) or use DSU with rollback.
    • Directed graphs. DSU ignores direction; cycle detection in a directed graph needs DFS colouring (Ch. 11).

    Number of Operations to Make Network Connected

    Medium

    Why the algorithm applies

    Approach

    Part III · Algorithm A4

    Minimum Spanning Tree: Kruskal and Prim

    Connect every vertex of an undirected, weighted graph with the minimum total edge weight. Both classic algorithms are greedy, and both are justified by the same cut property.

    A4.1Purpose and practical applications

    Purpose
    Find a set of V − 1 edges that connects all V vertices of an undirected graph with minimum total weight (a minimum spanning forest if the graph is disconnected).
    Applications
    Network/cable/pipe layout, connecting points at minimum cost, clustering (remove the k − 1 heaviest MST edges), approximation for metric TSP, minimax paths (the MST contains a bottleneck-optimal path between every pair), "critical and pseudo-critical edges".
    Key insight
    For any partition of the vertices into two sides, the cheapest edge crossing the partition is safe to add. Kruskal and Prim are two different ways of choosing which partition to look at.

    A4.2Recognition signals

    • "Connect all", "minimum total cost to link every", "any network is fine as long as everything is reachable".
    • Undirected graph; the cost is the sum of chosen edges, not the distance between particular pairs.
    • Points in a plane with a cost per pair (an implicit complete graph).
    • The answer should be −1 or "impossible" when the graph cannot be connected: check that V − 1 edges were taken.

    Ask yourself. "Is the objective the total weight of the network, or the distance from a source?" Total weight → MST. Source distances → shortest-path tree (Dijkstra). The two trees are generally different.

    Not applicable to directed graphs (that is the minimum arborescence problem, solved by Chu–Liu/Edmonds), or when only a subset of terminals must be connected (the Steiner tree problem, which is NP-hard).

    A4.3Core concept and invariant

    Invariant (both algorithms). The chosen edge set F is always a subset of some minimum spanning tree.

    Cut property and its exchange proof

    Let (S, V∖S) be a cut that no edge of F crosses, and let e = (u, v) be a minimum-weight edge crossing it. Take an MST T ⊇ F. If e ∈ T, we are done. Otherwise T + e contains a cycle, and that cycle must cross the cut a second time through some edge e' ∈ T. Since w(e) ≤ w(e'), the tree T' = T + e − e' is spanning, has weight ≤ w(T), and contains F + e. So F + e is still inside an MST.

    Kruskal scans edges by weight. When edge (u, v) joins two different components, take the cut S = component of u: no lighter edge crosses it (any lighter crossing edge would have been taken already), so the edge is safe. Prim grows a single tree S and repeatedly takes the cheapest edge leaving S, which is a direct application of the cut property.

    Cycle property (the dual). The heaviest edge on any cycle (if strictly heaviest) is in no MST. That is why Kruskal may safely reject an edge whose endpoints are already connected.

    A4.4Important formulas and derivations

    A spanning tree of V vertices has exactly V − 1 edges. Connected ⇔ Kruskal accepts exactly V − 1 edges. Spanning forest of a graph with c components has V − c edges. Kruskal : O(E log E) sort + O(E · α(V)) DSU = O(E log V) Prim : binary heap, lazy O(E log E) = O(E log V) adjacency matrix / complete graph, array scan O(V²) Dense complete graph (E = V(V−1)/2): Prim O(V²) beats Kruskal O(V² log V)

    If all edge weights are distinct the MST is unique. With ties there may be several MSTs, all with the same total weight.

    A4.5Reusable Java implementation

    Template A — Kruskal with DSU. Undirected edges {u, v, w}, vertices 0..n−1. Returns the forest weight and reports connectivity.

    Template B — Prim with a lazy binary heap. Adjacency list; a vertex is added to the tree when it is first popped.

    Prim's heap holds edge weights (the cost to attach a vertex), not path distances. Writing dist[u] + w, the Dijkstra habit, computes a shortest-path tree instead.

    A4.6Time and space complexity

    KruskalO(E log E) time; O(V) DSU space + O(E) for the sorted copy.
    Prim (heap)O(E log E) time; O(V + E) space for adjacency lists and heap.
    Prim (array, dense)O(V²) time, O(V) space; no edge list needs to be materialised.

    A4.7Common pitfalls

    • Confusing MST with shortest paths. Prim's key is the single attaching edge weight, not the path distance from the root.
    • Disconnected input. Prim started at vertex 0 silently returns a tree of 0's component only. Check that all V vertices were added (or V − 1 edges, for Kruskal).
    • Materialising V² edges for 1000+ points in Kruskal: about 500k edges and an O(E log E) sort works but is slower and heavier than O(V²) Prim.
    • 1-indexed vertices (LC 1135): size the arrays n + 1, or subtract 1.
    • Overflow. The total of V − 1 weights can exceed the int range: accumulate in long.

    A4.8Comparison with related algorithms

    AlgorithmMechanismBest for
    KruskalGlobal edge order + DSUSparse graphs given as edge lists; spanning forests; "process edges by threshold" problems
    Prim (heap)Grow one tree via the cheapest crossing edgeGraphs given as adjacency lists
    Prim (array)Linear scan for the closest outside vertexDense or complete graphs (point sets), O(V²)
    Dijkstra (A2)Grow a tree by path distanceShortest paths from one source, a different objective

    Kadane's Algorithm

    A one-pass dynamic programme for the best contiguous subarray. The best subarray ending at index i either extends the best one ending at i − 1 or starts fresh at i.

    A5.1Purpose and practical applications

    Purpose
    Maximum (or minimum) sum over all non-empty contiguous subarrays in O(n) time and O(1) space.
    Applications
    Maximum subarray, circular maximum (via a minimum-subarray complement), best time to buy and sell once (Kadane on price differences), maximum-sum submatrix (Kadane over compressed column sums, O(R²·C)), and "maximum gain from flipping a segment" style problems.
    Key insight
    Only the best sum ending exactly at i needs to be carried forward. A negative running sum can never help any future subarray, so drop it.

    A5.2Recognition signals

    SignalStructural reason
    Contiguous subarray, objective is a sum (max or min), no length or target constraintThe objective decomposes as "best ending here" with a two-way choice: extend or restart.
    Negative values presentWith all non-negative values the answer is the whole array. Negatives make Kadane, not a sliding window, the right tool.
    Wraparound allowedA circular subarray is either a normal subarray or the complement of a normal one (total − minimum subarray).
    "Profit", "gain", "net change" over a contiguous periodConvert to a difference array and run Kadane over it.

    Ask yourself. "Is the objective a sum of a contiguous block with no other constraint?" If there is a target sum, use prefix sums + hash map (Pattern 4). If there is a length bound, use prefix sums with a monotonic deque. If the objective is a product, track both max and min.

    A5.3Core concept and invariant

    Let end(i) be the maximum sum of a non-empty subarray that ends exactly at index i, and best(i) the maximum over all subarrays within a[0..i].

    Invariant after processing index i: cur = end(i) = max sum of a[j..i] over 0 ≤ j ≤ i best = max(end(0), …, end(i))

    Every subarray ends somewhere, so the answer is max over i of end(i). That is the whole correctness argument: local best (ending here) feeds the global best (anywhere so far).

    A5.4Important formulas and derivations

    end(0) = a[0] end(i) = a[i] + max(0, end(i−1)) = max(a[i], end(i−1) + a[i]) answer = max over i of end(i) Derivation: a subarray ending at i is either [i] alone, or a[j..i−1] followed by a[i]. The best of the second kind is end(i−1) + a[i]. So keep the previous run only if it is positive.

    Prefix-sum view. sum(a[j..i]) = pre[i+1] − pre[j], so end(i) = pre[i+1] − min(pre[0..i]). Kadane is the same as tracking the running minimum prefix. This view generalises to length-constrained versions: use a minimum over a sliding range of prefixes (monotonic deque).

    Circular case. A wrapping subarray takes a suffix and a prefix, which is the complement of a middle block a[j..i]. Its sum is total − sum(a[j..i]), maximised when the middle block is the minimum subarray:

    circular = max( maxSubarray(a), total − minSubarray(a) ) Exception: if every element is negative, minSubarray = total, so total − min = 0 corresponds to the empty subarray, which is not allowed. Return maxSubarray(a) in that case (detect it with maxSubarray < 0).

    Empty-subarray conventions. If the problem allows an empty subarray (answer ≥ 0), start with cur = 0, best = 0 and clamp cur = max(0, cur + a[i]). If subarrays must be non-empty (LeetCode 53, 918), initialise both with a[0]. Initialising best = 0 returns 0 instead of −1 on [-3,-1,-2].

    Extensions worth knowing
    • Recovering indices. Record start whenever you restart (cur becomes a[i]) and copy (start, i) when best improves.
    • Maximum product subarray (LeetCode 152). Multiplying by a negative swaps max and min, so carry both maxEnd and minEnd. A plain Kadane is wrong here.
    • K-concatenation (LeetCode 1191). The answer uses at most two copies plus (k − 2) · total when total > 0. Run Kadane over two copies.
    • 2D maximum-sum rectangle. Fix a pair of rows, compress columns into a 1D array, run Kadane: O(R²·C).
    • At most one deletion (LeetCode 1186). Two states: best ending here with no deletion, and with one deletion used.

    A5.5Reusable Java implementation

    A5.6Time and space complexity

    TimeO(n), a single pass. The circular version is also O(n) (one pass tracking max, min and total).
    Auxiliary spaceO(1). The DP table end[] collapses to one variable because end(i) depends only on end(i − 1).

    A5.7Common pitfalls

    • Zero initialisation when subarrays must be non-empty: returns 0 for all-negative input.
    • Updating best before cur, or resetting cur = 0 before adding a[i]. That variant silently allows the empty subarray.
    • Circular all-negative case: total − min = 0 is the empty subarray. Guard with if (max < 0) return max.
    • Using Kadane with a target or length constraint. Kadane cannot enforce either; switch to prefix sums.
    • Overflow on long arrays of large values. LeetCode 53 fits in int (n ≤ 105, |a| ≤ 104), but a template should use long.

    A5.8Comparison with related algorithms

    TechniqueUse whenWhy not Kadane
    Prefix sum + hash map (P4)Subarray sum equals k, divisible by k, longest with sum kKadane optimises; it cannot match an exact value.
    Sliding window (P2)Non-negative values with a sum boundWith non-negative values and no bound, the whole array is optimal, so Kadane is unnecessary.
    Prefix sum + monotonic dequeMaximum sum with length ≤ L, shortest subarray with sum ≥ K (LeetCode 862)Needs the minimum prefix over a bounded range.
    Divide and conquerWhen a segment tree must answer max-subarray queries on ranges with updatesKadane is offline and single-range; the (sum, prefix, suffix, best) merge supports range queries.
    General DP (P12)Extra state: deletions, products, k concatenationsKadane is the one-state special case of this DP.

    Medium

    Part III · Algorithm A6

    KMP String Matching

    Knuth–Morris–Pratt finds every occurrence of a pattern in linear time by precomputing, for each prefix of the pattern, its longest proper border. A mismatch then jumps straight to the next viable alignment.

    A6.1Purpose and practical applications

    Purpose
    Exact matching of a pattern P (length m) in a text T (length n) in O(n + m) worst case. Naive matching is O(n·m).
    Applications
    First or all occurrences, counting overlapping matches, the longest prefix that is also a suffix (LeetCode 1392), the smallest period of a string (LeetCode 459), the longest palindromic prefix (LeetCode 214), and rotation checks (B is a substring of A + A).
    Key insight
    When P[0..j−1] has matched and P[j] fails, the text's last j characters are P[0..j−1]. The next alignment that could succeed keeps the longest proper prefix of P[0..j−1] that is also its suffix, and that length is precomputed.

    A6.2Recognition signals

    SignalStructural reason
    Exact substring search with adversarial worst cases (aaaa…ab)Naive search degrades to O(n·m); KMP never moves backward in the text.
    "Longest prefix that is also a suffix", "border", "period", "repeated pattern"These are exactly the values of the prefix function.
    Prefix of S matched against a suffix of another stringConcatenate with a separator and read the final prefix-function value.
    Streaming text, with one pass and no backtrackingThe matcher's state is a single integer j (the matched prefix length).

    Ask yourself. "Is this about a prefix of a string reappearing later (as a suffix or inside another string)?" If yes, a prefix function on a well-chosen concatenation usually answers it. For many patterns at once, use Aho–Corasick or a trie (P19). For approximate or multi-length comparisons, rolling hashes are often simpler.

    A6.3Core concept and invariant

    Prefix function. For a string P, pi[i] = the length of the longest proper prefix of P[0..i] that is also a suffix of P[0..i]. Proper means shorter than i + 1.

    P = a b a b c a b a b a pi = 0 0 1 2 0 1 2 3 4 3 pi[8] = 4: "abab" is both a prefix and a suffix of "ababcabab". pi[9] = 3: "aba".

    Search invariant. After reading T[i], j = the length of the longest prefix of P that is a suffix of T[0..i]. A match is reported when j = m, after which j becomes pi[m − 1] so overlapping matches are found.

    Why matched characters need not be rechecked. Suppose P[0..j−1] equals T[i−j..i−1] and P[j] ≠ T[i]. Any shift that keeps fewer characters aligned must line a prefix of P up against a suffix of T[i−j..i−1] = P[0..j−1], which means a border of P[0..j−1]. Shifts that do not correspond to a border are mismatched on characters already known, so they are impossible. Trying borders in decreasing length (pi[j−1], pi[pi[j−1]−1], …) visits every viable alignment and skips the impossible ones without reading the text again.

    A6.4Important formulas and derivations

    Construction phase (pattern against itself). Borders of P[0..i] are obtained by extending borders of P[0..i−1]:

    pi[0] = 0 for i = 1..m−1: k = pi[i−1] longest border of P[0..i−1] while k > 0 and P[i] ≠ P[k]: k = pi[k−1] next shorter border if P[i] == P[k]: k++ pi[i] = k

    This is correct because the borders of a string are exactly pi[i−1], pi[pi[i−1]−1], …, so the loop tries every candidate border in decreasing order and takes the first that extends by P[i].

    Search phase. This is the same loop with T[i] in place of P[i], continuing to compare against P[j].

    Linear-time (amortised) proof. In each phase, k (or j) increases by at most 1 per character, so by at most n in total. Each iteration of the inner while loop decreases it by at least 1, and it never goes below 0. Therefore the total number of fallbacks is at most the total number of increases, and the work is O(m) for construction plus O(n) for search.

    Useful identities.

    Longest border of S = pi[|S| − 1] Smallest period of S = p = |S| − pi[|S| − 1] S is a repetition of a block ⇔ pi[|S|−1] > 0 and |S| mod p == 0 Longest palindromic prefix of S = pi[last] of S + '#' + reverse(S)

    A6.5Reusable Java implementation

    A6.6Time and space complexity

    TimeO(m) preprocessing + O(n) search = O(n + m) worst case, independent of the alphabet.
    Auxiliary spaceO(m) for the prefix function; O(n + m) if you build a concatenated string.

    A6.7Common pitfalls

    • if instead of while for the fallback: it stops after one shorter border, so it can compare against the wrong candidate and produce invalid pi values. For pattern aacaaab, the final value comes out as 1 instead of 0, because the last b is compared with a after only one fallback.
    • Off-by-one in the link: the fallback is pi[k − 1], not pi[k]; pi is indexed by the last index of the prefix.
    • Proper border: pi[0] must be 0 and the loop starts at i = 1. Otherwise every string is its own border.
    • Separator in concatenation tricks: it must not occur in either string, or it must be a character the alphabet excludes. This keeps the border from crossing the boundary.
    • Resetting j to 0 after a full match misses overlapping occurrences ("aa" in "aaa"). Use j = pi[m−1].
    • Library comparison: String.indexOf is naive O(n·m) in the worst case but very fast in practice. Mention KMP's guarantee when asked about worst cases.

    A6.8Comparison with related algorithms

    AlgorithmComplexityWhen to prefer it
    Naive / indexOfO(n·m) worst, fast averageShort patterns, non-adversarial input, interview "warm-up" answers.
    KMPO(n + m) worstGuaranteed linear time; borders, periods and prefix/suffix questions.
    Z-algorithmO(n + m)Equivalent power. z[i] = the longest common prefix of S and S[i..]. Some find it easier for "prefix occurs at position i" questions.
    Rabin–Karp (rolling hash)O(n + m) expectedMany lengths or many substring comparisons (longest duplicate substring with binary search). Requires collision handling.
    Aho–Corasick / TrieO(n + Σm + matches)Many patterns at once (dictionary matching).
    ManacherO(n)All palindromic substrings. KMP only gives palindromic prefixes via the reverse trick.

    Part III · Algorithm A7

    Bellman–Ford Algorithm

    Relax every edge, repeatedly. After round i, every shortest path that uses at most i edges has been found. This one fact gives negative-weight support, negative-cycle detection and edge-budgeted shortest paths.

    A7.1Purpose and practical applications

    Purpose
    Single-source shortest paths in a directed (or undirected, with care) graph whose edge weights may be negative. It also detects negative cycles reachable from the source.
    Applications
    Shortest paths with at most K edges (LeetCode 787), currency arbitrage (a negative cycle of −log rates), difference constraints (xv − xu ≤ w), and routing protocols (distance-vector routing is distributed Bellman–Ford).
    Key insight
    Without a reachable negative cycle, some shortest path to every vertex is simple, so it has at most V − 1 edges. Round i extends correct "≤ i − 1 edges" distances by one edge.

    Honest scope note. LeetCode has very few mainstream problems with genuinely negative edge weights. Its main Bellman–Ford application is the edge-budget variant (787). Negative weights and cycle detection are still standard interview discussion topics, so the template below implements them in full.

    A7.2Recognition signals

    SignalStructural reason
    Negative edge weightsDijkstra's "popped means final" argument fails; Bellman–Ford needs no ordering.
    "At most K edges / stops / transfers"Round-limited relaxation computes exactly the best path with ≤ i edges after round i (with snapshots).
    Detect arbitrage or an infinitely improvable cycleA V-th round that still relaxes an edge proves a negative cycle is reachable.
    Small V·E (e.g. V ≤ 100, E ≤ 104)O(V·E) fits the budget, and the code is shorter than Dijkstra's.

    Ask yourself. "Is there a negative weight or an edge-count limit?" If neither applies and weights are non-negative, Dijkstra (A2) is faster. If all pairs are needed and V ≤ ~400, use Floyd–Warshall.

    A7.3Core concept and invariant

    Relaxation. if dist[u] + w(u, v) < dist[v] then dist[v] = dist[u] + w(u, v). A relaxation never sets dist[v] below the weight of some real path to v, so distances are always upper bounds (or ∞).

    Invariant after round i (snapshot version): dist_i[v] = min weight over walks src ⇝ v using at most i edges dist_0[src] = 0, dist_0[v] = ∞ otherwise dist_i[v] = min( dist_{i−1}[v], min over edges (u,v,w) of dist_{i−1}[u] + w )

    This is a DP over "number of edges used". With in-place updates (the classical algorithm), dist after round i is at most disti: it may already include longer paths. That does not affect correctness for unconstrained shortest paths, but it breaks any edge budget.

    A7.4Important formulas and derivations

    Why V − 1 rounds suffice. If no negative cycle is reachable from the source, every shortest walk can have its cycles removed (each has weight ≥ 0) without increasing its cost. The result is a simple path with at most V − 1 edges. By the invariant, round V − 1 has considered every path with ≤ V − 1 edges, so the distances are final.

    Negative-cycle detection. If after V − 1 rounds some edge (u, v) can still be relaxed, with dist[u] finite, then a shortest path would need ≥ V edges, so it repeats a vertex. That repeated section must be a negative cycle, and it is reachable from src (dist[u] is finite). Conversely, a reachable negative cycle always leaves at least one relaxable edge: summing dist[v] ≤ dist[u] + w around the cycle would give 0 ≤ (cycle weight) < 0.

    Detection: ∃ (u,v,w): dist[u] ≠ ∞ and dist[u] + w < dist[v] after V−1 rounds ⇔ a negative cycle is reachable from src Vertices whose distance is −∞ : every vertex reachable FROM a vertex on (or fed by) that cycle. Propagate −∞ with V more rounds, or BFS from every vertex that still relaxes.

    Early termination. If a full round changes nothing, no later round can change anything, because each round depends only on the previous one. Stop early. When distances stabilise, no reachable negative cycle can exist.

    Why the snapshot matters. With in-place updates, one round can relax a → b and then b → c using the new dist[b], so it uses two edges in a single round. If the edge list happens to be in path order, one round can traverse a whole chain, and the "≤ i edges after round i" guarantee disappears.

    A7.6Time and space complexity

    TimeO(V·E) worst case (V − 1 rounds × E edges); O(K·E) for the edge-budget variant; often far less with early termination.
    Auxiliary spaceO(V) for distances (+ O(V) for the snapshot). The edge list is the input.

    A7.7Common pitfalls

    • Relaxing from unreachable vertices: INF + (negative w) is less than INF and creates fake distances. Always check dist[u] != INF.
    • Overflow: using Integer.MAX_VALUE as INF and adding w overflows. Use a guarded check or Long.MAX_VALUE / 4.
    • In-place updates under an edge budget (see the warning above).
    • Undirected graphs with negative edges: an undirected negative edge is a negative cycle of length 2 (u → v → u). Bellman–Ford is meaningless there unless the problem forbids reusing an edge.
    • Detecting any negative cycle, not only reachable ones: add a virtual source with 0-weight edges to all vertices (or start with dist = 0 everywhere).
    • K stops vs K edges: in 787, K stops means K + 1 flights (edges).

    A7.9Practice problem

    LC 787

    Cheapest Flights Within K Stops

    Medium

    Task. Directed flights [from, to, price] with price ≥ 1. Return the cheapest price from src to dst using at most K intermediate stops (so at most K + 1 flights), or −1.

    Key insight

    "At most K stops" is "at most K + 1 edges". After round i of snapshot Bellman–Ford, dist[v] is exactly the cheapest walk with ≤ i edges, so run K + 1 rounds and read dist[dst].

    Why the algorithm applies

    The weights are positive, so Dijkstra is tempting. But a vertex's cheapest path may use too many edges, while a dearer path with fewer edges is what later vertices need. Plain Dijkstra on vertices discards that path. Bellman–Ford's round structure tracks the edge count directly. Chapter 18 solves the same problem with Dijkstra on the expanded state (vertex, edges used).

    Approach
    1. dist[src] = 0, others ∞.
    2. Repeat K + 1 times: copy dist to next; relax every flight reading from dist and writing to next; set dist = next. Stop early if nothing changed.
    3. Return dist[dst], or −1 if it is still ∞.

    TimeO((K + 1) · E)SpaceO(V)

    Pitfall. Relaxing in place (no snapshot) can chain several flights in one round and return a price that needs more than K stops. Running exactly K rounds instead of K + 1 is the other common off-by-one.

    Part IV · B

    Interview recognition checklist

    Run this before writing any code. Each phase should take about a minute for a Medium problem, and saying it aloud doubles as communication with the interviewer.

    1. Understand

    • Restate the task in one sentence: input → output.
    • Clarify contiguous vs any subset; distinct vs repeated values; 0- or 1-based output.
    • Read the constraints; write down the complexity budget.
    • Work a small example by hand, including one edge case.

    2. Recognise

    • Input structure: array, string, intervals, tree, graph, grid, operations.
    • Question type: existence, count, optimise, order, connectivity, shortest path.
    • Exploitable property: order, monotonicity, invariant, overlapping subproblems, a safe greedy choice.
    • Name the hypothesis and the closest wrong alternative, and why it is wrong.

    3. Design

    • State the invariant or recurrence in one sentence.
    • Choose the data structure and its exact contents (indices or values? which comparator?).
    • Fix the interval convention ([l, r] or [l, r)) and keep it.
    • Decide types: long for sums and products; a modulus if counts grow.

    4. Verify

    • Dry-run the hand example through the code, not through your intention.
    • Empty or single input; all equal; all negative; zero.
    • Duplicates; touching intervals; cycles; disconnected parts; unreachable targets.
    • Overflow at the maximum constraints; recursion depth.
    • Loop termination: does every iteration shrink the search space?

    5. Communicate

    • State time and auxiliary space, including sort, heap, map and recursion stack.
    • Mention the brute force and why the chosen approach improves on it.
    • Pre-empt likely follow-ups: streaming, updates, k variants, memory limits.
    • If stuck for more than 3 minutes, revisit the "Recognise" phase rather than patching code.

    Self-assessment framework

    Rate each technique on six independent dimensions. Being strong in one does not imply the others: many candidates recognise a pattern instantly but cannot prove it correct, or write a template fluently but mis-size the state on a new problem.

    How to use it

    1. Timed cold attempts. Pick an unseen problem tagged with the technique (or, better, untagged). Set a timer and do not look anything up. Record the time, the bugs and the hints you would have needed.
    2. Explain aloud. Before coding, state the invariant and complexity in under a minute, as if to an interviewer. If you hesitate, the "Conceptual" and "Proof" levels are not yet interview-ready.
    3. Template drill. Rewrite the chapter template on a blank editor, then compile and test it. Any boundary bug keeps "Template fluency" at Developing.
    4. Mixed sets. Readiness is judged on interleaved problems from several chapters. Recognition practised on one chapter at a time overstates skill.
    5. Spaced review. Re-test Developing items after about 3 days and Interview-ready items after about 2 weeks. Downgrade any item that fails.

    Readiness rule of thumb. A technique is interview-ready when you can solve two unseen problems with it, under time, with a stated proof and correct complexity, after at least a week without reviewing it.
