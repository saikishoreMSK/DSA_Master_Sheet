Pattern 01

Two Pointers: Opposite Direction / Left–Right

Key insight. Two pointers is correct only when each move discards a provably useless set of candidates. If you cannot say "every pair containing the pointer I just moved is impossible or no better than one already seen", you do not have a valid two-pointer solution.

Recognition rule. Pair over an ordered axis + a score that is monotone in each end → shrink from the side that can no longer help.

Concepts

The elimination invariant. For a sorted array a and target t, maintain:

Invariant: if a valid pair (i, j) with i < j exists, then l ≤ i and j ≤ r. If a[l] + a[r] < t: for every j ≤ r, a[l] + a[j] ≤ a[l] + a[r] < t ⇒ no pair uses l ⇒ l++ If a[l] + a[r] > t: for every i ≥ l, a[i] + a[r] ≥ a[l] + a[r] > t ⇒ no pair uses r ⇒ r--

Each step shrinks the search rectangle by one row or column, so the scan ends after at most n − 1 moves.

The dominance invariant (optimisation version). In Container With Most Water, area(l, r) = min(h[l], h[r]) · (r − l). Suppose h[l] ≤ h[r]. Then for every r' < r, the width shrinks and min(h[l], h[r']) ≤ h[l], so area(l, r') ≤ h[l] · (r' − l) < area(l, r). Pointer l has achieved its best pair, so discard it. The argument does not show the move is safe for the taller side, which is why you must move the shorter one.

Bounded-side invariant (Trapping Rain Water). Water above index i is min(maxLeft(i), maxRight(i)) − h[i]. Track leftMax over a[0..l] and rightMax over a[r..n−1]. If leftMax < rightMax, then for index l the true right maximum is at least rightMax > leftMax, so its water level is exactly leftMax, even though the rest of the right side has not been seen.

When sorting changes the problem. Sorting is safe when the answer depends only on the multiset of values (3Sum returns values). It is unsafe when it depends on positions: Container With Most Water uses indices as widths, so it must not be sorted, and its two-pointer validity comes from dominance, not order. Two Sum I returns indices, so sort index–value pairs or use a hash map.

Template

Template A — pair search with elimination. Reusable: the loop and the move rules. Problem-specific: score and what "found" means.

Template B — fix one, two-pointer the rest (k-sum with deduplication).

Medium

The shorter line has already met its best partner (the farthest one). Every narrower container using it is no larger, so it can be discarded.

Pattern 02

Sliding Window: Fixed and Variable Size

Key insight. A variable window is correct only when validity is monotone under containment: every sub-window of a valid window is valid (for "longest" problems), or every super-window of a valid window is valid (for "shortest" problems). Without that property, a greedy shrink can throw away the answer.

Recognition rule. Contiguous range + a constraint that only gets worse as the window grows (or only better) → expand right, shrink left, never move back.

Concepts

Fixed window. The state equals the aggregate of exactly the last k elements:

S(r) = S(r−1) + a[r] − a[r−k] for r ≥ k; window = [r−k+1, r]

The aggregate must be invertible (sum, count, xor, frequency map) to remove a[r−k] in O(1). Max and min are not invertible, which is why they need a deque.

Variable window, "longest valid". Invariant after processing r: [l, r] is the longest valid window ending at r. When adding a[r] breaks validity, shrink until valid. Correctness: if [l, r] is invalid then every [l', r'] with l' ≤ l, r' ≥ r is invalid (it contains an invalid window), so no future answer starts at or before the discarded l.

Variable window, "shortest valid". Invariant: after shrinking, [l−1, r] was the last valid window. Expand r until valid, then shrink while still valid, recording the answer at each valid state. Correctness: once [l, r] is valid, any window [l, r'] with r' > r is longer, so l never needs to pair with a larger r.

Window length = r − l + 1 (inclusive [l, r]) Longest with ≤ k bad : grow r; while bad > k: drop a[l++]; ans = max(ans, r − l + 1) Shortest with condition : grow r; while valid: ans = min(ans, r − l + 1); drop a[l++] Exactly k = atMost(k) − atMost(k − 1) (counting problems)

Window state design. Keep a frequency array (int[26], int[128]) when the alphabet is small, and a HashMap otherwise. Pair it with a single scalar that summarises validity: distinct, bad, or missing. Checking the scalar is O(1); re-scanning the frequency table per step is O(σ) and turns O(n) into O(nσ).

Template

Template A — fixed size k. Reusable: the add/remove rhythm. Problem-specific: what the state is and what is recorded.

Template B — variable size, longest valid window (shrink while invalid).

Assumption. Shrink-while-valid is correct only because all values are non-negative, so shrinking never makes an invalid window valid again. With negative values, use prefix sums with a monotonic deque instead.

Pattern 03

Fast and Slow Pointers: Cycle Detection / Linked Lists

Key insight. Fast/slow works on any structure where each state has exactly one next state (a functional graph). Its paths look like the Greek letter ρ: a tail leading into one cycle. It does not apply to general graphs, where a node can have several neighbours.

Recognition rule. One-successor sequence + a question about looping or relative position + O(1) memory → tortoise and hare.

Concepts

Convergence. Once both pointers are in the cycle (length L), let the gap be d = (fast − slow) mod L. Each iteration fast moves 2 and slow moves 1, so the gap changes by exactly one each step. It therefore passes through 0 within L steps and the two meet, with no risk of fast "jumping over" slow. Detection costs O(μ + L), where μ is the tail length.

Entry point derivation. Let μ = distance from head to entry, and suppose they meet k steps into the cycle.

slow travelled s = μ + k (+ whole loops, absorbed below) fast travelled 2s = μ + k + m·L for some integer m ≥ 1 ⇒ s = m·L ⇒ μ + k = m·L ⇒ μ = m·L − k = (m − 1)·L + (L − k)

From the meeting point, walking μ steps lands on k + μ ≡ 0 (mod L), which is the entry. So reset one pointer to the head and move both one step at a time; they meet exactly at the entry after μ steps.

Midpoint conventions. With slow = fast = head and the loop guard fast != null && fast.next != null, slow ends at index ⌊n/2⌋ (0-based): the second middle for even n. With the guard fast.next != null && fast.next.next != null, slow ends at ⌊(n−1)/2⌋: the first middle, which is what you need to split a list before reversing its second half.

Template

Template A — middle node (both conventions).

Template B — Floyd on any functional sequence. The same two phases work for list nodes, array indices (i → a[i]) or numbers (x → f(x)). Only next changes.

Pattern 04

Prefix Sum / Cumulative Sum

Key insight. Prefix sums make no monotonicity assumption, which is exactly why they work with negative values where a sliding window fails. The price is O(n) memory for the map of earlier prefixes.

Recognition rule. Exact sum, balance or divisibility on a contiguous range, especially with negatives → prefix sums plus a hash map of earlier prefixes.

Concepts

Indexing convention. Use a length-(n+1) array with an empty prefix:

P[0] = 0, P[i+1] = P[i] + a[i] P[i] = sum of a[0..i−1] sum(a[l..r]) = P[r+1] − P[l] inclusive l..r, 0 ≤ l ≤ r < n 2D: S[i+1][j+1] = S[i][j+1] + S[i+1][j] − S[i][j] + g[i][j] sum(r1..r2, c1..c2) = S[r2+1][c2+1] − S[r1][c2+1] − S[r2+1][c1] + S[r1][c1]

The extra slot P[0] = 0 represents the empty prefix. It is what allows subarrays starting at index 0 to be counted, and it is the reason hash-map solutions seed the map with {0: 1} (counting) or {0: −1} (index-based).

Hash-map invariant. Process j = 0..n−1 with running prefix p = P[j+1]. Invariant: before handling j, the map contains exactly the prefixes P[0..j], which are the starts of subarrays ending at j. Therefore:

  1. Query first: count += map[p − k] counts subarrays (i..j) with i ≤ j.
  2. Then insert p, so it can serve as a start for later ends.

Inserting before querying makes P[j+1] available as its own start, which pairs it with itself and counts the empty subarray whenever k = 0. That is the classic wrong-order bug.

First vs last occurrence. For the longest subarray, store a prefix's first index and never overwrite it (use putIfAbsent). For the shortest, keep the latest index (overwrite). For counting, store frequencies.

Difference arrays (the inverse operation). To add v to every element of a[l..r] for many updates, then read the array once: D[l] += v; D[r+1] −= v, and the final array is the prefix sum of D. This gives O(1) per update and O(n) to materialise.

Template

Template A — static range sums (1D and 2D).

Template B — prefix + hash map (count, longest, modular). Reusable: the scan, the seeding, and query-before-insert. Problem-specific: the key transform and the stored value.

Pattern 05

Binary Search: Index / Sorted Array

Key insight. Correctness comes from one invariant: "the answer, if it exists, lies within my current interval". Each update must discard only indices that provably are not the answer, and the interval must strictly shrink.

Recognition rule. An index space plus a predicate that splits it into "no" then "yes" (or tells you which side holds an answer) → halve it.

Concepts

Two interval conventions. Pick one per problem and never mix them:

ConventionLoopShrink rulesExit state
Inclusive [lo, hi]while (lo <= hi)lo = mid + 1 / hi = mid − 1Empty interval: lo = hi + 1. Use for exact match with early return.
Half-open [lo, hi)while (lo < hi)lo = mid + 1 (pred false) / hi = mid (pred true)lo == hi == first true (or n if none). Use for boundaries.

In the half-open form, hi = mid keeps a possible answer, and mid = lo + (hi − lo) / 2 < hi guarantees progress. If you need lo = mid (searching the last true), round the midpoint up (lo + (hi − lo + 1) / 2) or the loop can stall at a two-element interval.

lowerBound(x) = first i with a[i] ≥ x (n if none) upperBound(x) = first i with a[i] > x (n if none) count(x) = upperBound(x) − lowerBound(x) last index of x = upperBound(x) − 1 (valid iff count > 0) mid = lo + (hi − lo) / 2 or (lo + hi) >>> 1 never (lo + hi) / 2 when lo + hi may overflow

Duplicates. Exact-match search returns an occurrence, not a specific one. First/last occurrence must be phrased as a boundary (≥ x, > x), and then duplicates need no special handling.

Partition search. For the median of A (size m ≤ n) and B (size n), choose i elements from A and j = ⌈(m+n)/2⌉ − i from B for the left half. The cut is valid iff A[i−1] ≤ B[j] and B[j−1] ≤ A[i]. If A[i−1] > B[j], i is too large; otherwise it is too small. So "i is too large" is a monotone predicate over i ∈ [0, m], and the search costs O(log min(m, n)).

Template

Template A — exact match, inclusive interval.

Template B — boundary search on a predicate, half-open interval. This one shape covers lower bound, upper bound, rotated minimum and "first bad version".

LC 4

Median of Two Sorted Arrays

Hard

Task. Return the median of the union of two sorted arrays of sizes m and n in O(log(m + n)).

Key insight

The median is defined by a partition: a left half of size ⌈(m+n)/2⌉ with every left element ≤ every right element. Choosing i elements from the shorter array fixes j = half − i from the other, so you are binary searching a single integer i ∈ [0, m].

TimeO(log min(m, n))SpaceO(1)

Pattern 06

Binary Search on Answer: Parametric Search

Key insight. You do not need a formula for the optimum. You need (1) a range guaranteed to contain it, (2) a predicate that is monotone over that range, and (3) a fast, correct way to evaluate the predicate.

Recognition rule. "Smallest / largest value such that a budget is respected" + an O(n) way to test one value → binary search the value.

Concepts

Defining the answer space. Choose lo as a value that is certainly no larger than the answer and hi as a value that is certainly feasible. Good bounds come from the problem's extreme cases:

Problemlo (lower bound)hi (always feasible)Why
Koko (875)1max(piles)At speed max, each pile takes one hour and h ≥ n is guaranteed.
Smallest divisor (1283)1max(nums)Every term ceil(v / max) = 1 and threshold ≥ n.
Ship within D days (1011)max(weights)sum(weights)A package cannot be split, and one ship can take everything in one day.
Split array (410)max(nums)sum(nums)Some part contains the largest element, and one part is always allowed.

Monotone predicate and the boundary search. For minimisation, the predicate over [lo, hi] looks like F F F … F T T … T. Search the first T with the half-open discipline:

Invariant: answer ∈ [lo, hi] and feasible(hi) is true. mid = lo + (hi − lo) / 2 (rounds down, so mid < hi and the loop always shrinks) feasible(mid) ⇒ hi = mid (mid may be the answer: keep it) otherwise ⇒ lo = mid + 1 (mid is infeasible, so everything ≤ mid is too) Loop while lo < hi; on exit lo == hi == answer.

For maximisation (T T … T F F), search the last T. Round up, mid = lo + (hi − lo + 1) / 2, with lo = mid on success and hi = mid − 1 on failure. Rounding down here makes lo = mid loop forever when hi = lo + 1.

Integer ceiling without floating point. For positive a and b, ceil(a / b) = (a + b − 1) / b, or (a − 1) / b + 1 for a ≥ 1. The second form avoids overflow when a is near Integer.MAX_VALUE. Never use Math.ceil((double) a / b) in interviews: it is slow and, for large longs, inexact.

Overflow. The checker's accumulator (total hours, total sum) can exceed 231−1. For Koko, 104 piles × 109 hours each overflows an int, so use long. Bounds like sum(nums) can also overflow int in general; LeetCode 410's constraints keep it within 109, but writing long costs nothing.

Template

Template A — minimise x subject to a monotone feasibility predicate. Reusable: the loop. Problem-specific: bounds and feasible.

Template B — maximise x subject to a monotone predicate (max-min problems). Note the upward rounding.

Pattern 07

Merge Intervals: Sorting and Sweep

Key insight. Sorting by start converts a pairwise O(n²) overlap relation into a single running value, the end of the current block. Counting overlaps instead requires splitting each interval into a +1 event and a −1 event and sweeping them in time order.

Recognition rule. Intervals + "combine / gaps / how many at once" → sort by start and sweep, keeping one running end or a heap of ends.

Concepts

Overlap conditions. Closed intervals [a, b] and [c, d] overlap iff max(a, c) ≤ min(b, d); they are disjoint iff b < c or d < a. For half-open [a, b) and [c, d), replace ≤ with <, so touching intervals do not overlap.

Key insight. Define the function's contract in one sentence, for example "gain(node) = the best downward path sum starting at node". Then trust it for the children. Correctness follows by structural induction: if the contract holds for the children, the combination step makes it hold for the node.

Recognition rule. The answer at a node is composed from its children, or the question is about components or reachability, so use DFS with a clear return contract and a visited set.

Concepts

Traversal order is a modelling choice.

Pattern 10

BFS and Level Order: Shortest Path in Unweighted Graphs

Key insight. BFS is Dijkstra with a priority queue that happens to be FIFO, which works only because every edge adds exactly 1. Change one weight and the guarantee disappears.

Recognition rule. Fewest equal-cost moves, or simultaneous spreading → BFS (multi-source when there are many starts).

Concepts

The layer invariant. At any moment the queue contains nodes from at most two consecutive layers, d and d + 1, with every layer-d node ahead of every layer-(d+1) node.

Claim: when node v is first enqueued from u, dist(v) = dist(u) + 1. Proof sketch: nodes are dequeued in non-decreasing dist order (layer invariant). If a shorter path to v existed, its predecessor w would have dist(w) < dist(u) and was dequeued earlier, so it would already have enqueued v. Contradiction.

Visited-state timing. Mark a node visited when it is enqueued, not when it is dequeued. Marking at dequeue lets the same node be enqueued many times by different neighbours in the same layer. Distances stay correct, but the queue can grow to O(E), or exponentially in implicit graphs, and lead to TLE or MLE. The exception is weighted search (Dijkstra), where the distance is final only at dequeue time.

Level boundaries. Two equivalent techniques:

  • Size snapshot: for (int k = q.size(); k > 0; k--) processes exactly one layer, and the loop counter is the level.
  • Distance array: store dist[v] = dist[u] + 1 at enqueue time; no layer loop is needed. This is more flexible (multi-source, and the visited test becomes dist[v] == -1).

Multi-source BFS. Enqueue all sources with distance 0 before starting. This is the same as adding a virtual super-source S with a 0-weight edge to each real source, then running BFS from S. The result is dist[v] = min over sources s of dist(s, v) in a single O(V + E) pass, compared with O(k · (V + E)) for k separate BFS runs.

Template

Template A — single/multi-source BFS on a grid with a distance array. Reusable: queue, directions, bounds check, enqueue-time marking. Problem-specific: what counts as passable, and which cells are sources.

Template B — level-order BFS with a size snapshot (adjacency list or implicit graph).

Pattern 11

Topological Sort: DFS / Kahn's Algorithm

Key insight. Ordering is possible if and only if there is no directed cycle. Kahn's algorithm detects a cycle when it emits fewer than n vertices; DFS detects one when it meets a gray (in-progress) vertex.

Recognition rule. Directed "before/after" constraints + "find an order" or "is it possible" → topological sort (and its built-in cycle check).

Concepts

Kahn's invariant. The queue holds exactly the vertices whose indegree has dropped to 0 and which have not yet been emitted. Every emitted vertex has had all its predecessors emitted before it.

indeg(v) = number of edges (u → v) with u not yet emitted Emit u ⇒ for each u → v: indeg(v)--, and enqueue v when indeg(v) becomes 0 Termination: emitted == n ⇔ graph is a DAG If a cycle exists, no vertex on it can ever reach indegree 0 (each has a predecessor on the cycle).

DFS colouring. White = unvisited, gray = on the current recursion stack, black = finished (all descendants explored).

  • An edge to a gray vertex is a back edge, which proves a directed cycle.
  • An edge to a black vertex is safe: that vertex's subtree is complete and acyclic.
  • When a vertex turns black, every vertex reachable from it is already black. Appending on finish gives reverse topological order, so reverse the list (or prepend).

Choosing between them. Kahn is iterative (no recursion-depth risk), naturally gives a lexicographically smallest order with a priority queue, and supports "process in parallel rounds" questions (the number of BFS layers is the minimum number of semesters). DFS is shorter when you already have a recursive traversal, and its colour states answer "which nodes can reach a cycle?" (Problem 802).

Template

Template A — Kahn's algorithm (BFS on indegrees). Directed graph: edges[i] = {u, v} means u → v (u before v). Returns an order, or an empty array if there is a cycle.

Template B — DFS with three colours and reverse postorder. Iterative alternatives exist, but recursion is the interview norm. Note that the depth can reach V.

Pattern 12

Dynamic Programming: 1D

Key insight. A correct state answers "what does the rest of the problem need to know about the past?". If two different histories with the same i can lead to different futures, the state is missing a dimension.

Recognition rule. Exponential recursion + small repeated arguments → memoise; the arguments are the state.

Concepts

The four parts of a DP. Write each down before coding:

  1. State: a precise sentence, e.g. "dp[i] = number of ways to split the suffix s[i..n−1]".
  2. Transition: case analysis on the last (or first) decision. The cases must be disjoint for counting and exhaustive for both counting and optimisation.
  3. Base case: the empty prefix or suffix. In counting DP the empty problem has exactly 1 way, not 0.
  4. Order: compute every dependency before its use (increasing i for prefix states, decreasing i for suffix states).
Counting : dp[i] = Σ over disjoint last choices c dp[prev(i, c)] (sum rule) Optimising : dp[i] = max over last choices c ( dp[prev(i, c)] + gain(c) ) House Robber: dp[i] = max(dp[i−1], dp[i−2] + a[i−1]) over prefix length i (skip house i−1) (rob house i−1, so house i−2 must be skipped)

State dependencies and space optimisation. If dp[i] reads only dp[i−1] and dp[i−2], keep two variables: O(1) space. If it reads a window of size w (a piece of at most w digits), keep a circular buffer of size w + 1. The rolling update must read the old values before overwriting them.

Counting vs optimisation. Counting needs disjoint cases (no double counting) and a modulus. Optimisation tolerates overlapping cases (max is idempotent) but needs a sentinel such as Integer.MIN_VALUE / 2 or −∞ for impossible states, so that adding to it does not overflow.

Top-down vs bottom-up. Memoised recursion is quicker to derive and visits only reachable states, but costs O(depth) stack. Bottom-up allows space compression and avoids stack overflow. Interviewers accept either, as long as you can state the complexity as (#states × transition cost).

Template B — counting partitions of a sequence (suffix DP, modulo). Reusable: the suffix loop and modular sum. Problem-specific: which pieces s[i..j] are valid.

Key insight. Use prefix lengths (an (m+1) × (n+1) table), not indices. Row 0 and column 0 then represent empty prefixes, the base cases become explicit, and the boundary ifs disappear.

Recognition rule. Two sequences compared position by position, or a grid with monotone moves → a (prefix × prefix) or (row × column) table.

Concepts

Grid DP. With moves right/down, every path to (i, j) enters from (i−1, j) or (i, j−1):

Count: paths[i][j] = paths[i−1][j] + paths[i][j−1] (0 for blocked cells) Minimise: cost[i][j] = grid[i][j] + min(cost[i−1][j], cost[i][j−1]) Borders: first row / column have a single predecessor

Pattern 14

Greedy: Interval Scheduling / Local Optimality

Key insight. A greedy algorithm is only as good as its proof. State the choice ("take the compatible interval with the smallest end") and the exchange ("replacing OPT's first interval with mine keeps OPT feasible and the same size"). If the exchange fails on some example, switch to DP.

Recognition rule. Unweighted "keep as many as possible" over intervals → sort by end, take each one that fits.

Concepts

Exchange argument for earliest end. Sort intervals by end. Let g1 be the first interval with the smallest end and let OPT = o1, o2, … be an optimal compatible set sorted by end.

end(g₁) ≤ end(o₁) (g₁ has the globally smallest end) o₂ starts at or after end(o₁) ≥ end(g₁) ⇒ {g₁, o₂, o₃, …} is still compatible |{g₁, o₂, …}| = |OPT| ⇒ some optimal solution contains g₁ Induct on the intervals compatible with g₁ ⇒ greedy is optimal.

The same argument, phrased as "greedy stays ahead", says that after k picks the greedy's k-th end is ≤ OPT's k-th end, so greedy can never fall behind.

Why sort by end and not by start. Sorting by start and taking the earliest-starting interval fails on [1,100], [2,3], [4,5]: you take one long interval instead of two short ones. Sorting by length fails on [1,5], [4,7], [6,10]: the shortest, [4,7], blocks both others. The end time is the only key whose exchange argument works.

Boundary convention. LeetCode 435 and 252 treat touching intervals ([1,2] and [2,3]) as compatible, which means half-open semantics. LeetCode 56 and 986 use closed intervals, where touching intervals overlap or intersect at a point. Write the comparison (>= vs >) as a deliberate decision.

When the greedy view is not the full story. Merging (56) and intersecting lists (986) are often filed under greedy because each step commits to something permanently. Their correctness comes from sortedness plus a sweep or two-pointer invariant, not from an exchange argument. The assigned problems below label this explicitly.

Key insight. The heap type is the opposite of the goal for bounded top-k. The root must be the element you are ready to throw away. For k largest that is the smallest element kept, so use a min-heap.

Heap invariant. Every parent compares ≤ its children under the comparator, so the root is the extreme. Java's PriorityQueue is a binary min-heap by natural order. Pass a comparator for anything else.

Pattern 17

Union-Find / Disjoint Set Union

Key insight. DSU does not store how elements are connected, only whether they are. If you need paths, distances or edge directions, traverse the graph instead. If you only need connectivity under insertions, DSU is the simplest correct tool.

Recognition rule. Undirected relations merging over time + "same group?" or "how many groups?" → DSU.

Concepts

Representation. parent[x] is x's parent and roots satisfy parent[r] == r. Invariant: following parents from any element reaches its component's unique root.

Two heuristics, used together.

  • Union by size (or rank): attach the smaller tree under the larger root. A node's depth increases only when its tree at least doubles in size, so depth ≤ log2 n even without compression.
  • Path compression: during find, point visited nodes (all of them, or every other one with path halving) closer to the root, flattening future queries.
With both heuristics: m operations on n elements cost O(m · α(n)) (Tarjan) α = inverse Ackermann; α(n) ≤ 4 for any n that fits in memory → "effectively constant" Union by size alone: O(log n) per find. Compression alone: O(log n) amortised.

Cycle detection. Process undirected edges in order. If find(u) == find(v) before the union, a u–v path already exists, so adding (u, v) closes a cycle. This is also Kruskal's rejection rule.

Component counting. components = n − (number of successful unions), because each successful union merges exactly two components.

Pattern 18

Shortest Path: Dijkstra's Algorithm

Key insight. Dijkstra is BFS with a priority queue instead of a FIFO queue. It needs exactly one property: extending a path never makes it cheaper. Sums of non-negative weights have it; so do the maximum edge on a path and the product of probabilities ≤ 1. Negative edges do not.

Recognition rule. Weighted edges + non-negative costs + "minimum total" from a source → Dijkstra. Before coding, ask whether the vertex alone is a sufficient state.

Concepts

Relaxation. For edge (u, v, w): if dist[u] + w < dist[v], set dist[v] = dist[u] + w and push (dist[v], v). Every algorithm in this family is a schedule of relaxations. Dijkstra's schedule relaxes the outgoing edges of each vertex exactly once, in order of final distance.

Invariant: when u is popped with d == dist[u], dist[u] = δ(s, u) (true shortest distance) Proof sketch: let P be a shortest s→u path, and let (x, y) be its first edge with x settled, y not. dist[y] ≤ δ(s, x) + w(x, y) = δ(s, y) ≤ δ(s, u) (prefix of a shortest path; w ≥ 0) u was chosen as the minimum ⇒ dist[u] ≤ dist[y] ≤ δ(s, u) ≤ dist[u] ⇒ equality. The step δ(s, y) ≤ δ(s, u) is exactly where non-negative weights are used.

Stale entries (lazy deletion). java.util.PriorityQueue has no efficient decrease-key, so push a new entry on every improvement. Old entries stay in the heap. When popped, an entry whose d > dist[u] is stale and is skipped. The heap holds at most O(E) entries, so each operation costs O(log E) = O(log V), because E ≤ V².

Total: O((V + E) log V) time, O(V + E) space (adjacency list + up to E heap entries) Dense graphs (E ≈ V²): the array version (scan for the minimum) is O(V²) and beats the heap.

Why negative weights break it. Take the edges s→a (2), s→b (5) and b→a (−4). Dijkstra settles a at distance 2, but the true distance is 1 via b. Once a is settled, its outgoing edges were relaxed with the wrong value, so the error propagates. Adding a constant to every edge does not fix it, because paths with more edges are penalised more.

Generalised path costs. Dijkstra works for any cost that satisfies (1) monotonicity: cost(P + e) ≥ cost(P), and (2) isotonicity: if cost(P) ≤ cost(Q) for two paths to the same vertex, then cost(P + e) ≤ cost(Q + e). Bottleneck max(cost, w) (LC 1631) and the probability product with factors in [0, 1] under a max-heap (A2) both qualify.

State expansion. When a constraint makes "cheapest so far" insufficient (for example, a cheap path that has used too many edges), encode the constraint in the state: vertex v becomes (v, edgesUsed). The expanded graph has V·(K+2) states, and Dijkstra applies unchanged. The first time the target appears at the top of the heap, in any layer, its cost is optimal.

Template

Template A — adjacency-list Dijkstra with lazy deletion. Reusable: everything. Problem-specific: graph construction (directed or undirected, index base) and what you read from dist.

Template B — grid Dijkstra with a pluggable path-cost rule. The combine line is the only problem-specific part: d + w for sums, Math.max(d, w) for bottleneck costs.

Pattern 19

Trie / Prefix Tree

Key insight. Use a trie when you need to ask "can this partial string still become a word?" while building the string one character at a time. That early "no" is what prunes backtracking in Word Search II.

Recognition rule. Many words + prefix questions or character-by-character construction → trie. One word or only whole-word membership → hash set.

Concepts

Structural invariant. The path from the root to node x spells a unique string prefix(x). Node x exists if and only if some inserted word has prefix(x) as a prefix. x.end (or a stored word) is true if and only if prefix(x) itself was inserted.

insert(w), search(w), startsWith(p): O(L) time, L = query length Total nodes ≤ 1 + Σ |w_i| (one node per distinct prefix) Memory (array children): nodes · alphabet · reference size ≈ ΣL · 26 · 4–8 bytes

End-of-word markers. Prefix and word are different questions. After inserting "apple", search("app") is false while startsWith("app") is true. Storing the full word at the terminal node (String word instead of boolean end) avoids rebuilding strings during DFS, which is standard in Word Search II.

Pattern 20

Segment Tree / Fenwick Tree (Binary Indexed Tree)

Key insight. Two questions decide the structure. (1) Is the merge operation invertible (sum, xor, counts)? If yes and updates are point updates, a Fenwick tree is enough. (2) Do you need non-invertible aggregates (max, min) over arbitrary ranges, range assignments, or custom merges? Then use a segment tree, with lazy propagation if updates cover ranges.

Recognition rule. Interleaved updates and range queries over the same array (or value axis) → Fenwick if the operation is invertible and updates are point updates; otherwise a segment tree, lazy if updates cover ranges.

Concepts

Segment tree — array representation. Node 1 is the root and covers the whole input range [0, n−1]. Node x covering [l, r] has children 2x covering [l, mid] and 2x+1 covering [mid+1, r], with mid = (l + r) >>> 1.

Invariant: tree[x] = merge(tree[2x], tree[2x+1]), leaves hold a[i] Height h = ⌈log₂ n⌉, so indices are < 2^(h+1) ≤ 4n ⇒ allocate 4n Query [ql, qr]: at most 2 nodes per level are partially covered ⇒ O(log n) nodes visited Point update: one root-to-leaf path, then recompute ancestors ⇒ O(log n) Build: each of the < 2n real nodes is computed once ⇒ O(n)

The segment tree needs only an associative merge with an identity element for ranges that fall outside the query (0 for sum, Integer.MIN_VALUE for max, +∞ for min). Commutativity is not required as long as left and right are merged in order. That is what allows merges such as "max subarray sum within a range" that store a tuple per node.

Bottom-up (iterative) segment tree. Leaves live at [n, 2n) and node x has children 2x and 2x+1. A query over the half-open range [l, r) walks both bounds upward. It is short and fast, and its natural convention is half-open. The 2407 solution uses it; the recursive Template A uses inclusive bounds. Never mix the two conventions inside one implementation.

Lazy propagation (range updates). A range update would touch O(n) leaves, so instead store a pending tag on each fully covered node and push it to the children only when a later operation needs to descend. This requires (1) a tag that can be applied to a node aggregate in O(1) (add: sum += tag · length; assign: max = value), and (2) tags that compose (add then add equals one add; assign overrides an earlier assign or add). If you cannot define both, lazy propagation does not apply as written.

Fenwick tree — the low-bit structure. Internally 1-based. bit[i] stores the sum of the half-open range (i − lowbit(i), i], where lowbit(i) = i & −i is the value of i's lowest set bit.

Two's complement: −i = ~i + 1. Below the lowest set bit, ~i has 1s and adding 1 carries through them, flipping back exactly that bit. Above it, i and ~i differ, so i & −i keeps only the lowest set bit. e.g. i = 12 = 1100₂, −i = …0100₂, i & −i = 4 prefix(i) = bit[i] + prefix(i − lowbit(i)) → strip low bits: ≤ log₂ n steps update(i, δ): bit[i] += δ; i += lowbit(i) → climb to every block containing i rangeSum(l, r) = prefix(r) − prefix(l − 1) → requires an inverse ("−") Index 0 is unusable: lowbit(0) = 0, so update(0) would loop forever. Hence 1-based.

Zero-based input vs one-based internals. Keep the public API 0-based, matching LeetCode, and shift once at the boundary (i + 1) inside add and prefix. Shifting by hand at call sites is where off-by-one bugs come from.

Why Fenwick fails for range max. With max you cannot recover max(l..r) from max(1..r) and max(1..l−1); the larger prefix hides the window. A Fenwick "prefix max" works only for prefix queries with increase-only updates. LC 2407 needs a window [x−k, x−1], so it needs a segment tree.

Algorithm A1

Monotonic Stack

A stack whose contents stay sorted. Each element is pushed once and popped once, and the moment it is popped is exactly when you learn its nearest greater (or smaller) neighbour.

Concepts

Goal (scanning left → right)Stack order bottom → topPop while…
Next greater elementDecreasinga[top] < a[i]: i is top's next strictly greater
Next greater or equalStrictly decreasinga[top] <= a[i]
Next smaller elementIncreasinga[top] > a[i]
Previous smaller (after pops)IncreasingPop a[top] >= a[i]; the new top is the previous strictly smaller element

Invariant (next-greater form). After processing index i, the stack holds exactly the indices j ≤ i that do not yet have a next greater element, and their values are non-increasing from bottom to top. A popped index has found its answer, and that answer is final: i is the first index after it with a larger value, because every index between them was either smaller (popped earlier, or never above it) or is still on the stack above it, which contradicts the order.

Index vs value storage. Store indices. They give you the distance (i − top), the value (a[top]) and a write position in the answer array. Store values only when positions never matter (e.g. remove-k-digits builds the output directly).

Amortised O(n). Each index is pushed exactly once and popped at most once, so the inner while loop runs at most n times in total across all iterations, even though a single iteration may pop many.

For contribution counting, let L[i] be the index of the previous element strictly smaller than a[i] (or −1), and R[i] be the index of the next element smaller or equal (or n). Then a[i] is the minimum of every subarray [l, r] with L[i] < l ≤ i ≤ r < R[i]:

count(i) = (i − L[i]) · (R[i] − i) Σ over subarrays of min = Σᵢ a[i] · (i − L[i]) · (R[i] − i) Why one side strict and the other non-strict: with duplicates, a subarray such as [2, 2] has two positions holding its minimum. Making exactly one side non-strict assigns it to exactly one of them (here the rightmost occurrence), so nothing is double-counted or missed.

Algorithm A2

Dijkstra's Algorithm

Greedy single-source shortest paths for non-negative weights: always finalise the closest unfinished vertex. Chapter 18 covers the pattern and its problem shapes. This chapter covers the proof, the exact conditions under which the greedy step stays valid, and two generalisations: multiplicative path values and counting shortest paths.

Concepts

Relaxation. For an edge u → v with weight w: if dist[u] + w < dist[v] then dist[v] = dist[u] + w. Every shortest-path algorithm is a strategy for ordering relaxations. Dijkstra orders them by settling vertices in increasing distance, so each edge is relaxed once from its final source distance.

Invariant. Let S be the set of settled vertices. (1) For every v ∈ S, dist[v] equals the true distance δ(s, v). (2) For every v ∉ S, dist[v] is the shortest path to v that uses only vertices of S before its last edge.

Why negative weights break it. Edges s→a (2), s→b (3), b→a (−2). Dijkstra settles a at distance 2 before it settles b. The true distance is 3 + (−2) = 1, found only after a has been finalised. With lazy re-insertion some implementations happen to recover in this case, but then the "settled once" guarantee and the complexity bound both disappear, and negative cycles make the answer undefined. Use Bellman–Ford (A7).

Stale entries. Java's PriorityQueue has no decrease-key. Push a new (dist, v) entry on every improvement and, when popping, skip any entry whose distance is larger than the current dist[v]. The heap holds at most E + 1 entries.

Generalised condition: path value f(P · e) is computed from f(P) and w(e) by an operation ⊕ that is (a) monotone: a ≤ b ⇒ a ⊕ w ≤ b ⊕ w (b) non-improving: a ⊕ w ≥ a (for minimisation) Sum with w ≥ 0 : a ⊕ w = a + w ✓ Bottleneck (LC 1631) : a ⊕ w = max(a, w) ✓ Reliability (LC 1514) : a ⊕ p = a · p, p ∈ [0, 1] ✓ (maximise; value never increases) Sum with w < 0 : violates (b) ✗ → Bellman–Ford Counting shortest paths (weights > 0): ways[s] = 1 ways[v] = Σ ways[u] over edges u → v with dist[u] + w(u, v) = dist[v]

The counting recurrence is evaluated correctly in pop order because every predecessor u on a shortest path to v has dist[u] < dist[v] when weights are strictly positive. So all of v's contributors are settled, and their counts are final, before v itself is popped. With zero-weight edges this ordering argument fails and the counting needs extra care: zero-weight ties may be popped in either order.

Template

Template A — lazy Dijkstra with path reconstruction. Directed edges {u, v, w} with w ≥ 0; add the reverse edge for undirected graphs. Distances are long because sums of int weights overflow.

Template B — dense-graph Dijkstra, O(V²), no heap. When E ≈ V² (a complete graph or adjacency matrix), a linear scan for the minimum beats a heap's O(E log V).

Algorithm A3

Union-Find / Disjoint Set Union

A forest of parent pointers that answers "are x and y in the same group?" while groups only ever merge. Chapter 17 applies it to connectivity problems. This chapter covers why the two optimisations matter, what the amortised bound really means, a weighted extension, and the counting arguments that recur in DSU problems.

Concepts

Representation. parent[x] points toward the root of x's tree, and a root has parent[r] = r. Two elements are in the same set exactly when their roots coincide. The invariant to preserve: every element's parent chain ends at its own set's root. A union only re-points one root, so it never breaks the chains of other elements.

  • Path compression: during find, point visited nodes directly (or every other node, for path halving) at the root. Membership is unchanged; only the shape changes.
  • Union by size / rank: attach the root of the smaller tree under the root of the larger. A node's depth grows only when its tree at least doubles in size, so depth ≤ log₂ n even without compression.
Union by size alone : height ≤ ⌊log₂ n⌋ ⇒ find is O(log n) worst case Path compression alone : O(log n) amortised per operation (m ≥ n operations) Both together (Tarjan) : O(m · α(n)) for m operations; α(n) ≤ 4 for any n < 2^65536 Components after processing edges: components = n − (number of successful unions) Redundant edges : redundant = E − (number of successful unions) Connecting k components needs exactly k − 1 additional edges.

Why size beats rank in interviews. Both give the same bound. Size has a direct meaning: it answers "how large is x's group?" with size[find(x)] at no extra cost.

Template

Template A — DSU with path halving and union by size. The iterative find avoids recursion depth issues for n up to 106.

Template B — weighted DSU (potential to the root). This stores w[x] = value(x) − value(parent[x]), so constraints such as value(b) − value(a) = d can be merged and checked. It is the basis of LC 399 (Evaluate Division, in multiplicative form) and of parity problems.

Template B uses recursion and no union by size, to keep the offset algebra readable. Its depth is O(log n) amortised but can be O(n) on a single first call, so add union by size (the offset formula is symmetric) when n is large.

Invariant (both algorithms). The chosen edge set F is always a subset of some minimum spanning tree.

Algorithm A5

Kadane's Algorithm

A one-pass dynamic programme for the best contiguous subarray. The best subarray ending at index i either extends the best one ending at i − 1 or starts fresh at i.

Concepts

Let end(i) be the maximum sum of a non-empty subarray that ends exactly at index i, and best(i) the maximum over all subarrays within a[0..i].

Invariant after processing index i: cur = end(i) = max sum of a[j..i] over 0 ≤ j ≤ i best = max(end(0), …, end(i))

Every subarray ends somewhere, so the answer is max over i of end(i). That is the whole correctness argument: local best (ending here) feeds the global best (anywhere so far).

end(0) = a[0] end(i) = a[i] + max(0, end(i−1)) = max(a[i], end(i−1) + a[i]) answer = max over i of end(i) Derivation: a subarray ending at i is either [i] alone, or a[j..i−1] followed by a[i]. The best of the second kind is end(i−1) + a[i]. So keep the previous run only if it is positive.

Prefix-sum view. sum(a[j..i]) = pre[i+1] − pre[j], so end(i) = pre[i+1] − min(pre[0..i]). Kadane is the same as tracking the running minimum prefix. This view generalises to length-constrained versions: use a minimum over a sliding range of prefixes (monotonic deque).

Circular case. A wrapping subarray takes a suffix and a prefix, which is the complement of a middle block a[j..i]. Its sum is total − sum(a[j..i]), maximised when the middle block is the minimum subarray:

circular = max( maxSubarray(a), total − minSubarray(a) ) Exception: if every element is negative, minSubarray = total, so total − min = 0 corresponds to the empty subarray, which is not allowed. Return maxSubarray(a) in that case (detect it with maxSubarray < 0).

Empty-subarray conventions. If the problem allows an empty subarray (answer ≥ 0), start with cur = 0, best = 0 and clamp cur = max(0, cur + a[i]). If subarrays must be non-empty (LeetCode 53, 918), initialise both with a[0]. Initialising best = 0 returns 0 instead of −1 on [-3,-1,-2].

Algorithm A6

KMP String Matching

Knuth–Morris–Pratt finds every occurrence of a pattern in linear time by precomputing, for each prefix of the pattern, its longest proper border. A mismatch then jumps straight to the next viable alignment.

Concepts

Prefix function. For a string P, pi[i] = the length of the longest proper prefix of P[0..i] that is also a suffix of P[0..i]. Proper means shorter than i + 1.

P = a b a b c a b a b a pi = 0 0 1 2 0 1 2 3 4 3 pi[8] = 4: "abab" is both a prefix and a suffix of "ababcabab". pi[9] = 3: "aba".

Search invariant. After reading T[i], j = the length of the longest prefix of P that is a suffix of T[0..i]. A match is reported when j = m, after which j becomes pi[m − 1] so overlapping matches are found.

Why matched characters need not be rechecked. Suppose P[0..j−1] equals T[i−j..i−1] and P[j] ≠ T[i]. Any shift that keeps fewer characters aligned must line a prefix of P up against a suffix of T[i−j..i−1] = P[0..j−1], which means a border of P[0..j−1]. Shifts that do not correspond to a border are mismatched on characters already known, so they are impossible. Trying borders in decreasing length (pi[j−1], pi[pi[j−1]−1], …) visits every viable alignment and skips the impossible ones without reading the text again.

Construction phase (pattern against itself). Borders of P[0..i] are obtained by extending borders of P[0..i−1]:

pi[0] = 0 for i = 1..m−1: k = pi[i−1] longest border of P[0..i−1] while k > 0 and P[i] ≠ P[k]: k = pi[k−1] next shorter border if P[i] == P[k]: k++ pi[i] = k

This is correct because the borders of a string are exactly pi[i−1], pi[pi[i−1]−1], …, so the loop tries every candidate border in decreasing order and takes the first that extends by P[i].

Search phase. This is the same loop with T[i] in place of P[i], continuing to compare against P[j].

Linear-time (amortised) proof. In each phase, k (or j) increases by at most 1 per character, so by at most n in total. Each iteration of the inner while loop decreases it by at least 1, and it never goes below 0. Therefore the total number of fallbacks is at most the total number of increases, and the work is O(m) for construction plus O(n) for search.

Useful identities.

Longest border of S = pi[|S| − 1] Smallest period of S = p = |S| − pi[|S| − 1] S is a repetition of a block ⇔ pi[|S|−1] > 0 and |S| mod p == 0 Longest palindromic prefix of S = pi[last] of S + '#' + reverse(S)

Algorithm A7

Bellman–Ford Algorithm

Relax every edge, repeatedly. After round i, every shortest path that uses at most i edges has been found. This one fact gives negative-weight support, negative-cycle detection and edge-budgeted shortest paths.

Concepts

Relaxation. if dist[u] + w(u, v) < dist[v] then dist[v] = dist[u] + w(u, v). A relaxation never sets dist[v] below the weight of some real path to v, so distances are always upper bounds (or ∞).

Invariant after round i (snapshot version): dist_i[v] = min weight over walks src ⇝ v using at most i edges dist_0[src] = 0, dist_0[v] = ∞ otherwise dist_i[v] = min( dist_{i−1}[v], min over edges (u,v,w) of dist_{i−1}[u] + w )

This is a DP over "number of edges used". With in-place updates (the classical algorithm), dist after round i is at most disti: it may already include longer paths. That does not affect correctness for unconstrained shortest paths, but it breaks any edge budget.

Why V − 1 rounds suffice. If no negative cycle is reachable from the source, every shortest walk can have its cycles removed (each has weight ≥ 0) without increasing its cost. The result is a simple path with at most V − 1 edges. By the invariant, round V − 1 has considered every path with ≤ V − 1 edges, so the distances are final.

Negative-cycle detection. If after V − 1 rounds some edge (u, v) can still be relaxed, with dist[u] finite, then a shortest path would need ≥ V edges, so it repeats a vertex. That repeated section must be a negative cycle, and it is reachable from src (dist[u] is finite). Conversely, a reachable negative cycle always leaves at least one relaxable edge: summing dist[v] ≤ dist[u] + w around the cycle would give 0 ≤ (cycle weight) < 0.

Detection: ∃ (u,v,w): dist[u] ≠ ∞ and dist[u] + w < dist[v] after V−1 rounds ⇔ a negative cycle is reachable from src Vertices whose distance is −∞ : every vertex reachable FROM a vertex on (or fed by) that cycle. Propagate −∞ with V more rounds, or BFS from every vertex that still relaxes.

Early termination. If a full round changes nothing, no later round can change anything, because each round depends only on the previous one. Stop early. When distances stabilise, no reachable negative cycle can exist.

Template

Template A — classical Bellman–Ford with early exit, detection and −∞ propagation. Directed edges {u, v, w}; weights may be negative.

Template B — shortest path with at most K edges (snapshot per round).

Why the snapshot matters. With in-place updates, one round can relax a → b and then b → c using the new dist[b], so it uses two edges in a single round. If the edge list happens to be in path order, one round can traverse a whole chain, and the "≤ i edges after round i" guarantee disappears.
